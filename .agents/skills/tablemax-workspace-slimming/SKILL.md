# TableMax 工作区瘦身

1. 先看工作树、当前发行指针、上次执行台账和本次目标。按[工作区维护](../../../docs/reference/workspace-maintenance.md)选分支。用同一根目录计量逻辑长度，计入 Git 与嵌套仓库，记录但不跟随重解析点。先计算目标缺口，再排大目录。
   - 复审历史对比时，先从发行记录确定最新两个三位公开版本，按[两周期窗口](../../../docs/reference/workspace-maintenance.md#历史可比性的两个公开版本周期2026-11-21)处理。目录沿用旧版号时，核对实际验收包、冻结输入或生成器记录的运行批次；窗口外仅承担比较用途的明细可在登记结论、失败原因和哈希后退役。
2. 沿[深度瘦身方法论](../../../docs/reference/deep-slimming-methodology.md)追溯大项的生产者和消费者。旧任务清单用于定位当时的归属。将现存文件与旧清单的 SHA 逐一相交，再检查当前引用。审阅页要核对 HTML、脚本和相对资源；有动态引用时保留依赖子树。快照逐成员与保留归档比较；链接指向的子树单独保护。验收夹具保留报告、唯一输入和有效成品。开发会话先核对可丢弃标记，再选工具已支持的缓存成员。
   - 遇到目录名命中时记录消费者、访问的子路径及读写方向。验收器写出的 bundle 可由保留的源入口重建；发行证明引用的安装夹具则应沿指针保留。清理台账中的路径只证明它曾被盘点。
   - 复审历史渲染轮次时，从已交付的审阅页反查最终轮和画面，再查前轮的报告、截图索引和外部入链。区分同字节副本与被替代画面，后者在退役清单记录原 SHA 和对应的新画面。
   - 对来源可疑的 SQLite 文件，先读夹具生成器，再用只读查询比对实例及修订与独立场景证明；录制用例可比对源库与录制库的实例、测试席位及成片记录。遇到未核实的 WAL 或缺失的来源证明，保留该库。
3. 汇总各类已核验字节、受保护字节和未判定的大项，预留证据自身的空间。在[维护工具](../../../tools/maintenance/README.md)的精确清单中绑定来源、保留件、路径、长度、时间和 SHA。只读请求止于预算。已授权清理先预览，在空闲门禁下按预览哈希执行一次 Apply。
   - 先扣除已确认的消费者和保留成本，用每组可回收字节上限排序。拆开混合目录核查，记录上限、实际入选字节和排除原因；归档方案另扣归档自身的逻辑字节。
   - 历史副本与当前源码不一致时，沿生成脚本定位原始路径，验证副本能从固定提交可达的 Git blob 逐字节恢复。源码 TAR 另需用原命令、路径参数复现整包 SHA；若仅有成员相似或同名工作树，继续保留。
   - 对签名模块暂存件，分别核对文件名中的模块标识、目录清单及 ZIP 实际字节 SHA。确认现用读者、旧局保留清单、独立原件及历史载荷成员后，为退役副本登记可恢复的位置。
   - Git 对象存在但分支或标签不可达时，先核实对象在原 TAR 之外独立存在，再把恢复所缺的对象和目录树持久保存。用只含固定提交可达历史的隔离对象库做反向检查，确认缺失对象无法读取，再导入恢复包。整包长度与 SHA 均一致且恢复材料已持久化后，才可退役原 TAR。
   - 载荷按实际读者的字段判定范围。验收中的 candidateDirectory 可以绑定整棵候选目录；archivePath 绑定 ZIP，旁边的展开目录要另查。核对嵌套载荷时记录外层归档、内层成员名和最终文件 SHA；所有解码成员都相同也要单独比较 ZIP 原字节。已结束的一次性台账若仍需全文，可按原相对路径归档并绑定执行回执，计算收益时扣除索引和归档开销。
4. 用执行台账核对实际删除与缺失项，用同口径终值报告净减量、目标差额和剩余大头。重验链接、恢复依赖和当前交付。把本轮数字及新判断依据登记到[项目瘦身记录](../../../docs/reference/project-slimming.md)，可跨任务复用的经验补到方法论。历史路径和哈希只证明当轮结论。
