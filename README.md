# TableMax

Windows 局域网数字桌游平台。电脑运行本地服务、管理对局并展示公共牌桌，玩家通过各自手机的浏览器加入和操作。平台负责动作校验、规则执行、计分与存档，将公开局势和个人信息分别呈现在公共屏与玩家端。

适用于同一地点的多人聚会，可连接电视或第二块屏幕展示牌桌。游戏资源随程序提供，正式对局不依赖互联网。

| 游戏                           | 人数   | 已实现的对局内容                                               |
| ------------------------------ | ------ | -------------------------------------------------------------- |
| 《宝可梦奇遇：皮卡丘和朋友们》 | 2–6 人 | 卡牌能力、自动计分、小局结算与三胜大局                         |
| 《现代艺术》                   | 3–5 人 | 公开竞价、一次出价、暗标、定价与双拍，四轮行情和资金结算       |

三款游戏均支持真人与本地电脑玩家混合入座。人机提供“默认／豆包／绝悟”三档策略，由各游戏独立实现，运行时不调用在线模型。

规则采用范围与出版版本差异分别记录在 [宝可梦规格](docs/games/pokemon-encounters/README.md)、[现代艺术规格](docs/games/modern-art/README.md)和[电力公司规格](docs/games/power-grid/README.md)。宝可梦六人玩法属于项目扩展；电力公司采用经典版，不混用 Recharged。玩法教学由参与者在线下完成。

## 产品能力

- **手机操作与公共展示**：手机扫码入座，查看本人信息并提交动作；公共屏只读展示公开牌桌、行动进度和结算。
- **可选头像与游戏介绍**：26 个本地头像预设，含 20 个新增 imagegen 头像；服务端先确认的玩家优先占用，已被选择的头像标记并禁用。盒子按所选游戏展示核心玩法和胜利目标。
- **自动规则与信息隔离**：服务端校验动作并执行规则。手牌、现金及秘密出价按各游戏的信息权限投影到对应身份。
- **持久化与恢复**：已确认动作自动保存，支持暂停、决策点回退和重启恢复；同设备、同地址下可恢复手机身份。
- **连续对局**：再玩一局保留身份、座位和人机设置；大厅或对局结束后可切换兼容游戏。
- **独立大屏**：管理员与公共屏使用独立窗口，支持全屏、720p 至 4K 显示预设及分别保存的界面缩放。电脑公共屏优先播放声音；现代艺术手机可独立解锁提示音并保存静音偏好。
- **决定倒计时**：电脑盒子设置统一调整，默认 20 秒、15 挡非线性滑动选择 5–120 秒；到时提醒，仍可继续操作。暂停冻结，恢复继续。现代艺术选画不显示倒计时。
- **现代艺术展示**：明确行情数量与每幅收益，厚色框及独立顶部大角标辅助辨识；画作按画家聚组，纵向滚动、每行至少两幅。三端提供本地真实截图的图文规则卡片；五种拍卖分别使用主题音效与全屏开场，保存后触发。公开报价保留正在输入的金额，同价确认可并发保存；人机按估值跳价，三档有不同历史记忆与跨轮规划。
- **电力公司牌桌**：参考经典实物的德国地图与工业厂景，支持地图缩放、拖动、城市费用预览、逐厂采购／混燃及终局实际供电排名；现金只向本人公开，短工业音效表达保存结果。

## 运行要求

| 项目   | 要求                                       |
| ------ | ------------------------------------------ |
| 主机   | Windows 11 x64，系统共享 WebView2 运行时   |
| 玩家端 | 每位真人使用自己的手机，通过浏览器访问主机 |
| 网络   | 电脑与手机处于可互相访问的同一局域网       |
| 公共屏 | 电脑屏幕，或连接电脑的电视／第二块屏幕     |

便携包内含 Node.js，无需另行安装。缺少 WebView2 时，程序提供安装入口。主机须在对局期间保持运行；访客网络隔离或防火墙可能阻止手机连接，程序的“连接帮助”提供排查入口。

## 开始对局

1. 下载并解压便携包，运行 `TableMax.exe`。
2. 在电脑端选择游戏，通过“连接帮助”选择手机可访问的 Wi-Fi 或以太网地址。
3. 玩家用各自手机扫码，输入昵称、选择空闲头像后入座并准备；电脑管理员按需添加人机并调整座位。
4. 全员准备后开始对局。需要大屏展示时，在电脑菜单中打开公共屏窗口。

电脑管理员不占玩家座位，负责游戏选择、座位与人机管理、授权及回退。可指定一位真人为手机房主，由其处理开局、下一小局或下一轮、再玩一局、暂停与恢复。

手机入座确认超时可重试；刷新或重连时应使用原设备和原地址。电脑可通过 `F11` 切换全屏，通过 `Alt` 打开原生菜单。

玩家可在大厅或对局结束后的盒子更换本人头像，对局进行中锁定。头像随身份保存，离线、恢复、续局和兼容的游戏切换均保留；成功更换、移除座位或清空牌桌后释放原头像。在盒子点击“玩法”可查看所选游戏如何行动、怎样获胜；玩法教学仍由参与者在线下完成。

## 存档与续局

界面显示“已保存”后，动作已由服务确认。重新启动程序会恢复已保存对局并暂停，等待房主继续。手机在原设备打开原地址可恢复已有身份；身份不会跨浏览器或地址迁移。

存档默认位于当前 Windows 用户本地应用数据的 `TableMax` 目录。备份与排障应保留 SQLite 及其 WAL／SHM 文件，具体操作见 [开发环境](docs/reference/development.md)。更换整批参与者时，由电脑管理员确认“清空牌桌”。

## 项目与开发

前端采用 React／TypeScript，平台服务使用 Node.js 与 SQLite；Windows 桌面采用 C# WinForms／.NET Framework 4.8 和共享 WebView2。各游戏的规则、策略与界面集中在 `games/<id>/`，资源集中在 `assets/`，通过通用契约接入平台。

从源码构建的环境准备、锁定工具链与检查命令以 [开发环境](docs/reference/development.md) 为准。接入新游戏请阅读 [游戏开发指南](docs/game-development/README.md)。
