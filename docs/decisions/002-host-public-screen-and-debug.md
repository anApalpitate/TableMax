# 002：公共大屏兼房主管理与调试模式

2026-10-01。状态：界面合并及增加调试模式已由用户明确确认；调试信息范围、修改能力及恢复语义待答，尚未实现。

## 问题与依据

此前需求基线与工程基础把公共屏、手机和房主管理作为三个界面入口。用户在第二阶段规则确认中明确要求“房主管理界面等于公共大屏”，并要求房主界面增加调试模式，可查看更多信息及执行额外操作和修改。按用户最新指示调整后续产品设计，保留第一阶段既有工程验证结果。

## 已采用选择

- 桌面公共大屏兼房主管理，在同一界面呈现对局和房主操作；手机继续承载本人游戏动作及授权信息。
- 用户所说主机展开全部弃牌，归属该合并桌面界面；手机普通视图仍只显示弃牌堆顶。
- 房主界面增加显式调试模式，详细字段、动作及显示范围通过[规则确认清单](../tasks/phase-02-rules-and-interaction.md#规则确认清单) Q23 确认。
- 服务端继续校验普通管理动作和玩家动作的身份；界面合并采用同一视觉表面，身份与动作授权按服务端权限执行。

## 未确定范围

调试是否可以查看全部暗牌、牌库／随机状态，能否改牌、牌序、分数或阶段，以及这些信息是否直接呈现在所有人可见的大屏，均待用户说明。调试动作如何保存、形成历史／恢复边界、影响当前待处理选择和退出调试后的继续游玩，须依据最终能力清单接续定义；本决策不预先授予未明确的修改权限。

普通模式仍按规则投影秘密信息；调试模式的例外字段单列。房主若参赛，手机继续以本人玩家身份进行初始翻牌及游戏操作。

## 落地与交接

当前正式工程与独立原型仍是三个角色入口／布局，没有实现界面合并或调试能力。此前三入口检查及截图是其当时实现的证据，继续保留。

第二阶段先更新界面、权限与决策规格；第三阶段接合并界面和管理授权；第四阶段按确认的调试动作清单补可靠提交、历史与恢复；第五阶段接游戏字段和实际显示。通用协议／SDK 本轮不修改。普通模式和调试模式须分别记录规格走查与后续产品验收，不能沿用旧三入口走查宣称新模式已验证。

本决策更新 [001 工程基础](001-engineering-foundation.md) 的后续产品界面划分；独立服务、服务端权威、身份连接不回退、本地资源及前端工程方向继续沿用。实际行为规格集中在[通用交互与交接规格](../reference/phase-02-platform-spec.md#公共大屏兼房主管理与调试模式)。
