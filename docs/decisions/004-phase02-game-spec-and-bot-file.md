# 004：首版采用版本与独立策略入口

2026-10-01。状态：第二阶段设计采用；第五、六阶段已实现正式规则、独立策略及所需 SDK 演进，当前验证见 [验收记录](../reference/acceptance.md)。

用户已授权首版未知规则先中文检索，无可靠依据时自主确定合理项目方案，不再追问。规则采用版本与未取得的出版原文认证分别记录，当前使用 `tablemax-cn-s19-v1`；名称仍为用户指定简体中文版，不改用其他语言版。来源与每条项目处理在 [游戏规格](../games/pokemon-encounters/README.md) 可追溯。

游戏标识采用需求目录建议中的 `pokemon-encounters`，用于文档、后续源码和资源命名空间。稳定技术标识不等于猜测出版印次；后续原文差异通过新采用版本及显式迁移处理，不静默改变旧存档。

用户要求独立维护电脑决策文件，未指定额外文件形式，B01 由项目默认方案落定。为完成可执行交接，采用**可替换的独立 TypeScript 模块默认方案**：计划 `games/pokemon-encounters/bot/index.ts`，统一声明策略 ID、版本、兼容范围和受限输入，只返回合法意图。理由是复用已锁定语言、类型及本地构建，能覆盖多步／被动选择；无需新建配置解释器。本选择是项目设计默认，不声称用户另行确认过 TypeScript／JSON 二选一，也不推断热加载、外部脚本或编辑器承诺。

默认策略无记忆、确定性，未来策略随机使用独立可恢复随机源。策略、计分、规则、投影、UI、通信及存档职责独立；有生命周期的协调器适度对象封装，规则纯计算保持纯函数。当前 SDK 的待处理选择／多行动者／策略及自动推进缺口按 [状态与交接](../games/pokemon-encounters/information-and-decisions.md#正式初始契约缺口与交接) 在第三、四阶段演进，本阶段不改 API。

后果：出版原文未认证仍明确保留；规格可按采用版本交给后续阶段。真实策略文件、规则测试、存档兼容及正式人机完整对局需后续实现并验证，第二阶段原型不冒充真实游戏。
