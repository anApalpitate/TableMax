# 003：基础人机与适度封装

2026-10-01。状态：用户已确认新增产品与开发要求；尚未实现。具体形式已由[决策004](004-phase02-game-spec-and-bot-file.md)采用独立 TS 默认；正式 SDK API 仍由第四阶段接入。

## 问题与采用范围

原始首版需求将 AI 玩家排除在外。用户现要求在游戏中添加电脑，能对全部游戏操作作简单决策，并独立维护电脑决策文件；同时要求开发注意面向对象的适度封装以优化可维护性。

因此基础 bot 纳入首版，新增游戏也需提供其逐选择策略；不以智能强度、胜率或联网大模型为目标。原“AI 玩家不纳入首版”条款由新要求替代，调试与纠错专项仍按既有后续规划处理。

工程上对有生命周期、依赖及不变量的能力适度封装，优先组合和明确接口；纯规则、计分与投影可保留纯函数，持久化仍采用普通数据。用户要求不等于全类化、深层继承或通用机器人平台。

## 理由与后果

- 电脑策略和规则执行分开，平台负责座位、授权、调度、校验、保存与恢复，具体游戏负责完整选择策略。bot 不取得额外秘密或调试权限，也不自动接管掉线真人。
- 新增独立文件、策略版本和恢复数据约定，需要补充 SDK／注册、模板、逐节点验证与人机混合整局；文件形式及逐选择上下文已有规格，正式签名在第四阶段接入。
- 第二阶段补规格与职责设计，第三至六阶段吸收实现／验证责任；已完成的第一阶段记录保持历史范围，不将新增要求计为既有成果。
- 维护时以职责和变化点审查封装，以实际行为回归证明改动；不按类或设计模式的数量评价可维护性。
