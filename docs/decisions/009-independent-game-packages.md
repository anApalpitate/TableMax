# 009：独立游戏包、不可变发行与公共作者契约

2026-10-11用户确认，沿用v1.0.6。当前已实施核心路径，任务已按用户决定关闭，实际交付与验收边界以[验收范围记录](../reference/acceptance.md#106安装故障矩阵与验收范围调整2026-10-11)和[验收](../reference/acceptance.md)为准。

基础程序仅交付盒子、服务、共享运行时、目录与小封面；游戏按玩法安装到便携根目录 `games/`。规则、人机与网页代码和公共／玩法资源分别构建，以不可变发行引用绑定完整依赖。资源字节变化不要求重新编译游戏代码。所有客户端从主机读取资源，完成安装后的游玩不依赖互联网。

2026-10-11最新选择：游戏包与项目Ed25519签名目录采用 GitHub Pages 按版本／游戏／玩法目录发布，基础EXE、发布源码和作者工具包继续用 GitHub Release。静态目录便于浏览、共用依赖复用和独立分发，不要求每次游戏资源变化都替换基础附件。具体路径、1GB站点边界、历史包保全和手动发布入口见[Release流程](../reference/release.md#最新分发决定与暂缓发布2026-10-11)。此前v1.0.6暂撤为草稿，随后经用户明确授权，本次Pages已部署、Release已正式重新发布，公开文件及三附件核验通过；保留旧标签并审计实际发布源码映射，旧引用及同名旧包不覆盖。内置公钥核验目录，私钥不进入Git、站点、运行包或工具包；版本目录、精确文件名和哈希定位，公共契约不宣称隔离恶意JavaScript。

新实例固定规则、人机、网页、CSS和资源的同一发行引用，正在进行的实例不替换。更新原子提交安装索引，显式选择新版建立新实例；下一小局仍属于原发行。存档与回退引用阻止卸载，缺包保留数据库并提供补装，恢复保持暂停。旧内置游戏先按实际字节保全再迁移，不把旧存档猜测绑定到最新发行。

公开SDK、宿主控件和类型通过包名导入，与平台私有身份和会话适配分开。网络协议8和模块契约7各自保持兼容。外部作者工具包须脱离私有源码构建，并用隔离运行目录、数据库、浏览器配置、证据和回环端口完成真实接入。

基础EXE、ZIP及实际解压内容严格小于120,000,000字节，预警110,000,000；每个玩法完整依赖组合下载与安装各严格小于64,000,000字节，预警48,000,000。组合内公共依赖计一次，已安装游戏合计空间不受基础交付门禁限制。这些选择要求增加安装事务、历史包保护和发行审计，取代依赖覆盖文件与清空模块缓存的更新方式。
