# 009：独立游戏包、不可变发行与公共作者契约

## 唯一完整 EXE 交付（2026-10-12）

Windows 只导出预装全部正式游戏及玩法的完整 EXE，文件名不加类型后缀。游戏仍独立组织和增量构建；不可变模块仓库仅用于程序内部预装和原局恢复。取消盒子版、游戏下载、游戏 ZIP 导入、独立更新／卸载／回退及安装型作者工具包导出。新局以本 EXE 验证后的预装映射为准，旧安装索引和缓存目录不能覆盖。旧存档固定原发行；本机原版本保留，缺失时保留存档并提示使用包含原版本且支持存档格式的旧完整 EXE。本轮仅本地导出，不发布、不部署 Pages、不生成源码 ZIP。

选择唯一完整EXE是为了让首次运行及升级始终提供完整、经验证的游戏集合，同时保留模块独立组织与原局恢复。`PackageStore.current`仅来自本EXE验证后的预装清单，旧安装选择或线上缓存不能改变新局发行；当前模块缺失或损坏从本地载荷修复，不能回退旧包。公共SDK、模板和源码接入继续保留，新增游戏随新的完整EXE交付。

旧局有 `releaseRef` 时固定原规则、策略、网页和资源；无引用时按精确版本元组匹配。所有非当前发行运行时标记 `restoreOnly`，只继续原局；旧大厅开局及结束后再玩切当前，原局内部下一轮仍保持旧发行。旧版本缺失、匹配不唯一或接口不兼容时保留原数据，提示所需旧完整EXE；不加恢复ZIP导入或额外预装历史版本。可替换运行目录外的历史模块仓库及升级前旧内置字节仍受保护。

## 2026-10-11独立安装体系（已退役）

以下旧安装／分发章节保留其实施与历史边界，涉及独立游戏下载、盒子版及 Pages 的操作已退役，不作为当前使用指南。

2026-10-11用户确认，沿用v1.0.6。当轮已实施核心路径，任务按用户决定关闭，历史交付与验收边界以[验收范围记录](../reference/acceptance.md#106安装故障矩阵与验收范围调整2026-10-11)为准，当前完整EXE验收另见[现行交付](../reference/acceptance.md#当前源码与本地交付)。

基础平台包含盒子、服务、共享运行时、目录与小封面；游戏按玩法安装到便携根目录 `games/`。当时日常导出 full／box 两种 EXE：full 预装当前游戏，box 通过下载或离线导入安装；内部载荷 ZIP 用于组装及验收，不对外作为运行包。规则、人机与网页代码和公共／玩法资源分别构建，以不可变发行引用绑定完整依赖。资源字节变化不要求重新编译游戏代码。所有客户端从主机读取资源，完成安装后的游玩不依赖互联网。

2026-10-11当时选择：游戏包与项目Ed25519签名目录采用 GitHub Pages 按版本／游戏／玩法目录发布，基础EXE、发布源码和作者工具包继续用 GitHub Release。静态目录便于浏览、共用依赖复用和独立分发，不要求每次游戏资源变化都替换基础附件。历史路径、1GB站点边界、包保全与当时发布入口见[Release流程](../reference/release.md#最新分发决定与暂缓发布2026-10-11)。此前v1.0.6暂撤为草稿，随后经用户明确授权，当轮Pages已部署、Release已正式重新发布，公开文件及三附件核验通过；保留旧标签并审计实际发布源码映射，旧引用及同名旧包不覆盖。内置公钥核验目录，私钥不进入Git、站点、运行包或工具包；版本目录、精确文件名和哈希定位，公共契约不宣称隔离恶意JavaScript。现行不再新增这些分发产物，本轮不改变既有线上内容。

新实例固定规则、人机、网页、CSS和资源的同一发行引用，正在进行的实例不替换。更新原子提交安装索引，显式选择新版建立新实例；下一小局仍属于原发行。存档与回退引用阻止卸载，缺包保留数据库并提供补装，恢复保持暂停。旧内置游戏先按实际字节保全再迁移，不把旧存档猜测绑定到最新发行。

公开SDK、宿主控件和类型通过包名导入，与平台私有身份和会话适配分开。网络协议8和模块契约7各自保持兼容。外部作者工具包须脱离私有源码构建，并用隔离运行目录、数据库、浏览器配置、证据和回环端口完成真实接入。

基础EXE、ZIP及实际解压内容严格小于120,000,000字节，预警110,000,000；每个玩法完整依赖组合下载与安装各严格小于64,000,000字节，预警48,000,000。组合内公共依赖计一次，已安装游戏合计空间不受基础交付门禁限制。这些选择要求增加安装事务、历史包保护和发行审计，取代依赖覆盖文件与清空模块缓存的更新方式。
