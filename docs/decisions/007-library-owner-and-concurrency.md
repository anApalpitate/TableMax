# 007：游戏目录、手机房主与独立提交

2026-10-02 用户确认，1.6.0 采用。目标是让电脑专注管理与展示，朋友在手机完成常用对局控制，并为其他游戏保留清晰接入边界。本轮不新增完整游戏，内部模板只用于切换与契约验证。

以下协议6、单游戏目录、手机房主旧权限、删除换手机和5／4GiB维护门槛是1.6.0当轮事实。当前完整EXE预装六款正式游戏，目录只取当前预装映射；手机房主增加移除其他席位及人机改名，换机改为管理员批准接续，详见[平台规格](../reference/phase-02-platform-spec.md)。日常瘦身默认超过10GiB清到8GiB，2026-10-12深度瘦身另按用户当轮6GB目标完成，不能将历史门槛用于当前维护，见[瘦身记录](../reference/project-slimming.md)。

- 协议升级为 6；新房间没有当前游戏，管理员从目录选择后才加载对应规则、策略、UI、样式与资源。已有存档按 manifest 加载，正式目录只公开宝可梦。大厅／结束可切换，保留身份与席位、清准备；进行中和不兼容配置拒绝，加载或保存失败保持原状态。静态模块缓存可复用，离开游戏清理有生命周期的资源。
- 电脑 host 是管理员；ownerSeatId 是一位真人手机房主。手机房主可开局、下一小局、再玩一局、暂停／恢复，不能改座位、结束、清空、回退或切换测试模式；公共屏始终只读。授权保存在房间层，原班续局保留，移除座位／清空撤销，回退不恢复旧授权。
- 删除换手机入口、兑换接口、绑定码与当前协议；格式 1 的历史 bindings 可兼容读入后丢弃。可靠入座仍保留请求密钥、事务回复和同编号重试。同设备同源刷新／断线不丢身份。
- 不放宽所有旧修订：只有规则明确声明的独立 concurrencyGroup 和同座位准备窗口可接受仍有效的旧快照。宝可梦首翻决策按小局和座位稳定编号；同人双击、准备取消后的旧准备、暂停／恢复／回退／换局后旧请求仍被拒绝。串行事务和去重保持。
- 玩家选择按决策 token 保存，动效按已保存修订触发；别人独立翻牌不清本人选择。声画只使用授权投影，公开反馈不包含私看位置。桌面公共屏优先且全窗口去重，手机静音。
- 每次事务复制可变容器，共享不可变 checkpoint，规则本身仍纯变换。保存失败与回退不能修改已发布状态；不裁剪历史，不声称长期内存有界。维护检查在工程进程退出后执行，超过 5 GiB 清到 4 GiB 或安全候选耗尽，保留全部路径／进程／链接／近期修改及 ZIP 证据保护。

接口及接入见 [扩展指南](../reference/game-development.md)，实现边界见 [工程结构](../reference/architecture.md)，实测与限制见 [1.6.0 验收](../reference/acceptance.md#160盒子对局体验与可靠性)。

2026-10-11阿瓦隆密投沿用规则独立窗口和串行事务：策略声明并发后，所有待密投人机独立等待、计算和提交；同组他席保存不取消剩余任务，迟到结果仍验证本人决策、分支、窗口底水位和源策略数据。测试直接微任务启动，没有0ms或40ms准备等待；取消结果不记作策略故障。该变更不放宽其他游戏的修订校验，详见[人机规格](../reference/bot-players.md#声明式立即动作与并发密投2026-10-11)。
