# 006：首版完整游戏与模拟交付

2026-10-01，已落地。范围是第五、六阶段，当前交付版本 1.0.0。规则采用 `tablemax-cn-s19-v1`，官方原文／印次认证仍按 [来源页](../games/pokemon-encounters/sources.md) 分开记录。

## 设备校验范围

用户明确使用当前 Windows 电脑、外接屏目标为电视，并要求开发中无需实际用电脑之外的设备，只通过模拟校验。采用当前电脑真实 Electron／独立服务，1920×1080 电视视口与 Android／iPhone 尺寸、触控、UA、后台冻结和断网导航模拟；便携包在新解压目录、仅系统 PATH 下运行。

选择该范围避免把设备购买或现场接入变成开发前提。Chromium 模拟不宣称实际 Safari、电视硬件、手机锁屏或另一台无开发环境电脑已测；声音验证解码／播放调用，不宣称现场听音。AC 对应和范围见 [验收记录](../reference/acceptance.md)。

## 主题资源

最初角色绘画请求被内置图像工具拒绝，失败记录保留。随后采用独立的原创植物、矿物和天气静物，不包含角色／动物形象或相似轮廓；类别名称、数字与能力仍由代码清晰显示。这是已授权资源制作内的自主方案，未把无回复的可选偏好询问写成用户明确选择，也不把图片称为出版卡图。

20 张 WebP 与 5 类原创短音本地打包；提示词、原图、版本、尺寸／哈希和视觉核验分别保留。既有自然背景候选不另作页面大背景；使用主题封面及 CSS 色彩维持阅读对比度，候选仍保留。详细来源和映射见 [资源](../games/pokemon-encounters/assets.md)。

## 原子能力与反馈

火箭队皮卡丘效果的同位弃底和全部补位无额外玩家选择，因此在一次规则执行和 SQLite 事务中完成。只恢复玩家动作前或完整效果后，避免半补位存档和 UI 动效阻塞规则。闪电鸟每个接牌者有独立决策；正常 turnSeat 保持原发起者，当前 actor 独立计算。

房主参赛通过加入时校验主机凭证记录 hostSeat，同时取得独立玩家身份；管理投影仍不显示本人的游戏秘密。安全公开事件仅在保存成功后广播，带实例／分支／修订去重；同步、重复确认、回退不补播。规则／计分、普通存档和独立策略继续遵循 [工程边界](../reference/architecture.md)。

## 1.1.0 美术维护变更

2026-10-02 用户要求卡面贴近原版宝可梦和实物，每类独立制作并统一角标，替代旧自然静物方案。16 次独立生成只有百变怪成功，其余明确审核拒绝；为落实角色外观，14 类角色及喵喵采用中文官方图鉴原图，火箭队采用香港官方动画群像，逐张记录导入／生成区别。牌框、分值、名称仍用代码排版，全部资源集中根目录 assets、可替换；旧素材与历史证据保留。当前来源和限制见 [资源规格](../games/pokemon-encounters/assets.md)。测试改为后台隐藏 offscreen 渲染，不 showInactive 或聚焦。
