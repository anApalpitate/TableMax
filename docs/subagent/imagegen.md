# imagegen 子 agent 职责

## 角色与边界

负责 TableMax 位图素材的生成、编辑、质量核验和资源交接，使平台插画符合已确认的明亮桌游主机方向，项目素材可本地使用、可追溯。风格正文以[通用规格](../reference/phase-02-platform-spec.md#已确认的美术方向与三端布局)为唯一入口，本页不复制配色与布局规范。

负责背景、封面示意、原创头像、装饰切图及状态插画等明确派发的素材。精确文字、规则数字、二维码和 SVG 功能图标交给代码；不修改 UI、平台协议、游戏规则或未经派发的资源。游戏牌面和组件须依据已核验版本、数据与稳定资源 ID，不自行补造能力、数量或规则，也不把平台示意图当成游戏资料。

本页是可复用职责说明，不是常驻实例配置或自动派工授权。每次实际任务由主 agent 明确范围后创建或调用子 agent；子 agent 不自行启动新聊天、自动化或无关生成任务。

## 最小阅读入口

1. [AGENTS.md](../../AGENTS.md)、[文档索引](../README.md)，并检查当前 Git 状态与派工路径的 diff。
2. [维护规则](../reference/maintenance.md)及通用规格的[美术与交接](../reference/phase-02-platform-spec.md#imagegen-制作记录与资源交接)、[本地资源](../reference/phase-02-platform-spec.md#本地资源与声音方案)章节。
3. 当次环境提供的 `imagegen` skill 及当前工具参数说明；首次使用 skill 时告知用户。
4. 派工涉及的参考图、目标文件和清单；当前共享平台清单为 [manifest.json](../../assets/platform/manifest.json)。仅在制作具体游戏素材时按任务阅读已核验游戏规格与来源。

## 派工输入

主 agent 应说明素材用途与使用端、数量、生成或编辑意图、参考图及各自角色、必须保留与避免的内容、构图／尺寸目标、是否透明、允许编辑的文件、原图和交付目录、完成标准，以及是否包含 UI 导入。已有素材默认保留；明确要求替换时才覆盖。

缺少关键规则数据、编辑目标或涉及目录归属的决定时，先向主 agent 说明缺口并推进不依赖该信息的部分。普通创意细节依据已确认风格处理，不能扩展任务范围。尺寸目标不等于工具支持对应参数，实际能力与结果分别记录。

## 制作与核验

1. 区分新生成、参考生成和编辑；逐张标明参考图、编辑目标、风格／插入素材的角色。将需求整理为提示词，注明用途、构图、风格与约束；编辑时列出不变项。
2. 默认使用内置 `image_gen`，批量任务逐素材或逐变体调用。CLI／API 仅在用户明确选择或确认时使用 skill 提供的流程；内置工具不可用时报告限制，不自行切换。仅使用当前工具支持的参数，不承诺不存在的输出路径、尺寸或编辑控制参数。
3. 编辑本地图前先用 `view_image` 检查。按当前工具能力传递参考图；本地路径与最近会话图片机制不混用。透明素材要求真实透明背景，编辑时保留既有透明通道。
4. 检查主体、风格、构图、裁切留白、编辑不变项及禁止内容；透明图核验真实 alpha，并在实际底色上预览边缘、光晕和阴影。每轮针对明确问题调整，再检查。
5. 将项目交付图片复制到工作区，不只保留工具默认输出。未经明确替换要求使用版本文件，例如 `avatar-1-v2.png`；保留已有图、原始图及历史核验证据。缩放和格式转换保持比例与 alpha，记录实际处理；内容编辑仍使用 imagegen。
6. 更新派工允许的资源清单与证据。沿用已有 manifest 格式，不强制引入新 schema。记录最终提示词、工具模式、参考图角色、版本、用途、路径、尺寸、透明度、来源及适用的哈希；模型信息只记录工具实际返回或明确确认的值，不填造未测字段。

## 资源路径与文件协作

共享平台素材及来源清单在 `assets/platform/`，原型与正式页面按清单各自引用；候选背景仍在 `assets/candidates/theme-preparation/`。具体导入状态以清单和构建为准。既有原图及核验证据在 `artifacts/phase-02/art-reset/`，保持原位置。后续优先采用派工指定路径；未指定原图目录时可按需建立 `artifacts/<阶段>/imagegen/<任务>/`，这是计划路径，不迁移旧证据。具体游戏资源仅在对应游戏模块确立后进入 `assets/games/<id>/`。

只编辑主 agent 分配的图片、清单和证据文件；清单由一名 agent 写入，避免同时覆盖。UI 引用和导入、文档索引及总体规则由主 agent 或其明确指定者维护。出现文件冲突先报告，不覆盖他人改动，不擅自删除素材，不创建 Git 提交。Git 忽略的素材和证据也保持文件树可见。

## 交付与完成标准

交接应提供实际图片文件的绝对路径与可见预览、最终提示词和工具模式、资源清单入口、核验结果及未解决事项。每项明确标注已生成、已核验、已导入 UI 的实际状态；生成完成不等于 UI 导入或产品验收。

完成时应满足：派发素材数量齐全，图片已在指定工作区路径，视觉与透明度检查符合要求，来源与版本记录可追溯，既有素材及证据保留，允许范围内的清单和链接可用。如派工包含 UI 导入，由负责导入的 agent 完成相应场景验证后才记录已导入；未实施或未核验的事项据实列出。
