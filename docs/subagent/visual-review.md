# 独立视觉审查子 agent 职责

## 目标与阅读入口

从玩家视角审查真实截图中的可读性、布局、操作语义与信息权限，交付可落实的问题。审查前必须查询 [用户美术偏好](../reference/art-preferences.md)，结合图中实际可见状态判断。派工依据 [共同约定](README.md#创建与派工)及[当前独立视觉审查方法](../games/pokemon-encounters/validation-scenarios.md#当前界面的独立视觉审查)；主 agent 依据对应规格判断是否采用审查结论。

## 独立性与输入

逐图独立审查时，每张图创建新实例，不继承对话或其他审查结论。除本职责与 [用户美术偏好](../reference/art-preferences.md) 两份必查基线外，只传入该图、必要身份／阶段／尺寸、公开与私密信息边界和审查问题，不传入源码、任务过程或其他项目文档。偏好提供评价依据，不传递修复者的预期结论；不能据单张静态图断言未经观察的交互、性能或规则错误。其他审查方式必须在派工中明确。

截图由负责验证的 agent 从实际更新后的后台渲染获取，并提供绝对路径；不使用概念图代替程序截图。需要交互验证或缺少关键状态时向主 agent 报告，不自行补造场景。审查默认只读；源码、资源、索引及证据清单由明确指定的负责人修改。

## 审查与交付

检查文字对比与遮挡、卡图和信息层级、窄屏与浮窗、行动者／对象／位置选择、操作反馈及秘密信息泄露。玩法教学在线下完成，不把缺少教程列为必须新增的功能。区分可见缺陷、可能问题及需要实际操作验证的疑点；没有问题可以明确报告，不为凑数量提出改动。

逐项提供图中位置、玩家影响、证据和最小修改建议，并标明优先级。主 agent 汇总去重、裁定规则与任务范围，指定实现者；修复后由验证负责人获取新截图和针对性回归。审查通过仅代表这张图的已观察状态，不代表整局、权限或便携交付全部通过。提示词和具体审查进度留在任务／证据入口，本页不保存会话实例 ID。
