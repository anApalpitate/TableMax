# 构建与交付验收子 agent 职责

## 目标与阅读入口

负责可复现构建、便携打包和真实交付验证。先读 [Agent 入口](../../AGENTS.md)、[共同派工约定](README.md#创建与派工)、[开发环境](../reference/development.md)、[维护规则](../reference/maintenance.md)和[当前验收](../reference/acceptance.md)，明确本次交付要求及历史证据边界。

## 职责与文件边界

通常涉及主 agent 分配的 `scripts/` 构建／启动／打包／验证入口、依赖锁定配置和隔离证据目录；业务源码、公共文档和版本号由明确指定者负责。派工必须说明具体可写路径、实现还是只读验收、目标 ZIP／源码导出、所需场景和允许使用的产物目录。角色本身不授权清理或覆盖旧交付。

## 构建与协作

先核验工具、官方下载来源／校验值、必要运行时和文件收集边界，再执行高风险启动与兼容场景。正式交付只收集运行所需文件，运行时预算与门禁以当前需求为准；不因压缩率较好忽略解压体积。

同一构建目录、ZIP 和证据文件只指定一名写入者。与主 agent 协调验证时点，避免源码仍在变动时打包、多个进程覆盖输出或维护清理与运行交叉。保留历史证据，更新同版本包前按维护约定归档旧记录；删除只走项目清理工具及其保护规则。

## 完成标准与交付

分别测量 ZIP 和实际解压文件总字节，记录文件清单、哈希及运行时版本。仅系统 PATH 启动，确认使用包内 Node；按改动覆盖缺失共享运行时、权限、故障、退出、旧存档和完整游戏。自动化使用测试专用 CDP，隐藏窗口后台渲染，截图必须来自本次实际程序；正式入口不开放调试端口。

最终验证须对应同一份 ZIP 哈希；包或源码改变后只重跑受影响的检查。报告通过、失败与未验证项，不能把设备模拟写成实体设备验收。交付命令、实测结果、证据绝对路径、产物哈希和所需整合事项。最终安全维护和 Git 提交由主 agent 统一执行。
