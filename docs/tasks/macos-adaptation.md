## 任务目标与范围

用户目标：支持导出 macOS 上可用的运行文件，优先选择最小风险、最少改动面的方案，并建立专门任务文档。本轮只建立文档，不执行导出或发布。

现有任务索引记录的2026-10-11范围为**仅导出 macOS 服务端运行包**，不包含原生桌面外壳移植、构建流程改造或验收流程实施。2026-10-12的分析与文档请求未明确扩大这一范围；本任务沿用该边界。此前分析中的 Swift／AppKit + WKWebView 属于完整桌面体验的备选，不作为本任务实施内容。

交付目标：导出含对应 macOS Node 运行时、现有服务、Worker、网页及全部当前正式游戏完整运行产物的独立运行包，附启动与停止说明。用户无需安装 Node 或开发工具；玩家继续通过浏览器操作。保留现有权限、离线游玩、保存恢复与游戏发行边界，Windows交付按2026-10-12要求统一为完整EXE；本任务不实施Windows变更。

2026-10-12用户补充：**Mac版本只支持导出完整全游戏版**。导出仅提供full内容，不提供box／仅盒子版或选择部分游戏的导出方式。完整包包含导出时全部当前正式游戏的规则、策略、网页、资源与必要共享依赖，首轮运行现有游戏无需另行下载或导入；内部template不属于正式游戏。该要求限定Mac导出内容，不改变仅服务端运行包的任务范围，也不改变Windows当前唯一完整EXE交付。

管理员浏览器入口是否包含在包内尚待明确。支持系统、Apple Silicon／Intel架构、包格式与执行日期尚未确定，下面均为执行草案，不写成用户已确定的产品要求。没有真实 Mac 运行证据时必须标注“未验证”，不宣称完整 Mac 桌面支持或已通过产品验收。

## 当前实现与复用依据

- `apps/server/src/entry.ts` 提供独立服务入口，也支持 `--desktop-pipe` 私有 stdin／stdout 协议；独立启动不输出管理员凭证，直接打开 `/host` 不获得管理员权限。
- 服务存储使用 Node 内置 `node:sqlite`，bot 由独立 Worker 执行。现有网页、规则、策略和资源已分模块，优先收集现成运行产物，不改游戏玩法或人机策略。
- `tools/build/setup-desktop.mjs` 固定 Windows x64 与 `node.exe`；现有桌面组装包含 WinForms、WebView2及Windows运行文件，不能直接把完整Windows目录重命名为Mac包。
- Node 22.14.0有官方darwin-arm64／darwin-x64发行及校验清单，可以保持当前服务运行时版本；仍需核对对应系统要求。
- 网页已有Safari 16构建目标，但构建目标不等于实体Safari或全部游戏验收。

工程职责查[工程结构](../reference/architecture.md)，现有Windows体积与原生体验取舍查[决策008](../decisions/008-small-native-desktop.md)。执行前重新检查相关diff，尤其版本、模块兼容性、预装映射、历史恢复和打包的已有改动，不覆盖其他任务成果或将其混入本任务提交。

## 最小风险路线

推荐草案：**收集可移植的现有服务运行产物 + 官方Mac Node + 启动／停止脚本与说明**。只增加导出所必需的窄范围收集和平台启动适配，不改造全项目构建流程，不移植Windows宿主，也不首轮引入新的桌面框架。

| 路线                           | 本任务适用性     | 风险与取舍                                                       |
| ------------------------------ | ---------------- | ---------------------------------------------------------------- |
| Mac Node + 服务产物 + 启动脚本 | 推荐执行草案     | 改动最小；需处理路径、执行权限、网络监听、数据目录及退出         |
| 服务启动器自动打开浏览器管理   | 待明确范围       | 必须设计受保护的本机管理启动方式，不能直接暴露凭证               |
| Swift／AppKit + WKWebView      | 当前范围外的备选 | 可保留完整桌面体验，但新增双窗口、桥接、声音、生命周期及签名实施 |
| Electron或全平台跨平台宿主迁移 | 当前不采用       | 增加运行时、体积、维护和Windows回归面                            |

建议分别收集arm64与x64运行包，避免首轮Universal合包；实际覆盖以确定的目标架构为准。运行包建议为可解压目录及启动脚本，压缩容器和文件名待确定；不沿用Windows EXE自解压方案，不把此前建议的`.app`／`.dmg`视为本任务交付要求。

## 必须保留的边界与风险

1. **管理员权限**：独立服务不输出管理员凭证。若确认需要浏览器管理，先明确受保护的本机启动方式，可评估复用私有管道；不通过普通日志、命令行或开放HTTP初始化接口泄漏凭证。不以页面路由替代授权。
2. **进程与停止**：复用服务的SIGINT／SIGTERM和正常保存关闭路径，记录如何停止自身服务，避免误杀其他Node进程。脚本退出是否停止服务需明示，不能借用Windows Job Object行为作Mac保证。
3. **数据与资源**：明确配置、存档、日志及预装／历史模块仓库的位置；不可写时报错，不静默回退或操作正式存档。服务、Worker、网页与资源全部使用实际包路径；旧数据搬迁不在未经授权时自动执行。
4. **网络**：默认本机试跑监听`127.0.0.1`，局域网使用时明确选择监听与可达地址；端口冲突、网络权限及防火墙提示如实说明，不全局放行或关闭防火墙。
5. **游戏模块**：核对内部签名清单及代码／资源模块的可移植性，保持发行引用、哈希、权限及存档保护，不为Mac导出改写历史签名模块。全部当前正式游戏必须随完整运行包提供并可离线运行，新局只采用本包验证的当前映射，原局恢复固定原发行；原版本缺失时保留数据并说明所需程序版本，不新增游戏下载、离线包导入或独立安装能力。
6. **平台与分发**：Windows可以准备可移植产物和Mac运行时，但不能据此声明Mac实际可运行。执行权限、下载隔离属性、系统安全提示、Node系统要求和浏览器兼容性需在说明中保留边界；不推荐关闭系统安全机制。签名／公证或原生应用分发若成为必要要求，另行明确范围。
7. **容量**：记录下载与实际目录逻辑字节，不能照搬Windows包通过结果。现行Windows120,000,000字节门禁不变；Mac门禁尚未确定，不预先承诺达标。

候选导出辅助逻辑归`tools/release/`，不预建Mac原生宿主目录；实际输出目录、平台文件名、缓存与清理保护在执行时确定并同步[目录职责](../reference/project-structure.md)。沿用现有资源，不开展美术改版。
