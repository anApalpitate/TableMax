## 美术方向：小怪虫的恶作剧牌桌

建议用明亮、带纸张与印刷质感的卡通牌桌：八类动物的古怪表情和动作是主角，桌边少量虫迹、贴纸、切纸边与局部阴影提供细节。暖浅底、墨色轮廓与来自原牌的物种色构成辨识；具体色值在实际样板中确定。

丰富细节集中在插画、牌背、桌沿和关键演出；承载信息的名片、操作托盘与浮窗采用简洁平面，减少套框、重复标题和装饰性分隔线。桌面中区优先给在途牌与揭晓，周边给玩家与风险；手机优先给当前动作与本人手牌。背景不占用交互热区，不靠巨大插画背景冒充主体占比。

所有游戏内页面统一重做：游戏主画面、出牌／接牌／查看后转传、等待与揭晓、终局、规则浮窗及游戏内菜单。平台管理和设置复用上游控件及权限，改游戏侧组合和外壳；盒子及其他游戏不扩散改造。

## 用图像表达玩法

| 信息               | 新表达提案                                   | 必须保留的语义                           |
| ------------------ | -------------------------------------------- | ---------------------------------------- |
| 谁正在行动         | 玩家头像高亮、当前操作托盘激活               | 不仅靠颜色，不以头像替代可辨认的姓名     |
| 谁传给谁           | 头像 → 共用牌背 → 头像，细路径连接           | 座位顺序稳定，传牌者与原出牌者不混淆     |
| 声明物种           | 牌背旁独立的动物图像气泡                     | 气泡表示“声称”，不能画成已公开真实牌面   |
| 公开收牌           | 同物种实牌叠放、数字、四格／双人五格风险标识 | 阈值来自规则，保留每张真实cardId对应插画 |
| 手牌张数           | 共用牌背图标＋数字                           | 不产生对他人手牌内容的猜测或预览         |
| 已看过／可转传目标 | 路线节点及目标资格状态                       | 可选范围只来自合法动作，不仅靠降低透明度 |
| 最近结算           | 翻牌、实际收牌者、收牌入堆                   | 演出对应已保存事件，结果稳定后能继续核查 |

常驻文字只保留姓名、必要数字、短动作与当前关键状态。删除“选择一张牌、一名对手与一种声明”“声明是真的／假的”等重复解释；工具条改用可辨识功能图标并保留可访问名称。默认动作使用“相信”“质疑”“看后转传”“传出”等短词；转传承诺的不可撤回含义保留，不做成含义模糊的眼睛按钮。

每个状态最多保留一处简短状态说明；不为了零文字隐藏断线、暂停、失败、未确认、重试或关键后果。来源、加工说明和素材注释放进规则来源／文档，不常驻牌桌。鼠标说明需有触摸和键盘等效入口。

## 三套布局与共用组件

| 布局       | 构图                                                      | 交互与空间策略                                                                                     |
| ---------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 服务端横屏 | 中央大在途牌／揭晓，周围2–6个紧凑玩家区，管理入口收于角部 | 只展示公开信息，无本人手牌和玩家动作；主要信息尽量首屏可见；按上游最大画布限制居中，超宽／超高留边 |
| 玩家竖屏   | 上方紧凑对手与公共牌桌，中段当前动作，下方稳定手牌带      | 主要动作在拇指可及区；目标与声明用头像／动物图像直接选择，完整预览与确认不被挤到长页面底部         |
| 玩家横屏   | 公共牌桌与个人操作并排，手牌沿下缘排布                    | 手机短横屏压缩次要区域；宽电脑沿用同一布局规则，增大有效牌面并设最大宽度，不拉成巨大稀疏表单       |

复用牌面、牌背、物种气泡、玩家区、公开收牌、手牌带、声明选择器、目标选择器、判断按钮、结算演出和规则组件；横竖只调整区域排列与密度。角色决定授权，布局决定摆放；不能因窗口变宽就出现管理员能力。

在上游布局接口上保存一个决策草稿：所选cardId、target、claim。旋转、resize和横竖切换保留草稿，只有决策／实例／分支失效时清理；不再让展示组件重挂载意外清空选择。最终提交仍匹配当前合法动作与decisionId，适配不自动选目标或提交。

长手牌按物种分组组织实际牌带，支持单击选牌、抬起预览、局部水平浏览和分组快跳；不把一类八张不同插画合并成一张替代牌。双人27张起手、近空手牌与大量收牌均须可用。玩家公开区按当前人数收敛，不保留无用空席大卡。

## 行动流程

1. **出牌**：直接点本人牌、目标头像、声明动物；三者可任意顺序修改。一个紧凑预览组合显示本人牌 → 目标头像＋声明气泡，最终点“传出”。实际手牌预览只在本人端存在。
2. **接牌**：当前牌背与声明保持画面中心；“相信”“质疑”直接行动。“看后转传”明确承诺，保存后才显示本人获授权的真实牌面，随后只保留合法目标与声明选择。
3. **最后接收者／双人**：根据合法动作隐藏不可用的转传入口，不留一整段解释。必要短提示可为“必须判断”，规则入口提供完整原因。
4. **旁观等待**：保持牌桌、玩家风险和本人手牌可读；移除不相关操作表单，不用大段等待说明填空。暂停／断线状态单独清晰呈现。
5. **揭晓与终局**：真实牌面公开后短翻牌，移入实际收牌者区域，更新同类风险。终局按经典共同赢家表达，不能包装成只有一名冠军；“再来一局”等仍走既有权限。

## imagegen卡牌精修

实际制作由[imagegen子agent](../subagent/imagegen.md)负责，按[素材工作区入口](../../../TMP/TableMaxMaterial/AGENTS.md)交接。本轮只有加工计划。

- 从64张搜集原图精修，逐牌维持cardId、物种、姿态、构图、八张差异与经典牌框辨识；修整锯齿、压缩噪点、边缘、明暗与局部层次。原JPG保留，AI衍生另存，不称官方扫描或原图恢复。
- 先加工约三张代表牌：深色细线、明亮大片色、复杂肢体各一张，另试统一牌背；用小尺寸手牌、中央大牌和4K截图比较。样板达到身份与清晰度门槛后再扩展64张，不先批量做完再发现风格漂移。
- 牌背以现有经典灰背实拍为依据加工平整化候选，保留八动物构成，明确是照片参考的AI衍生；所有未知牌使用完全相同背面，禁止按实际物种生成不同背面。原实拍独立保留，包装封面不因UI重做擅自换版。
- 不给牌面添加文字、数值、皇冠、能力或新版组件；八物种选择缩略图优先从同批精修图复用，箭头、状态、数字、风险格与功能图标由代码绘制。
- 逐张核对64个独立映射与前后对照；先核验素材，再导入UI。记录原件／派生SHA、提示词、工具、输入角色、尺寸、透明度及核验结果，禁止用整组拼图裁出含错误牌面的批量替代品。
- 母版与运行图分开，运行图按实际展示尺寸和清晰度编码。原运行图仅220像素长边且整包有120,000,000字节硬限；以优化后的真实余量设预算，不承诺把64张高分辨率PNG直接打包，也不靠重度压缩掩盖精修收益。

## 实施顺序与完成标准

1. **接收上游**：确认前置完成，冻结实际源码／入口／组件接口；在实际新架构留下旧德国小强三布局与关键状态基线。
2. **完整设计样板**：先做六人竖屏最拥挤场景、六人服务端与390高短横屏；明确牌桌构图、简约内容卡、文字删减清单和状态语义，再补其余状态。精修样板可在接口稳定后独立制作。
3. **主流程改造**：先真实出牌→接牌→查看→转传→判断→保存／回退最小链，再完成全部界面与声画。游戏规则、服务权威、人机策略及旧档格式保持原职责。
4. **接入完整美术**：映射、解码、边缘、缩放和包内资源检查通过后替换运行引用，移除旧UI样式与失效测试选择器；保留来源和原件。
5. **范围验收与交付**：重构现有德国小强验证脚本适配上游新入口，不再生成独立公共屏矩阵；检查通过后交付实际前后变化展示HTML、截图、素材映射、检查结果和未测边界。仅有后续明确导出新包指示才进入完整installer验收。

验证按[范围规则](../reference/validation.md)和现有测试入口执行，参数归[工具文档](../../tools/test/README.md)，不另造测试注册表。优先：秘密与承诺、真实服务保存与失败、六人短屏主流程，再覆盖适用尺寸。

建议尺寸组为服务端1280×720／1920×1080／3840×2160，玩家竖屏320×568／390×844及较宽竖窗，玩家横屏844×390及1280×720；这些是待校准代表值，断点沿用上游契约。增加切换边界两侧、超宽留边、125%／150%模拟缩放、长昵称、2／6人、27张起手、公开收牌密集、规则／菜单浮窗及减少动态。浏览器模拟不称实体手机或物理DPI通过。
