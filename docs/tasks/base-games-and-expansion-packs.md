# 初始10款游戏与可独立下载的扩展包

2026-10-16用户确认的未来计划，尚未开始实施。产品方向见[需求增补](../requirements.md#2026-10-16-未来计划初始10款游戏与扩展包)；现行交付与验证边界仍以[验收](../reference/acceptance.md#当前源码与本地交付)为准。

## 目标与范围

初始包计划包含10款游戏，目前已接入6款，剩余4款尚未确定名单与开发顺序。数量按游戏计算，同一游戏的多个玩法不重复计数。

初始10款之外的后续游戏作为扩展包，支持单独下载。这里的扩展包是新增游戏的分发方式，与既有游戏内部的扩展玩法区分。下载、接入及后续维护机制尚待设计，不将历史上已退役的独立游戏下载功能视为现成实现。

启动扩展包游戏开发前，必须先形成并验证一套成熟的游戏开发架构方案，具备可复用能力、明确接口和接入流程，便于新增游戏独立接入。

本计划不立即改变当前完整installer的交付方式，也不授权现在恢复下载接口、调整现有安装与更新流程、发布扩展包或部署下载站点。

## 阶段安排

- [ ] 确定初始包剩余4款游戏的名单、采用版本、优先级和各自开发范围。
- [ ] 盘点现有游戏SDK、模块发现、规则／策略／网页／资源边界及内部签名仓库，区分可复用能力、历史实现和缺口。
- [ ] 在启动扩展包游戏开发前完成架构方案、接口契约与接入指南，并通过验证样例证明可复用性。
- [ ] 按冻结方案实现扩展包下载与独立接入能力，再启动后续扩展包游戏开发。

## 架构准备需要回答的问题

架构方案应基于[现有架构](../reference/architecture.md)和[游戏开发指南](../reference/game-development.md)增量设计，重点明确以下边界；具体实现选择在该阶段定案。

| 主题               | 需要明确的内容                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| 游戏与平台接口     | 规则、合法动作、身份与秘密投影、保存恢复、人机策略、三端页面和平台能力的接口；避免平台层按具体游戏增加分支 |
| 可复用开发流程     | 模块模板、稳定游戏ID、元数据、资源归属、构建发现及接入步骤；区分通用能力与游戏专属逻辑                     |
| 包与兼容契约       | 包内代码／资源／依赖清单、平台与SDK兼容范围、发行身份、版本固定及不兼容处理                                |
| 下载与接入         | 下载来源、完整性与签名核验、失败恢复、接入生效时机，以及与完整程序更新的职责分工                           |
| 存档与资源生命周期 | 新局选择、旧局固定原发行、缺失依赖、共享资源及保留／清理规则，确保接入新包不破坏原局                       |
| 构建与验证         | 游戏独立构建和定向验证、接口契约测试、接入与故障样例、平台回归范围及可复用证据                             |

## 架构阶段完成标准

形成可审阅的依赖边界与接口契约，给出新游戏从创建、构建、验证到接入的完整示例。通过样例验证正常接入、接口不兼容、损坏包、下载中断及旧局恢复等关键边界，证明新增游戏能够按约定接入。

接口与依赖契约定案后进入架构正文，操作方法进入游戏开发指南，分发与验证方法进入对应唯一主题；本任务只维护剩余事项和接续，不提前将方案写成已实现能力。
