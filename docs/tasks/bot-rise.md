# 人机崛起：统一评估与分层策略升级

## 任务接续速查

- 目标：建立可复用的人机评估环境，逐游戏升级默认／豆包／绝悟，增加捣蛋王策略。
- 状态：2026-10-17完成任务规划；下列实施阶段均未开始，尚无本任务的新策略、训练或强度验收结论。
- 当前构建：沿用[当前验收](../reference/acceptance.md#当前源码与本地交付)，本次只修改文档。
- 所属范围：游戏SDK、人机运行与验证工具、各游戏策略及必要的配置／展示／恢复适配；规则、计分和秘密边界不因策略升级改变。
- 有效基础与缺口：已有三档策略、Worker和多款无界面对局测试；统一评估、跨版本比较、捣蛋王与高级训练尚待实施。
- 下一步：执行R0盘点，冻结试点游戏、逐决策覆盖表、评价指标和样本计划，再进入接口与评估工具开发。

## 来源、范围与目标

本任务承接用户[手写改动单](手写改动单.md#v108)中的“人机崛起”，2026-10-17用户明确要求形成专用任务文档。原“留待v1.0.8”是历史任务标记，不据此调整公开版本或承诺发布日期。本页维护实施顺序与剩余工作；现行行为仍以[人机规格](../reference/bot-players.md)及对应游戏主题为准。

| 项目     | 用户目标与尚待确定的内容                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 统一抽象 | 研究能否用一至两套交互结构承载环境信息、可执行动作与目标信息，便于复用算法；这是研究方向，具体结构与通用算法尚未定案                               |
| 快速评估 | 每款游戏开发时须配套符合统一标准的快速对局环境并保存日志；允许无UI，现有单游戏工具优先复用                                                         |
| 默认     | 观察约1–2回合，采用简单决策和一定随机扰动，正常完成合法选择，目标是普通玩家普遍能够战胜                                                            |
| 豆包     | 提高多回合判断能力，让普通玩家仍有一定获胜机会；具体搜索／估值算法待试点比较                                                                       |
| 绝悟     | 以本游戏得分或胜利为目标，争取使玩家难以战胜；强化学习、从豆包策略warmup是候选路线，须先验证收益与运行预算                                         |
| 捣蛋王   | 围绕干扰当前优势者、压低其收益开展高智能训练；具体方法逐游戏研究，不预定强化学习。“优势者”及阵营游戏中的目标必须逐游戏定义，不能视作单纯第四档强度 |
| 用户描述 | 只说明强弱、风格与实际支持范围，不向玩家披露内置算法或训练方法；研发文档仍保留技术依据                                                             |

“1–2回合”的计数、各档人类胜率及捣蛋目标没有统一数值基线，先在R0／R3确定可测定义。不得将单局胜负、少量人机对局或实现设想写成上述体验目标已达到。

## 可复用基础与约束

现有策略契约、观察记忆、调度及恢复见[人机规格](../reference/bot-players.md#授权输入与独立决策文件)、[随机与存档](../reference/bot-players.md#随机回退与存档)；接入职责见[游戏开发指南](../reference/game-development.md#模块与契约)。已有固定种子规则整局和真实服务／Worker／保存链可以分别复用，不能把“已有无UI测试”等同于“已有通用强度评估平台”。

- **统一外层契约，游戏逻辑内聚**：基于现有BotStrategy增量补充观察／动作／目标适配、运行和报告接口；规则、合法参数、估值、记忆、胜负与捣蛋目标留在对应`games/<id>`。不要求所有游戏共用同一种策略，也不为抽象重写全部游戏。
- **只使用本人授权信息**：策略与训练特征只来自本人合法观察、记忆和动作约束；环境适配不能将权威状态、真实牌序、其他玩家秘密或评估种子交给策略。大规模组合动作可用受限参数结构，不强制展开全部组合或靠试探秘密目标筛选。
- **扰动只影响判断**：默认级可以扰动估值或合法选择概率，不改写规则事实、本人资源与当前必知信息，不以遗忘强制选择或制造非法动作降低难度。
- **保持权威动作与恢复**：策略只返回意图，仍经统一校验、去重及保存；观察记忆与独立策略随机按原事务和checkpoint恢复。回退／取消拒绝旧任务，旧局固定原发行与策略，不替掉线真人行动。
- **本地运行预算保持有效**：现行每决策2秒、每Worker的V8老生代32MiB。训练成本与正式推理分开评估；候选模型必须验证依赖、耗时、内存和完整包体积，不能默认放宽预算或改成云端决策。

## 阶段、依赖与完成标准

所有阶段均待实施。R0→R1→R2→R3为主线；R3后可分别进行R4迁移与R5高级路线研究，R6按实际完成的游戏范围集成。单游戏已达标可独立收尾，未覆盖项继续保留；不等待所有游戏训练完才验证先行成果。

| 阶段                  | 工作与交付                                                                                                                                     | 完成标准                                                                                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R0 范围与基线         | 盘点全部正式游戏及独立玩法的决策、现有三档策略、无UI工具和缺口；选择两个差异明显的试点，建议UNO与宝可梦原版，必要时补现代艺术；制定样本和指标  | 明确哪些复用、哪些新增，冻结试点规则／策略版本、覆盖节点、比较方法与预算；不把现有合法整局数量换算为强度排名                                                 |
| R1 最小统一契约       | 基于现有接口验证授权观察、动作／参数约束、目标、可恢复记忆与策略随机的公共外层；游戏提供独立适配；定义捣蛋王在配置、能力声明及存档中的表达     | 两个试点实际运行同一接口；非法／秘密输入、无合法目标、多步／被动节点有明确处理；接口不兼容保留原档并明确失败，不静默降级                                     |
| R2 快速对局与评估     | 抽取无UI批次入口、生命周期与快照恢复、日志、种子／座位轮换、版本比较及报告；支持有界局数／动作数／运行时间和中断后复查；将统一要求写入开发准则 | 同输入可复查动作与结果，异常和未结束局不混入胜局；并发／计时决策保持游戏语义，快循环与生产路径的一致性另有服务／Worker／保存证据；每款新游戏有接入要求和示例 |
| R3 分层策略试点       | 先校准默认的有限观察与扰动，再改进豆包；为绝悟保留可比较基线；定义试点捣蛋目标，先建立合法动作与风格基线                                       | 全部决策可完成，授权／恢复与计算预算通过；用对照局面、换座批次和真人反馈分别验证强弱与风格；捣蛋收益不能冒充绝悟胜率，训练与效果目标继续待验收               |
| R4 逐游戏迁移         | 按基线缺口和试点收益排序迁移其余游戏／玩法，逐项补策略、目标、评估适配、配置与玩家描述                                                         | 每个游戏声明实际支持的策略与节点，记录未支持项；旧局、旧记忆和策略身份不被新版本覆盖；单游戏结论不推广为全部通过                                             |
| R5 高级策略与训练研究 | 先比较有界搜索／多回合估值，再选择游戏验证强化学习、豆包warmup或其他候选路线；单独开展捣蛋王目标训练与对照评估                                 | 候选在独立评估样本上有可解释收益，满足权限和推理预算；记录模型／数据／参数版本与资源成本。无收益则保留基线和研究结论，未达目标继续待办，不强行引入模型       |
| R6 集成与体验验收     | 完成等级／风格选择、实际支持声明、玩家文案、版本及恢复兼容；按影响验证本地完整程序                                                             | 快速评估、生产Worker／保存链和真人体验证据分开；公开界面不暴露算法或秘密，缺项明确保留；当前文档任务不触发封包或发布                                         |

R1／R2可与[游戏开发接口](../reference/game-development.md#模块与契约)及接入样例的增量建设共同推进，无须等待10款游戏齐全或扩展包下载实现。R5中绝悟强化学习是候选路线，捣蛋王的训练与效果目标仍须验收，不能以R3基线替代。高级训练依赖相应游戏规则与目标稳定；宝可梦未确定的Mega／羁绊效果不进入既有策略训练目标，规则定案后再补其覆盖。

## 评估与证据要求

### 快速环境与日志

快速环境复用真实规则、授权投影和动作校验语义，可以以内存循环减少界面与持久化开销；它不能替代真实调度、取消、事务与崩溃恢复验证。自动测试保持静音，服务类验证默认仅监听127.0.0.1。

每批至少记录游戏／玩法与发行、规则／策略／模型版本及源码摘要、运行时、初始种子与策略随机配置、人数与座位、等级／风格、预算、动作序号、终局指标、耗时和失败原因。正式存档与真人对局不默认作为训练集；训练样本优先来自隔离模拟。按座位管理观察与动作日志，公开汇总不含私牌／未知身份，评估器持有的隐藏状态和种子不能进入策略输入或可访问日志。

### 强度、风格与体验

- 先固定评估方案，再比较新旧策略及不同等级；按人数、阵营／座位轮换和多个初始种子成组运行。训练、调参与最终评估样本分开，不能看完结果再改样本或验收门槛。
- 按游戏报告胜率／平局、分数或名次及样本量和统计区间；合作／阵营游戏采用对应胜负目标。跨游戏不共用未经校准的“智能分”，不以全部自我对局证明普通人能否战胜。
- 捣蛋王的优势判断只用本人可知信息；没有公开分数或身份不明时，由游戏定义合法估计与信息不足时的行为。记录对领先者收益、自己／本阵营结果及目标切换的影响，不偷看真实阵营、不引入规则外动作。
- 正确性先于跑分：逐决策覆盖、越权／非法参数、循环与未终局、超时／内存、取消与迟到、暂停、回退、保存失败、重启和旧版本恢复均按影响验证；不能用胜率提高抵消这些失败。
- “普通玩家普遍可胜／有机会／难以战胜”通过注明人数、经验和样本量的真人混合对局验证；无人类数据时只报告策略对照，体验目标保留待验收。具体阈值与成本在试点阶段冻结，当前不捏造胜率承诺。

失败排序、每轮默认累计10失败停止、修复后定向新轮与证据复用遵守[验证规范](../reference/validation.md#历史通过率与失败阈值)，不另建计数规则。实施只验证当前游戏和实际共享依赖；本次纯文档仅检查格式、链接／锚点和diff。
