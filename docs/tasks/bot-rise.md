## 可复用基础与约束

现有策略契约、观察记忆、调度及恢复见[人机规格](../reference/bot-players.md#授权输入与独立决策文件)、[随机与存档](../reference/bot-players.md#随机回退与存档)；接入职责见[游戏开发指南](../reference/game-development.md#模块与契约)。已有固定种子规则整局和真实服务／Worker／保存链可以分别复用，不能把“已有无UI测试”等同于“已有通用强度评估平台”。

- **统一外层契约，游戏逻辑内聚**：基于现有BotStrategy增量补充观察／动作／目标适配、运行和报告接口；规则、合法参数、估值、记忆、胜负与捣蛋目标留在对应`games/<id>`。不要求所有游戏共用同一种策略，也不为抽象重写全部游戏。
- **只使用本人授权信息**：策略与训练特征只来自本人合法观察、记忆和动作约束；环境适配不能将权威状态、真实牌序、其他玩家秘密或评估种子交给策略。大规模组合动作可用受限参数结构，不强制展开全部组合或靠试探秘密目标筛选。
- **扰动只影响判断**：默认级可以扰动估值或合法选择概率，不改写规则事实、本人资源与当前必知信息，不以遗忘强制选择或制造非法动作降低难度。
- **保持权威动作与恢复**：策略只返回意图，仍经统一校验、去重及保存；观察记忆与独立策略随机按原事务和checkpoint恢复。回退／取消拒绝旧任务，旧局固定原发行与策略，不替掉线真人行动。
- **本地运行预算保持有效**：现行每决策2秒、每Worker的V8老生代32MiB。训练成本与正式推理分开评估；候选模型必须验证依赖、耗时、内存和完整包体积，不能默认放宽预算或改成云端决策。

## 阶段、依赖与完成标准

所有阶段均待实施。R0→R1→R2→R3为主线；R3后可分别进行R4迁移与R5高级路线研究，R6按实际完成的游戏范围集成。单游戏已达标可独立收尾，未覆盖项继续保留；不等待所有游戏训练完才验证先行成果。

| 阶段                  | 工作与交付                                                                                                                                     | 完成标准                                                                                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R0 范围与基线         | 盘点全部正式游戏及独立玩法的决策、现有三档策略、无UI工具和缺口；选择两个差异明显的试点，建议UNO与宝可梦原版，必要时补现代艺术；制定样本和指标  | 明确哪些复用、哪些新增，冻结试点规则／策略版本、覆盖节点、比较方法与预算；不把现有合法整局数量换算为强度排名                                                 |
| R1 最小统一契约       | 基于现有接口验证授权观察、动作／参数约束、目标、可恢复记忆与策略随机的公共外层；游戏提供独立适配；定义捣蛋王在配置、能力声明及存档中的表达     | 两个试点实际运行同一接口；非法／秘密输入、无合法目标、多步／被动节点有明确处理；接口不兼容保留原档并明确失败，不静默降级                                     |
| R2 快速对局与评估     | 抽取无UI批次入口、生命周期与快照恢复、日志、种子／座位轮换、版本比较及报告；支持有界局数／动作数／运行时间和中断后复查；将统一要求写入开发准则 | 同输入可复查动作与结果，异常和未结束局不混入胜局；并发／计时决策保持游戏语义，快循环与生产路径的一致性另有服务／Worker／保存证据；每款新游戏有接入要求和示例 |

| R4 逐游戏迁移         | 按基线缺口和试点收益排序迁移其余游戏／玩法，逐项补策略、目标、评估适配、配置与玩家描述                                                         | 每个游戏声明实际支持的策略与节点，记录未支持项；旧局、旧记忆和策略身份不被新版本覆盖；单游戏结论不推广为全部通过                                             |
| R5 高级策略与训练研究 | 先比较有界搜索／多回合估值，再选择游戏验证强化学习、豆包warmup或其他候选路线；单独开展捣蛋王目标训练与对照评估                                 | 候选在独立评估样本上有可解释收益，满足权限和推理预算；记录模型／数据／参数版本与资源成本。无收益则保留基线和研究结论，未达目标继续待办，不强行引入模型       |
| R6 集成与体验验收     | 完成等级／风格选择、实际支持声明、玩家文案、版本及恢复兼容；按影响验证本地完整程序                                                             | 快速评估、生产Worker／保存链和真人体验证据分开；公开界面不暴露算法或秘密，缺项明确保留；当前文档任务不触发封包或发布                                         |

R1／R2可与[游戏开发接口](../reference/game-development.md#模块与契约)及接入样例的增量建设共同推进，无须等待10款游戏齐全或扩展包下载实现。R5中绝悟强化学习是候选路线，捣蛋王的训练与效果目标仍须验收，不能以R3基线替代。高级训练依赖相应游戏规则与目标稳定；宝可梦未确定的Mega／羁绊效果不进入既有策略训练目标，规则定案后再补其覆盖。

## 评估与证据要求

### 快速环境与日志

快速环境复用真实规则、授权投影和动作校验语义，可以以内存循环减少界面与持久化开销；它不能替代真实调度、取消、事务与崩溃恢复验证。自动测试保持静音，服务类验证默认仅监听127.0.0.1。

每批至少记录游戏／玩法与发行、规则／策略／模型版本及源码摘要、运行时、初始种子与策略随机配置、人数与座位、等级／风格、预算、动作序号、终局指标、耗时和失败原因。正式存档与真人对局不默认作为训练集；训练样本优先来自隔离模拟。按座位管理观察与动作日志，公开汇总不含私牌／未知身份，评估器持有的隐藏状态和种子不能进入策略输入或可访问日志。

### 强度、风格与体验

- 先固定评估方案，再比较新旧策略及不同等级；按人数、阵营／座位轮换和多个初始种子成组运行。训练、调参与最终评估样本分开，不能看完结果再改样本或验收门槛。
- 按游戏报告胜率／平局、分数或名次及样本量和统计区间；合作／阵营游戏采用对应胜负目标。跨游戏不共用未经校准的“智能分”，不以全部自我对局证明普通人能否战胜。
- 捣蛋王的优势判断只用本人可知信息；没有公开分数或身份不明时，由游戏定义合法估计与信息不足时的行为。记录对领先者收益、自己／本阵营结果及目标切换的影响，不偷看真实阵营、不引入规则外动作。
- 正确性先于跑分：逐决策覆盖、越权／非法参数、循环与未终局、超时／内存、取消与迟到、暂停、回退、保存失败、重启和旧版本恢复均按影响验证；不能用胜率提高抵消这些失败。
- “普通玩家普遍可胜／有机会／难以战胜”通过注明人数、经验和样本量的真人混合对局验证；无人类数据时只报告策略对照，体验目标保留待验收。具体阈值与成本在试点阶段冻结，当前不捏造胜率承诺。

失败排序、每轮默认累计10失败停止、修复后定向新轮与证据复用遵守[验证规范](../reference/validation.md#历史通过率与失败阈值)，不另建计数规则。实施只验证当前游戏和实际共享依赖；本次纯文档仅检查格式、链接／锚点和diff。

### 数据抽象与保存

建议统一“记录与环境接口”，每款游戏独立编码观察、动作和目标，先训练各游戏模型，不以一个通用网络同时学会全部游戏为首期目标。首轮只用结构化状态，不采集屏幕图像。

| 层次         | 建议内容与用途                                                                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境重现资料 | 游戏／玩法的精确发行、规则与运行时、初始化配置、规则随机状态和必要环境快照；仅环境与诊断器可读，不进入策略样本输入                                                     |
| 观察与记忆   | 决策时本人授权投影、当前公开场面、本人资源与合法已知历史；未知值显式标记。席位按相对位置编码，保留多人／阵营、阶段及变长集合；不编码昵称、凭证或本人未获授权的隐藏身份 |
| 动作契约     | 保留动作类型、目标及参数的原始JSON语义，另存候选／参数约束和编码版本；小动作集可用候选评分与mask，大动作集采用逐步参数选择或受限生成                                   |
| 决策轨迹     | 对局／席位、决策ID、源分支／修订／并发组、观察与记忆引用、行为策略／模型、实际动作、成功保存水位、本人下一决策观察、累计奖励和终止原因                                 |
| 派生训练数据 | 版本化编码器把语义JSON转成张量；同时绑定数据集、编码器、动作映射与奖励版本。张量缓存可重建，不替代语义原件                                                             |
| 训练检查点   | 权重、模型结构／编码器、优化器、训练随机状态、必要经验池／采样器位置、训练参数及来源摘要；与仅供正式推理的模型包分开                                                   |

现有[SDK](../../packages/game-sdk/src/index.ts)明确`legalActions`可以只是有界建议，参数化完整动作由`isLegalAction`核验。因此不能把“候选列表第3项”永久当成动作，也不能把建议集误认为全部合法动作。索引必须伴随当时的候选标识／顺序和编码版本；模型最终还原语义意图，交真实规则校验。mask及候选生成本身也须经过信息权限检查，避免由合法性提示泄露秘密。

轨迹按每席自己的决策链组织：本人观察→本人动作成功保存→期间其他席／环境推进→本人下一次获准决策观察。中间奖励累计到对应转移，记录推进跨度与折扣约定；终局席位没有下一次决策时生成终止转移。并发密投保留各自原始观察，不让后保存者看到先保存者秘密；取消、过期和保存失败只作诊断，不能当游戏负奖励。资源限制截断与正常终局分开，回退分支不与实际继续分支重复计分。训练序列按对局和席位隔离，记忆／循环网络状态不能串到另一席或另一局。

小规模建议采用版本化JSONL分片加manifest，便于检查；规模上升再评估列式或张量存储。研发数据根在R0按容量与硬件确定，不默认堆入仓库、`tmp`、`assets`或安装载荷；本机学习资料建议置于用户配置数据目录的独立`learning`区域。原始样本、派生缓存、候选模型和验收记录分别管理，保护旧局仍引用的模型，保留配额、来源和可重建性说明。

### 样本质量分级

质量等级与来源、技术有效性、决策评价分别记录。真人决策归高质量，进入训练仍须通过规则合法、成功保存、本人观察完整和轨迹对齐等校验；损坏、越权、过期或未保存记录进入隔离诊断，不因真人来源跳过校验，也不改写其真实来源。

| 等级     | 建议归类与用途                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------ |
| 高质量   | 来源可核验的真实人工决策；优先用于示范预热、行为学习和关键局面分析，可采用更高采样权重           |
| 标准     | 已验证规则／投影／保存语义的脚本与模型对局样本，承担大规模覆盖和常规训练                         |
| 探索     | 随机策略、早期候选或尚未证明强度的探索样本，保持来源标记，用于探索与发现弱点，不直接视为优质示范 |
| 隔离诊断 | 未通过入库校验的记录，保留失败原因，不进入正式训练或胜负统计                                     |

后三类及其具体细分在R0定案。分级针对每席的实际决策来源，混合真人／人机对局不能整局标为真人高质量；测试脚本、agent代操作、模拟真人和来源未知也不能仅因座位`controller=human`就获得真人标签。采集协议须记录可追溯的实际输入来源，不靠动作强弱猜测来源。

真人失误、失败对局及探索性选择仍保留高质量来源标记，另记结果、复核评价或改进标注；高质量不等于每个动作都是最优答案，不因输局自动降级，也不要求模仿所有失误。建议记录`sourceType`、`qualityTier`、`validationStatus`、分级依据、共同对局／分支来源及标注版本，后续复核不覆盖原始观察和动作。

训练时按来源／等级分层抽样，可提高真人高质量样本的权重，同时约束同一样本的重复次数，报告独立样本量与各来源占比；具体比例在试点确定，不能用少量真人记录反复复制来虚增数据规模。真人日志仍按模仿或已验证的离线算法使用，高质量标签不使其成为PPO当前策略样本。真人记录及其回退分支、增强／派生记录按共同对局来源分组，避免跨训练／最终评估集合泄漏。

R0冻结分级与校验口径，R2实现来源、分级和隔离记录，R5验证分层采样／加权的实际收益，R6检查采集展示及玩家日志边界。此分级不改变按设置采集、不默认导入历史正式存档的约定，当前尚未实施。

### 训练数据生产与训练闭环

1. **先验证生产语义一致**：复用Node真实规则／投影生成无UI模拟，对照服务／Worker路径检查动作、记忆、规则随机、并发和终局；不另写一套“简化规则”。UNO闭环／宝可梦原版记忆与秘密验证仍只是候选路线，用户当前暂不启动试点，未来在R0选择。
2. **分级示范预热**：优先利用通过校验的真人高质量样本，并由现有豆包补充合法决策覆盖，用模仿学习初始化候选模型；脚本策略并没有可直接继承的网络权重。保留胜、负、平局和各种阶段，避免只收获胜局造成选择偏差；示范不是最优动作真值。
3. **混合对手训练**：当前候选与固定默认／豆包／现行绝悟、历史候选及不同风格对手进行对局，定期冻结新快照；训练期间记录行为策略版本。对手池用于降低只擅长打同一对手的风险，不保证所有游戏都从同一比例获益。
4. **GPU训练，CPU推进规则**：Node采样进程负责规则模拟，训练器负责GPU上的参数更新；先测对局／决策吞吐、传输、显存和推理预算，再确定批次与并发。GPU不自动加快规则模拟，不预设固定训练局数或工期即可达到人类水平。
5. **冻结候选后独立评测**：训练／调参／最终评估按对局种子与来源分组划分，同一开局的换座版本不能跨集合泄漏；报告真人／模拟、质量等级和独立对局的实际占比。通过验收才登记并供后续新局自动使用；失败保留原因，不覆盖当前模型。

奖励与目标按游戏版本化：绝悟按正式胜负／最终名次优先、个人收益为次目标，不能用任意收益加权反转主目标；中间奖励只作可验证的学习辅助，必须检查是否诱导拖局、刷分或偏离正式胜利条件。捣蛋王单独保存目标定义和训练结果，按本人可知信息识别优势者；允许为干扰目标牺牲个人成绩，但阵营局首先满足本阵营胜利目标，不能为捣蛋破坏该底线，也不把“损害所有人”自动等同于达标。

首期训练与自动模型升级面向绝悟、捣蛋王。默认／豆包保持各自固定难度和既有观察／恢复边界，可继续作为示范及对手；本阶段不因候选训练而自动替换其权重。R3对默认／豆包的常规策略校准仍须维持各自难度目标并独立验证。

不能将所有旧日志直接混入任意算法更新。例如采用PPO时，每批绑定冻结的行为策略、观察／动作编码器、候选约束及所需行为概率／价值估计，在该批允许的优化轮次后重新采样；参数动作记录完整动作的联合概率。历史策略可以成为对手，其动作不因此成为学习者的PPO样本。正式局模型冻结时，局中日志也不自动成为持续更新候选的当前策略数据；旧豆包与真人动作可用于模仿或另行验证的离线方法。具体算法须结合部分可观察、多人、动态动作与实际预算验证，当前不承诺PPO或其他单一路线。

### 验收与效果评估

| 验收层           | 建议判据                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境／数据正确性 | 授权输入与隐藏状态隔离；语义动作编码往返、候选重排、参数边界、并发密投及终止／截断正确；快循环与生产路径一致。发现非法动作、越权或恢复错误即不晋级                              |
| 可复现性         | 绑定游戏／模型／编码器／奖励／运行时和样本摘要；固定输入可复查语义轨迹。GPU数值差异记录容差与非确定性来源，不承诺所有设备逐位一致                                               |
| 策略强度         | 冻结权重、编码／归一化统计与探索设置，同预算比较现行策略与候选，对冻结对手池进行人数／座位／阵营轮换；按游戏报告胜率、分数／名次及配对差值的95%区间，不只看训练loss或自对弈奖励 |
| 泛化与退步       | 使用留出开局和多个独立训练随机种子；检查新对手／人数、关键战术局面及对手矩阵，防止仅击败某一策略。不能只挑最强的一次训练作为总体结果                                            |
| 风格与真人体验   | 捣蛋王独立验证优势者选择与实际干扰；默认／豆包／绝悟的玩家获胜体验通过真人混合对局评价，机器人胜率不替代人类反馈                                                                |
| 正式运行         | 在真实32MiB老生代Worker、2秒计算预算下验证冷／暖启动、耗时分布、总进程内存、模型加载和包体积；覆盖模型缺失／篡改、不兼容、暂停、取消、保存失败、回退与重启                      |

起步建议至少3次独立训练，每次每个主要配置先做500局留出评估，并安排换座配对；这只是测量预算建议，不能据局数直接判为充分。按训练运行与配对开局分层统计，在看最终结果前冻结样本量或区间宽度的扩样规则。建议晋级要求为“对现行基线的主目标成绩改进区间下界大于0，并满足预先定义的最小实际收益及主要配置退步限制”；绝悟遵循胜负／名次优先，捣蛋王遵循阵营胜利底线，不能仅以个人收益掩盖主目标退步，具体数值在R0定案。输局是正常样本，非法／越权／异常等才进入工程失败账本，不能把正常输局当作10失败停止规则的失败项。

### 游玩期间适应与局后学习

按用户选择，首期流程为：**固定模型开局→本局授权记忆适应对手并按设置采集样本→局后程序空闲时自动训练→独立验收→后续新局自动绑定通过验收的新模型**。这里“一局”指平台对局实例，同实例的小局／航次、重启读档和回退都不更换权重。

- **局中适应**：允许根据本人合法观察更新对手行为统计、策略记忆或模型内部状态，更新仍进入现有动作事务和checkpoint。首期以本局席位为范围，不默认建立跨局真人身份档案；不同人机席位的私有记忆不合并。
- **局后训练**：未来程序空闲时自动训练，提供开关、暂停、资源预算和数据保留设置；开始游玩时在安全边界尽快暂停并保留训练进度，不继续占用游玩所需资源。空闲判定、暂停边界与恢复方法由实现验证。历史正式存档不默认批量转为训练集；旧策略真人局日志仍须按所选算法处理，不能保证边玩就必然变强。
- **新局生效**：候选通过评测后，登记不可变模型引用并供后续新局自动绑定，绑定基础游戏发行、策略、编码器和权重摘要。现有`BotData`尚无独立模型字段，须补兼容与保全方案；缺模型时保留原档并明确提示，不能偷偷换成最新权重。
- **发行与信任**：本地模型作为明确支持学习能力的新策略的数据引用，不覆盖EXE核验的游戏／策略映射，不改写旧发行。本机生成模型标明本地来源，文件摘要不能冒充发布方签名；模型登记、校验与清理属于后续新增契约。

训练输入先封存为绑定分支／修订的不可变对局快照，训练器不读取可变实时存档。管理员结束记录为中断，不因状态为ended就生成自然胜负奖励；后续回退继续保留原模型，撤销分支标明共同来源，避免重复计权和跨集合泄漏。原终局被撤销后不再将其当作实际终局样本，未启用候选重新核验来源；不为采集禁用回退或热替换已绑定旧局的模型。

当前选择不包含在活动对局中对共享权重做梯度更新；这会额外影响保存／回退、跨席秘密隔离和公平性，若未来研究须作为独立实验。当前也不将训练器、优化器和大型数据集装入正式Worker或完整安装器；内置推理模型仍须通过现行交付预算。

### 本轮定案与待定项

已确认自学习边界、自有GPU条件、真人高质量分级、绝悟目标、自动训练／新局自动启用、捣蛋王底线、首期学习对象及游玩优先。用户当前暂不启动首轮试点，继续确认新对局默认采集、数据保留、GPU与存储条件。未来实施时由R0确定试点、语义／张量字段、参数动作编码、各游戏奖励实现、训练框架与推理格式、配额／资源预算、空闲／暂停细则、模型登记及晋级阈值；不重复询问已定产品方向。R1／R2实现统一记录与环境，R3建立基线，R5开展训练与效果对照，R6实现局后学习设置、新局模型绑定和旧局恢复；当前均未实施。

方法核验的一手参考：[OpenSpiel观察与环境概念](https://openspiel.readthedocs.io/en/latest/concepts.html)、[PettingZoo逐席决策与动作mask](https://pettingzoo.farama.org/api/aec/)、[不完全信息自对弈研究](https://arxiv.org/abs/1603.01121)、[多策略对手池研究](https://www.nature.com/articles/s41586-019-1724-z)、[PPO采样与优化](https://arxiv.org/abs/1707.06347)、[强化学习实验设计](https://jmlr.org/papers/v25/23-0183.html)。这些资料支持方法选择的分析，不表示已将相应框架接入TableMax，也不将其特定游戏结果推广到本项目。
