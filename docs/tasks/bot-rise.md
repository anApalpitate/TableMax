## 来源、范围与目标

本任务承接用户[手写改动单](手写改动单.md#v108)中的“人机崛起”，2026-10-17用户明确要求形成专用任务文档。原“留待v1.0.8”是历史任务标记，不据此调整公开版本或承诺发布日期。本页维护实施顺序与剩余工作；现行行为仍以[人机规格](../reference/bot-players.md)及对应游戏主题为准。

| 项目     | 用户目标与尚待确定的内容                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 统一抽象 | 研究能否用一至两套交互结构承载环境信息、可执行动作与目标信息，便于复用算法；这是研究方向，具体结构与通用算法尚未定案                             |
| 快速评估 | 每款游戏开发时须配套符合统一标准的快速对局环境并保存日志；允许无UI，现有单游戏工具优先复用                                                       |
| 默认     | 轻量启发式，按眼前收益和明显风险评分，参考少量近期信息，在评分相近的合法动作中适度随机。适当引入失误，目标是普通玩家普遍能够战胜。                             |
| 豆包     | 启发式加短前瞻，以有限的授权记忆评估接下来一两轮的机会。会留关键资源、拦截眼前威胁，普通玩家仍有一定获胜机会。                                   |
| 绝悟     | 启发式加有界搜索，比较与本人观察一致的未知情形和对手应对。正式胜负／最终名次优先，个人收益居次。首轮可用学习评分重排特定节点的候选动作。         |
| 捣蛋王   | 先用启发式估计谁最有胜势，再衡量各动作的干扰收益。可牺牲个人成绩，阵营局以本阵营胜利为底线。优势不明时按正常胜负目标行动。作为独立风格单独验收。 |
| 用户描述 | 只说明强弱、风格与实际支持范围，不向玩家披露内置算法或训练方法；研发文档仍保留技术依据                                                           |

四种人机先交付覆盖全部合法节点的启发式基线。默认、豆包、绝悟按强度区分，捣蛋王按干扰效果验收。各游戏的前瞻单位、档位胜率和领先者判据在 R0／R3 冻结；体验目标由成组对照与真人混合对局验证。

## 可复用基础与约束

现有策略契约、观察记忆、调度及恢复见[人机规格](../reference/bot-players.md#授权输入与独立决策文件)、[随机与存档](../reference/bot-players.md#随机回退与存档)；接入职责见[游戏开发指南](../reference/game-development.md#模块与契约)。已有固定种子规则整局和真实服务／Worker／保存链可以分别复用，不能把“已有无UI测试”等同于“已有通用强度评估平台”。

- **统一外层契约，游戏逻辑内聚**：基于现有BotStrategy增量补充观察／动作／目标适配、运行和报告接口；规则、合法参数、估值、记忆、胜负与捣蛋目标留在对应`games/<id>`。不要求所有游戏共用同一种策略，也不为抽象重写全部游戏。
- **只使用本人授权信息**：策略与训练特征只来自本人合法观察、记忆和动作约束；环境适配不能将权威状态、真实牌序、其他玩家秘密或评估种子交给策略。大规模组合动作可用受限参数结构，不强制展开全部组合或靠试探秘密目标筛选。
- **扰动只影响判断**：默认级可以扰动估值或合法选择概率，不改写规则事实、本人资源与当前必知信息，不以遗忘强制选择或制造非法动作降低难度。
- **保持权威动作与恢复**：策略只返回意图，仍经统一校验、去重及保存；观察记忆与独立策略随机按原事务和checkpoint恢复。回退／取消拒绝旧任务，旧局固定原发行与策略，不替掉线真人行动。
- **本地运行预算保持有效**：现行每决策2秒、每Worker的V8老生代32MiB。训练成本与正式推理分开评估；候选模型必须验证依赖、耗时、内存和完整包体积，不能默认放宽预算或改成云端决策。

### 共用接口与恢复验收

沿用现有 [BotStrategy](../../packages/game-sdk/src/index.ts) 与 [BotData](../../packages/platform-core/src/model.ts)，以两个玩法的实际适配结果收敛接口。下表描述建议契约和需要验证的约束，字段名与版本机制由 R1 定案。

| 边界           | 适配与验收                                                                                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境与策略输入 | 环境持有完整规则状态、规则随机与生命周期。策略只获得本席投影、当前决策、语义候选及参数约束、本人记忆和独立策略随机。用两个本席投影相同但秘密不同的夹具对照：输入、候选提示和同种子决策应一致。                         |
| 动作与参数     | UNO 用实体牌和随牌颜色验证完整意图。宝可梦原版用取牌、私看、换位与多步能力验证目标及阶段。对参数化动作保留规则校验，按实际候选契约区分建议集和合法全集。多步能力每次只推进当前决策，后一选择使用保存后更新的授权投影。 |
| 记忆与保存     | 记忆版本、策略随机与动作结果同一事务提交。保存失败、超时和取消分别验证结果、记忆、随机与临时观测是否未进入已保存状态。回退和读档恢复原策略引用及对应记忆，仍按平台现有授权和连接契约恢复。                             |
| 并发与配置     | 只在游戏声明的并发组执行独立决策，各席从各自授权输入评分。新局只显示玩法实际支持的等级和风格。试点捣蛋王须同时覆盖座位配置、游戏能力声明、快照和旧档载入。旧三档按原定义兼容，不支持的取值保留原档并明确提示。         |

### R0 实施前冻结清单

授权启动后先按一份可复查的基线记录冻结以下输入。文档中的参数示例和建议值在此时结合预算定案。

- **范围与身份**：按[游戏索引](../games/README.md)盘点规则发行、策略和现有验证入口，冻结 UNO 主配置、开放节点、三组对照和宝可梦原版接口验证。记录源码摘要、运行时、规则／策略／记忆与特征版本。保留当前已验收发行的独立依据。
- **证据和统计**：列每个策略节点的正向局面、授权对照、保存和恢复检查。冻结训练、调参、留出和备用种子、对手池、座次、报告指标、扩样规则及主要配置退步限制。
- **资源和本机配置**：冻结训练框架、推理格式、数据根、容量预算、设置与暂停恢复的设计依据。预先确定实际 Worker 预算测量、模型载入、数据写入和容量耗尽所用的开发验证样本，分别交 R5／R6 实测。
- **阶段交接**：列明可复用的既有证据、未支持节点与待测范围。完成适用前置阶段后再进入后续实施。新增规则或扩大训练玩法时重新冻结受影响输入。

#### 对手池、开局种子与换座

主配置沿用四人、开启补牌传递、打到 500 分的整场对局。每场只替换一个受测席，其余三席使用冻结的现行策略。建议预先固定三个对手池及汇总权重：

| 对手池 | 三个固定对手       | 主结果权重 |
| ------ | ------------------ | ---------- |
| 入门桌 | 默认 × 3           | 25%        |
| 混合桌 | 默认、豆包、旧绝悟 | 50%        |
| 强桌   | 豆包、旧绝悟 × 2   | 25%        |

各池分别报告，再按固定权重汇总。其他人数、经典配置和专项局面单独评估。

- **一个种子对应一个对手池。** 训练、调参、正式首批与备用扩样种子分开锁定。对每个受测座位，A／B／C 从同一个开局快照出发，初始手牌、发牌者、翻出的牌及规则相同，开局后按各自行动推进。[UNO 开局规则](../games/uno/rules.md#牌组与准备)
- **每个种子轮换四个受测座位。** 对手池含不同策略时，按预定顺序在不同种子间均衡轮换三名对手相对受测席的座次。四个座位各跑 A／B／C，共 **12 场**，组成一个完整配对种子块。
- **整块记录异常。** 未完成及异常的场次保留原始结果、故障原因和所属种子块，按预定故障与复验规则处理。只用完整块做主分析，同时报告未完成块，保留所有已判定的工程失败。

#### 正式样本量

开发批次以每个主要配置约 500 场完整对局作为起步预算。每个种子先算四个座位上「C 获胜指示值减 B 获胜指示值」的平均，再分对手池估计块差值标准差。建议以区间半宽约 **2 个百分点**为精度目标，并依据实际每块耗时冻结首批数量和扩样上限。

规划时可用各池的方差与固定权重估计总体方差，即各池「权重平方 × 块差值方差 ÷ 块数」之和。量级示例：若块差值标准差约为 0.25，在固定权重且按比例分层的近似下，单次 95% 区间需要约 **601 块、7,212 场**；采用两次查看的 97.5% 区间，同样精度约需 **785 块**。实际数量按各池波动、权重及整块配额确定。如需另定功效目标，建议按真实提升 **5 个百分点**的情景评估达到晋级条件的概率。

#### 95% 配对置信区间

1. 对每个完整块求四个座位的配对平均差，再按 **25%／50%／25%** 汇总各池。主指标为 C−B 的整场胜率差，同时报告 B−A 和 C−A。
2. 在各对手池内，以完整种子块为单位做有放回重抽样，保持各池块数、种子内四个座位及 A／B／C 配对关系。使用固定的重抽样种子，建议重抽 **10,000 次**，每次重新计算加权差值。
3. 单次正式查看时，取重抽分布的 **2.5% 和 97.5% 分位数**，作为 95% 配对置信区间。报告点估计、区间、各池有效块数和未完成块数。

#### 两阶段扩样规则

若允许查看首批结果后再决定是否加跑，R0 预先冻结首批块数、备用种子、各池配额和最大块数，建议最大块数先按首批的 **1.5 倍**评估可行性。只允许两次正式查看，每次用 **97.5% 配对置信区间**判定，取重抽分布的 **1.25% 和 98.75% 分位数**，用 Bonferroni 分配两次查看的总体 5% 错误预算。普通 95% 区间可随结果报告。

| 首批结果                                               | 处理                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------- |
| C−B 点估计 **≥ +3 个百分点**，且调整后区间下界 **> 0** | 整场胜率项通过。其他项仍按[首轮晋级门槛](#uno-绝悟首轮建议通过门槛)判定。 |
| 调整后区间上界 **< +3 个百分点**                       | 低于预定实际收益，停止扩样。                                              |
| 其余情况                                               | 按预留配额补齐完整种子块，在首批加扩样的合并样本上进行第二次判定。        |

第二次仍未达到通过条件时，按区间记录为低于预定收益或证据不足，保留 B，C 继续作为候选。扩样固定模型、校准器、对手池和统计口径。若调整 C 的权重、限幅或改选条件，新版本使用独立种子重新正式验收。

##### 截断局面采样与标注

1. **按 B 的实际搜索条件采样。** 固定候选筛选、未知牌抽样和截断预算，保留每个候选的截断局面。按普通回合中途、罚牌或质疑待处理、小局已结算但整场继续分层，同时记录领先者距 500 分的差额。训练可加采稀有阶段，主验收集保留正常搜索的出现比例，稀有阶段另行检查。
2. **从截断点续推到整场结束。** 保留模拟状态供离线规则引擎使用，预先固定续推策略、对手组合和随机种子。建议每个截断点先做 **16 条续推**，按正常规则跨小局打到有人达到 500 分。本席赢记 1、输记 0，取有效结果的平均作为软标签。未结束的续推单独记账，并按阶段报告截断率。搜索内已产生整场赢家的分支直接用 0 或 1，单独核对，不纳入截断概率检验。[UNO 整场计分](../games/uno/rules.md#两人小局结束与整场计分)
3. **按原对局分组切分。** 同一开局种子、换座结果、候选分支及重复续推全部保留在同一集合。用训练集拟合小型逻辑回归，用开发集选择特征和参数，冻结后在留出对局上一次性评估。多条续推提高单个标签的精度，置信区间按原对局分组估计。

校准器输入限于本席在截断点获准知道的信息。小局已结算时主要使用各席距 500 分的差额，小局进行中再加入公开手牌数、己方剩余牌点与接牌能力、下一行动席、待处理罚牌和质疑阶段。假设中的暗牌与牌序只供离线规则推进。校准器的输出概率与整场终局的 0 或 1 在同一尺度上按假设取平均。

##### 预测胜率与候选排序检验

- **预测胜率。** 在留出集按预测概率分桶，对照每桶平均预测与续推实际胜率，并按截断阶段检查系统性高估或低估。用同一训练集把现有启发式叶点评分映射成胜率作为简单对照。在相同留出样本上比较 Brier 分数，即预测概率与实际 0／1 胜负的平均平方误差。
- **候选排序。** 冻结 B 的根候选与短搜索排序，另取独立于短搜索的长推演假设，所有候选共用同一批。参考胜率差至少 **5 个百分点**且配对区间支持方向的候选对，计入主排序命中率，同时报告这类候选对的占比。用一批长推演选参考首选，再用另一批独立且按候选配对的假设估计它与 B 首选的胜率差。

## 评估与证据要求

### 快速环境与日志

快速环境复用真实规则、授权投影和动作校验语义，可以以内存循环减少界面与持久化开销；它不能替代真实调度、取消、事务与崩溃恢复验证。自动测试保持静音，服务类验证默认仅监听127.0.0.1。

每批至少记录游戏／玩法与发行、规则／策略／模型版本及源码摘要、运行时、初始种子与策略随机配置、人数与座位、等级／风格、预算、动作序号、终局指标、耗时和失败原因。正式存档与真人对局不默认作为训练集；训练样本优先来自隔离模拟。按座位管理观察与动作日志，公开汇总不含私牌／未知身份，评估器持有的隐藏状态和种子不能进入策略输入或可访问日志。

### 快速批次的可复现证据

- **输入清单**：每批绑定规则发行、初始设置、评估种子清单的受控引用、原对局分组、四座位安排、策略／记忆／模型版本和预算。规则随机与策略随机各自冻结。结果按整场、种子块、对手池及阶段统计。
- **记录和重放**：保留每席成功保存的动作意图、决策标识、源修订与分支、观察／候选引用、提交结果和结束原因。普通对照报告只公开汇总。按同一冻结版本重放代表局，对照终局、动作链和原始失败。中断批次以已完成的唯一块为续接单位，原失败保留，未完成块单列。
- **生产路径对照**：快速无 UI 评价覆盖规则完整局与定向局面。另用真实服务和 Worker 核对成功保存、重启读档、回退、取消、迟到及 UNO 反应窗口。宝可梦原版用同接口验证多步和秘密投影。将未终局、预算截断、操作取消与规则或系统失败分别记录。[按范围选择验证](../reference/validation.md#按变更范围选择检查)

### 首批离线评估证据

[共用执行器](../../tools/analysis/bots/evaluate.ts)和[实跑入口](../../tools/analysis/README.md#人机离线评估)使用真实规则、独立规则／席位随机源、逐席投影、统一动作校验及有界步数。同一 UNO 混合四人局中途序列化 checkpoint 后续跑，终局、动作摘要和状态与连续运行一致。UNO 种子 781 完成 949 步，宝可梦原版种子 20261126 完成 114 步。首轮校验暴露的非法动作诊断已修正，旧失败记录保留在范围验证历史。本批 35 项通过，见[范围验证结果](../../artifacts/maintenance/test-history/runs/9f9ab8bd-1342-4fab-b580-0e5e50751e19/results.json)。

当前快跑以稳定座序提交普通决策，并按规则声明模拟 UNO 反应竞争。正式 Worker 调度、并发密投和真实事务保存仍按[生产路径对照](#快速批次的可复现证据)验证。当前证据只覆盖模拟环境和接口适配。

### 强度、风格与体验

- 先固定评估方案，再比较新旧策略及不同等级；按人数、阵营／座位轮换和多个初始种子成组运行。训练、调参与最终评估样本分开，不能看完结果再改样本或验收门槛。
- 按游戏报告胜率／平局、分数或名次及样本量和统计区间；合作／阵营游戏采用对应胜负目标。跨游戏不共用未经校准的“智能分”，不以全部自我对局证明普通人能否战胜。
- 捣蛋王的优势判断只用本人可知信息；没有公开分数或身份不明时，由游戏定义合法估计与信息不足时的行为。记录对领先者收益、自己／本阵营结果及目标切换的影响，不偷看真实阵营、不引入规则外动作。
- 正确性先于跑分：逐决策覆盖、越权／非法参数、循环与未终局、超时／内存、取消与迟到、暂停、回退、保存失败、重启和旧版本恢复均按影响验证；不能用胜率提高抵消这些失败。
- “普通玩家普遍可胜／有机会／难以战胜”通过注明人数、经验和样本量的真人混合对局验证；无人类数据时只报告策略对照，体验目标保留待验收。具体阈值与成本在试点阶段冻结，当前不捏造胜率承诺。

## 训练数据与本机存储

### 采集默认值与设置

源码已在主机的「设置 → 游戏」提供 UNO 样本采集和独立的空闲训练偏好。发布用途默认关闭，有开发构建标记时默认开启；显式选择在本机配置数据目录持久化。SQLite 保存成功后才写入本席投影，保存失败和重复提交不新增，回退标记废弃分支。当前 UNO 原始日志上限为 16 MiB，达限或写入故障暂停采集，正式存档继续使用原路径。空闲训练状态和启用选项分别显示。本机独立训练器接通后按空闲许可运行，比赛或服务关闭时撤销许可并保留断点。[采集串行保存回归](../../artifacts/maintenance/test-history/runs/8f1385fc-d804-4e6f-a276-4463d714cd7a/results.json) · [390px 主机设置渲染检查](../../artifacts/maintenance/bot-rise-mischief-20261126/learning-settings/report.json)

采集默认按用户确认的构建用途区分，发布版提供主机设置入口以手动开启；构建版也应允许手动关闭。采集开关只控制新样本，不影响正常游戏保存、既有模型推理或已有数据的保全；历史正式存档仍不默认导入训练集。关闭采集后停止新增记录，开启采集不回填此前未记录的观察或秘密历史，采集起点与不完整轨迹须明确标记。

建议显式记录“未设置／手动开启／手动关闭”，未设置时使用本用途默认值；用户明确选择按配置保存，不能把构建版自动开启误记为发布版用户主动开启。开发用途构建与发布用途的身份／默认策略须在冻结输入中明确，不能仅按文件名、版本位数或网络发布状态猜测。

按现行[冻结发布契约](../reference/release.md)，发布已验同一EXE不得改字节。后续建议发布候选在封包时即采用发布用途、默认关闭，并验收其首次启动与设置持久化；不能把默认开启的构建包改名后就宣称默认关闭，也不在推广／上传时补改冻结包。具体标识与升级兼容机制在R1定案，本轮不改现行封包或发布流程。

R2定义采集起点、停止与来源记录；R6验证两种用途的首次默认、明确设置、升级／用途切换、关闭后的停止写入及正常保存不受影响。采集设置不自动等同于训练设置：空闲自动训练仅使用符合条件的已有本地数据，不能以训练为由绕过关闭的采集开关。

### 数据抽象与保存

统一记录和环境接口后，各游戏仍按自己的规则编码观察、动作与目标。首轮只用结构化决策特征，例如出牌后还可接几种颜色、后续座位剩余牌数。模型按候选动作逐一评分，动作语义和候选顺序由对应玩法的版本化编码器维护。

| 层次         | 建议内容与用途                                                                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境重现资料 | 游戏／玩法的精确发行、规则与运行时、初始化配置、规则随机状态和必要环境快照；仅环境与诊断器可读，不进入策略样本输入                                                     |
| 观察与记忆   | 决策时本人授权投影、当前公开场面、本人资源与合法已知历史；未知值显式标记。席位按相对位置编码，保留多人／阵营、阶段及变长集合；不编码昵称、凭证或本人未获授权的隐藏身份 |
| 动作契约     | 保留动作类型、目标及参数的原始JSON语义，另存候选／参数约束和编码版本；小动作集可用候选评分与mask，大动作集采用逐步参数选择或受限生成                                   |
| 决策轨迹     | 对局／席位、决策ID、源分支／修订／并发组、观察与记忆引用、行为策略／模型、实际动作、成功保存水位、本人下一决策观察、累计奖励和终止原因                                 |
| 派生训练数据 | 版本化编码器把语义JSON转成张量；同时绑定数据集、编码器、动作映射与奖励版本。张量缓存可重建，不替代语义原件                                                             |
| 训练检查点   | 权重、模型结构／编码器、优化器、训练随机状态、必要经验池／采样器位置、训练参数及来源摘要；与仅供正式推理的模型包分开                                                   |

现有[SDK](../../packages/game-sdk/src/index.ts)明确`legalActions`可以只是有界建议，参数化完整动作由`isLegalAction`核验。因此不能把“候选列表第3项”永久当成动作，也不能把建议集误认为全部合法动作。索引必须伴随当时的候选标识／顺序和编码版本；模型最终还原语义意图，交真实规则校验。mask及候选生成本身也须经过信息权限检查，避免由合法性提示泄露秘密。

轨迹按每席自己的决策链组织：本人观察→本人动作成功保存→期间其他席／环境推进→本人下一次获准决策观察。中间奖励累计到对应转移，记录推进跨度与折扣约定；终局席位没有下一次决策时生成终止转移。并发密投保留各自原始观察，不让后保存者看到先保存者秘密；取消、过期和保存失败只作诊断，不能当游戏负奖励。资源限制截断与正常终局分开，回退分支不与实际继续分支重复计分。训练序列按对局和席位隔离，记忆／循环网络状态不能串到另一席或另一局。

### 安装包与本机学习存储

- **安装器基线。** 2026-11-21 验收的 1.0.9.1 完整 EXE 为 49,906,647 字节，距 50,000,000 字节上限余 93,353 字节。这个余量仅对应当时的冻结产物。[安装交付](../reference/acceptance.md#当前安装交付2026-11-21) · [交付体积要求](../reference/release.md)
- **默认安装随附各玩法已支持的启发式策略。** 四种人机在 UNO 试点均有启发式基线。首轮权重由独立本机学习环境生成，评分在现有 Worker 内轻量推理。训练器、优化器、训练框架、样本和训练检查点放在安装载荷之外。举例而言，32 个单精度线性权重加一个偏置的参数原始大小是 132 字节。若将来随安装器附带通过验收的模型，按实际封包测量完整 EXE、内部 ZIP、提取及首次启动占用，模型参数估算仅作设计参考。
- **本机学习数据单独计量并限额。** 训练产物与游戏运行和正式存档分开管理。以版本化 JSONL 分片和 manifest 保存可读的语义记录，共享元数据上提，重复观察或候选用可还原的引用或差量。比较单局字节、还原耗时和可读性后定案。

容量上限覆盖学习目录中的原始样本、派生缓存、训练检查点、候选模型与相关记录，并分别统计；按实际普通文件逻辑字节计量，不把NTFS物理压缩量当作容量回收。本机原始采集日志上限为 16 MiB，受管训练任务目录上限为 96 MiB，模型目录上限为 32 MiB。写入预算计入原有记录及原子写入的临时字节，已保存的模型和断点继续保留。达到预算后停止继续写入并提示，可在核对本机余量后用同一任务恢复。研发数据不默认堆入仓库、`tmp`、`assets`或安装载荷，本机学习资料建议置于用户配置数据目录的独立`learning`区域。

建议写入前核对余量，并为训练安全暂停／检查点预留空间；优先回收可重建缓存和已审无引用生成物，真人原始样本的保留／轮换口径在R0定案。正式存档、活动训练输入、当前模型及旧局／checkpoint仍引用的模型受保护，不作为自动腾空间候选。无安全候选时暂停新增采集或训练写入并提示，不阻塞正常游戏保存、回退与恢复。R2验证紧凑表示可还原且不串席泄露，R6验证配额耗尽与恢复；本轮不创建数据目录或执行清理。

### 样本质量分级

质量等级与来源、技术有效性、决策评价分别记录。真人决策归高质量，进入训练仍须通过规则合法、成功保存、本人观察完整和轨迹对齐等校验；损坏、越权、过期或未保存记录进入隔离诊断，不因真人来源跳过校验，也不改写其真实来源。

| 等级     | 建议归类与用途                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------ |
| 高质量   | 来源可核验的真实人工决策；优先用于示范预热、行为学习和关键局面分析，可采用更高采样权重           |
| 标准     | 已验证规则／投影／保存语义的脚本与模型对局样本，承担大规模覆盖和常规训练                         |
| 探索     | 随机策略、早期候选或尚未证明强度的探索样本，保持来源标记，用于探索与发现弱点，不直接视为优质示范 |
| 隔离诊断 | 未通过入库校验的记录，保留失败原因，不进入正式训练或胜负统计                                     |

后三类及其具体细分在R0定案。分级针对每席的实际决策来源，混合真人／人机对局不能整局标为真人高质量；测试脚本、agent代操作、模拟真人和来源未知也不能仅因座位`controller=human`就获得真人标签。采集协议须记录可追溯的实际输入来源，不靠动作强弱猜测来源。

真人失误、失败对局及探索性选择仍保留高质量来源标记，另记结果、复核评价或改进标注；高质量不等于每个动作都是最优答案，不因输局自动降级，也不要求模仿所有失误。建议记录`sourceType`、`qualityTier`、`validationStatus`、分级依据、共同对局／分支来源及标注版本，后续复核不覆盖原始观察和动作。

训练时按来源和等级分层抽样，可提高真人样本权重，同时限制重复次数并报告独立样本量与来源占比。真人记录及其回退分支、增强和派生记录按共同对局来源分组，避免跨训练与最终评估集合泄漏。

R0冻结分级与校验口径，R2实现来源、分级和隔离记录，R5验证分层采样／加权的实际收益，R6检查采集展示及玩家日志边界。此分级不改变按设置采集、不默认导入历史正式存档的约定，当前尚未实施。

## 训练闭环与 UNO 绝悟评分

### 训练数据生产与训练闭环

进展：离线 C 修正、残差配对标注、CUDA 拟合和 A／B／C 配对统计已实现。使用 RTX 3060 Laptop 的 PyTorch CUDA 2.6.0 验证了线性求解，当前测试数据仅证明拟合链路。离线 C 入口可选择本机日志，按采集段和回退标记归并已完成轨迹，再对保留的合法根重新用配对长推演生成标签。玩家命令来源不直接标为已验证真人。离线训练可按完成种子保存断点，绑定 B 系数、语料摘要、策略版本和执行参数。正式 C 训练入口检验 B 校准是否过线和数据种子是否隔离，正式 A／B／C 入口校验两个阶段的输入和完整种子块。试点强度与正式推理启用继续按相应标准验收。入口见[分析工具](../../tools/analysis/README.md#uno-校准与配对试点)。

1. **先验证生产语义一致**。复用 UNO 真实规则／投影生成无 UI 模拟，对照服务和 Worker 检查动作、记忆、规则随机与终局语义。宝可梦原版仅做接口、授权和恢复对照。
2. **先用模拟建立评分基线**。按[配对标注方案](#未知牌假设与配对标注)生成 UNO 整场胜负标签。通过校验的真人决策可作示范或分析样本，保留胜负和失误。
3. **拟合对短搜索的修正**。按[合并方案](#学习修正与有界搜索合并)训练小型线性模型。用固定的默认、豆包、现行绝悟和不同风格对手组成训练对手池，记录行为策略版本、数据来源和样本分布。
4. **分开正式推理和本机训练**。CPU 运行现有规则模拟，本机 GPU 训练由独立训练环境负责。实施预检再核实可用硬件、训练吞吐与暂停恢复，框架与运行预算按实测选择。
5. **冻结候选后独立评测**。按[UNO 绝悟 A/B/C 对照](#uno-绝悟-abc-对照)比较三组，保留样本量、配对差值、运行成本和关键局面回归。通过[首轮建议门槛](#uno-绝悟首轮建议通过门槛)才供新局启用。

绝悟的胜负与名次目标按游戏规则版本维护。若引入个人收益或中间分数，验收须确认它们不会反转正式胜负的优先级，也不会诱导拖局或刷分。捣蛋王单独维护领先者判断和干扰目标，首轮只凭启发式基线验证风格与阵营底线。

默认和豆包保持固定难度，可作为示范来源和对手。首轮自动模型升级仅适用于完成学习验收的 UNO 绝悟节点。

如后续比较强化学习算法，按所选算法核验历史样本的适用性。例如 PPO 的采样批次应绑定对应行为策略、观察和动作编码及行为概率。已保存的真人与旧策略日志可用于模仿或经验证的离线方法。

### UNO 绝悟首轮动作评分模型

首轮以线性修正模型为候选。对[开放节点](#uno-绝悟学习评分节点)的每个合规候选，用本席在该决策时刻的授权观察和候选动作构造特征。模型估计短搜索对候选相对价值的偏差，最终动作仍经规则校验和保存。

#### 首轮特征

每条样本由一个局面和一个候选动作组成。候选保留牌及随牌选定的颜色，同一张 Wild 的不同合法选色分别评分。

| 特征组             | 建议字段                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| 己方出牌后的手牌   | 剩余张数和总点数、按结果颜色或符号可接的牌数、剩余 Wild 与控制牌数量、末张可接性。                         |
| 动作对下一位的影响 | 牌型、结果颜色、反转后的行动方向、按当前动作规则可确定的接棒席或受罚席、对应席位公开手牌数和仅剩一张标记。 |
| 整场形势           | 己方、受动作影响的对手和当前领先者分别距 500 分的差额。区分眼前快出完的人和最有机会赢下整场的人。          |
| 选色证据           | 相关下家的公开选色倾向、本人获准看到且仍有效的同色牌证据，以及证据可用标记。公开倾向和已知牌证据分别编码。 |

颜色按它与当前颜色、候选颜色和己方手牌的关系编码。可先试少量交互项，例如「下家剩一张 × 本席有其末张颜色证据」及「受罚席接近 500 分 × 候选会使其失去行动」。特征取自出手前可知信息及对己方候选动作的确定计算。真实暗牌、牌库顺序和未公开的 +4 合规证据仅在规则环境中使用。[UNO 信息投影](../games/uno/information-and-decisions.md#信息投影) · [授权记忆](../games/uno/bot.md#记忆预算与恢复)

#### 未知牌假设与配对标注

1. **每个决策先冻结一批假设。** 固定己方手牌、当前公开弃牌、各席公开手牌数、可见牌堆数量及仍可确认的授权牌面及所属席位。从剩余牌无放回地填入对手未知手牌、牌库和旧弃牌中的未知位置。公开选色倾向作为评分特征，抽样约束只用合法已知证据。批次、候选、抽样种子和对手策略版本在推演前记录。
2. **每个候选在同一批假设上分别推演。** 对同一假设复制相同的起始分牌和牌库，每个分支只替换第一步候选动作，然后按真实规则各自推进摸牌、重洗、响应和结算。模拟中的各席沿用固定策略，各自按本席投影决策。正式 B、C 共用短搜索批次。离线长推演可以使用另一固定批次，长批次内的所有候选仍共享同一组假设。
3. **用整场胜负做软标签。** 令 B 的首选为参照。长推演运行到有人达到 500 分，本席赢记 1、输记 0。逐假设计算「候选结果减参照结果」，再对有效配对取平均。同赢或同输的配对差为 0。任一分支截断时，该配对单列为未完成，并报告有效配对数和截断率。样本不足或差距很小的标签降权。训练、调参与留出集按原对局分组，同一来源的候选、假设和派生决策保持在同一集合。[UNO 整场计分](../games/uno/rules.md#两人小局结束与整场计分)

#### 学习修正与有界搜索合并

**训练目标 = 长推演的配对整场胜率差 − B 短搜索估出的同一对候选的胜率差。** 两个差都按「候选减 B 首选」计算。B 的叶节点评价采用[共用的整场胜率校准](#截断局面校准到整场胜率)。例如，B 估计选蓝相对首选选红低 0.8 个百分点，离线长推演估计选蓝高 2 个百分点，修正目标为 +2.8 个百分点。

##### 训练样本加权

- **按原对局分配基础权重。** 每场原对局分配相同的总权重预算，按有效决策数均分，再按一个决策内的候选数分摊。长局和候选较多的 Wild 决策都受这一预算约束。
- **按配对标签的可靠性折减。** 重复续推先按同一未知牌假设汇总。起步系数为「有效共同假设数占计划数的比例 ÷［1 +（配对胜率差的标准误 ÷ 5 个百分点）²］」。折减后的权重不重新分配。样本充分且稳定接近零的差值保留为低修正信号。未完成配对按[配对标注规则](#未知牌假设与配对标注)记账。
- **关键场景有限加权。** 接近 500 分、下家仅一张、Wild 选色等场景可在训练中加权，建议最多 **2 倍**。最终验收按自然对局比例统计，并单列关键场景结果。真人决策可用于选取分析局面，候选动作的胜率差仍来自配对长推演。

##### 候选改选范围

C 完整执行与 B 相同的有界搜索，随后只在同时满足下列条件时尝试改选。以下数值为建议，正式对照前冻结。

1. 处于[已开放的正常出牌节点](#uno-绝悟学习评分节点)，挑战候选已进入 B 的合规搜索集合，允许重排合规出牌及随牌选色。
2. 挑战候选的 B 估计胜率距 B 首选 **≤ 3 个百分点**。
3. B 至少完成 **8 组共同假设**，且完成数达到计划抽样数的 **75%**。例如计划抽 16 组时至少完成 12 组。以所有候选均有可用评分的假设计数。[预算截断与分支评分](#预算截断与分支评分)

样本或分差条件未满足时沿用 B 的选择。强制动作、规则可确认的直接终局和未开放节点继续走原策略。C 同分时沿用 B 的顺序。

##### 修正权重与限幅

**C 的排序分 = B 的估计胜率 + 限幅后的加权学习修正**，先乘权重，再限幅。B 首选的修正为 0。起步建议权重取 **0.5**，实际修正限制在 **±2 个百分点**。例如 B 的选红为 28.0%、选蓝为 26.5%，模型预测选蓝被低估 4 个百分点。加权并限幅后加 2 个百分点，选蓝的排序分为 28.5%，可以改选。若模型估计只低估 2 个百分点，实际加 1 个百分点，仍选红。

调参集比较权重 **0、0.25、0.5、0.75** 和实际修正上限 **1、2、3 个百分点**。收益相近时优先采用较小的权重和上限。查看留出结果前冻结启用节点、候选分差范围、最少共同假设、权重和限幅。

##### 学习评分的收益对照

| 对照                     | 方法与判读                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **完整对局 B 对 C**      | 共用候选、未知牌假设、搜索预算和校准器，只切换学习修正。按相同开局种子和换座比较所有整场结果。[首轮晋级门槛](#uno-绝悟首轮建议通过门槛)按单次查看或预先冻结的两阶段区间判定 C 相对 B 的整场胜率收益。 |
| **同一局面复核改选**     | 在 C 实际改选的同一授权局面，用独立的一批长推演假设配对比较 B 首选和 C 首选。报告可介入、实际介入与改选次数、改好和改坏的比例，以及分节点胜率差。                                                     |
| **打乱修正值的诊断对照** | 在同一局面的可改选候选之间打乱修正值，保留 B 首选的零修正、同样的改选条件和限幅。用开发集预先将改选率调到与 C 接近，再冻结对照。只有一个替代候选的局面单列，报告可打乱的覆盖范围。                    |

完整对局达标、实际改选在独立长推演中总体更好、打乱修正后收益减弱，三项合并支持学习评分的收益归因。若完整对局提升而其余证据仍不足，结论限于该批对局中 C 的表现，具体收益来源继续核查。[A/B/C 对照](#uno-绝悟-abc-对照)

## 模型验收与局后运行

### 验收与效果评估

| 验收层           | 建议判据                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境／数据正确性 | 授权输入与隐藏状态隔离；语义动作编码往返、候选重排、参数边界、并发密投及终止／截断正确；快循环与生产路径一致。发现非法动作、越权或恢复错误即不晋级                              |
| 可复现性         | 绑定游戏／模型／编码器／奖励／运行时和样本摘要；固定输入可复查语义轨迹。GPU数值差异记录容差与非确定性来源，不承诺所有设备逐位一致                                               |
| 策略强度         | 冻结权重、编码／归一化统计与探索设置，同预算比较现行策略与候选，对冻结对手池进行人数／座位／阵营轮换；按游戏报告胜率、分数／名次及配对差值的95%区间，不只看训练loss或自对弈奖励 |
| 泛化与退步       | 使用留出开局和多个独立训练随机种子；检查新对手／人数、关键战术局面及对手矩阵，防止仅击败某一策略。不能只挑最强的一次训练作为总体结果                                            |
| 风格与真人体验   | 捣蛋王独立验证优势者选择与实际干扰；默认／豆包／绝悟的玩家获胜体验通过真人混合对局评价，机器人胜率不替代人类反馈                                                                |
| 正式运行         | 在真实32MiB老生代Worker、2秒计算预算下验证冷／暖启动、耗时分布、总进程内存、模型加载和包体积；覆盖模型缺失／篡改、不兼容、暂停、取消、保存失败、回退与重启                      |

建议至少做 3 次独立训练，在开发批次用每个主要配置 500 场完整对局作为起步预算，估计配对差值的波动。R0 在查看留出结果前冻结[正式样本量](#正式样本量)及[两阶段扩样规则](#两阶段扩样规则)、关键局面、启用范围及主要配置退步限制。捣蛋王在独立的启发式风格验证中记录领先者胜势、个人成绩代价与阵营胜负。非法动作、越权和运行异常进入工程失败账本，正常输局保留为对局样本。

#### UNO 绝悟首轮建议通过门槛

门槛在正式试点前于 R0 冻结。当前只定义方案。

1. **整场胜率有实际收益。** 四人主配置中，C 相对 B 的整场胜率配对差值点估计**至少提高 3 个百分点**，且单次查看的 **95% 配对置信区间下界大于 0**。采用[两阶段扩样](#两阶段扩样规则)时按调整后的配对区间下界判定。同时核对 C 相对 A 的整场收益。小局胜率、平均得分和训练损失用于解释结果，晋级主指标为打到 500 分的整场胜率。
2. **关键局面与适用范围通过。** 固定核对接近 500 分、下家仅一张、反转换下一位和本席已知对手末张颜色等局面。规则、授权和固定决策节点的回归全部通过。经典配置、其他人数和对手组合分别报告，正式启用限于通过相应验收的配置。
3. **真实运行与恢复通过。** 每决策计算上限 2 秒，每 Worker 的 V8 老生代上限 32 MiB。要求零非法动作、越权、实际计算超时和错误恢复。比较 B／C 的决策耗时 P95、冷启动和模型加载开销，核对回退、重启续局恢复原模型及本席记忆。[人机调度契约](../reference/bot-players.md#调度暂停与失败处理)

C 同时通过以上三项才启用学习评分。若 B 相对 A 已通过独立验收，而 C 的额外收益仍不确定，则保留 B 作为策略方案，C 留作研究候选。

### 游玩期间适应与局后学习

对通过验收的 UNO 绝悟学习策略，流程为：**固定模型开局→用本局授权记忆适应对手并按设置采集→局后空闲训练→独立验收→新局绑定通过验收的模型**。同一平台对局内的小局、重启读档与回退均沿用原模型。

- **局中适应**：允许根据本人合法观察更新对手行为统计、策略记忆或模型内部状态，更新仍进入现有动作事务和checkpoint。首期以本局席位为范围，不默认建立跨局真人身份档案；不同人机席位的私有记忆不合并。
- **局后训练**：主机启用后，已准备的独立本机训练器在空闲许可内运行。服务等房间连续空闲 5 秒后发短期许可，开局（含局中暂停）、关闭学习或服务退出时撤销。训练器按完成种子和拟合阶段保存断点，CPU 续推检查许可，GPU 只终止自己启动的拟合子进程。训练器和 GPU 依赖独立准备，安装器未增加训练载荷。[空闲暂停与续跑夹具](../../artifacts/maintenance/bot-rise-idle-20261126/with-storage-quota-r2/report.json)
- **新局生效**：候选通过评测后，登记不可变模型引用并供后续新局自动绑定，绑定基础游戏发行、策略、编码器和权重摘要。`BotData.modelRef` 保存与发行、规则、策略与等级匹配的内容摘要。缺模型时保留原档并提示恢复原绑定。
- **发行与信任**：本地模型作为明确支持学习能力的新策略的数据引用，不覆盖EXE核验的游戏／策略映射，不改写旧发行。本机模型按内容摘要保存在配置数据目录的 `learning/models`，原游戏仍由签名包加载。模型登记和停用均在本机目录内操作。

训练输入先封存为绑定分支／修订的不可变对局快照，训练器不读取可变实时存档。管理员结束记录为中断，不因状态为ended就生成自然胜负奖励；后续回退继续保留原模型，撤销分支标明共同来源，避免重复计权和跨集合泄漏。原终局被撤销后不再将其当作实际终局样本，未启用候选重新核验来源；不为采集禁用回退或热替换已绑定旧局的模型。

活动对局只更新可恢复的本席记忆，权重由局后训练生成的独立版本更新。正式推理与训练的空间边界见[安装包与本机学习存储](#安装包与本机学习存储)。

#### 模型登记、停用与恢复验收

## 文档复核提示词

按「接着细化……先只讨论方案」的提问方式组织复核。以下提示词用于校对已写入的方案。共同边界为纯文档工作、试点保持待启动、实现按后续授权推进。

1. 接着细化人机统一接口和快速评估：对照现有 SDK，明确 UNO 与宝可梦原版各验证哪些授权、动作、记忆和保存节点，以及怎样记录与复现同一批结果。
2. 接着细化四种人机的体验差异：找出能区分默认失误、豆包短前瞻、绝悟整场布局和捣蛋王目标选择的 UNO 局面，并明确固定局面、完整对局、真人体验各自的通过条件。
3. 接着复核 UNO 绝悟 A／B／C 验收：核对对手池、种子块、扩样和区间规则，检查搜索校准与学习修正能否分开归因，保留实际样本量待 R0 冻结。
4. 接着细化逐游戏迁移：按正式玩法列适配重点、秘密和计分边界、可复用接口与独立验收条件，核对宝可梦扩展和拍卖类游戏的复用范围。
5. 接着细化本机学习与模型交付：核对设置、配额、暂停、独立验收、新局绑定、停用和旧档恢复，写清证据要求及等待实测的参数。
