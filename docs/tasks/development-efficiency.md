## 剩余试点验收

后续5个可比任务的读取输出减少50%以上、工具往返减少25%以上；暖构建或单游戏打包耗时减少25%以上。均为试点目标，未达时记录实际数据与原因，不把调用相关性、单个夹具或源码进程首次启动换算成额度节省与EXE冷启动收益。

### 实际任务采样

文档知识整合试点目前累计 **0／5**。试点期间，凡正常验收需要查阅项目文档的真实任务，从首次定向查阅开始采样。记录沿用该任务的现有验收报告，其他任务照常按范围验收。

1. 开始时锁定要回答的真实问题、适用范围、需要保留的前提与例外，以及改前文档和本任务实际使用的文档版本或 SHA。两侧从相同的已知线索出发，按各自版本的入口查阅，使用相同的工具、读取预算和结束条件。旧版依据缺失、问题或范围发生变化时，在报告中说明差异，等有可比证据再计入。
2. 在同一份报告中记录任务与日期，并留存两侧的入口、章节、读取命令及原始结果的可核验位置。按实际返回的 UTF-8 字节数统计读取量，含检索和续读输出。每轮发出工具请求并收回结果计一次往返，并行调用按实际交互轮次计。分别记录首次是否命中权威章节、是否覆盖必要例外，以及正文与入口的改动处数、资料整合和审计的实际投入。有真实 token 时另记缓存输入、未缓存输入和输出。暖构建和打包仅在任务本来需要时按同环境、同命令和同缓存状态测量。
3. 收尾时核对两侧数据和证据定位，每个合格任务在本节登记一次，链接其验收报告并更新累计数。同一任务的重试或续读合并记录。缺失、截断或不可比的部分说明原因，留在原报告。三道固定题的统计继续留在[文档提效回放](documentation-wiki-and-skills.md#固定问题回放2026-11-16)。
4. 第 5 个合格样本在该任务收尾时触发评估。列出五组实测及合计变化，与读取输出减少 50%、工具往返减少 25% 的目标比较，并核对正确性和维护成本。未达目标时记录实际值和原因，定向调整并复核受影响部分。结论和证据收入[原实施归档](../archive/documentation-optimization-2026-10-18.md)，按[更新与归档](../reference/maintenance.md#更新与归档)归档文档整合任务页，修复索引和入链，撤下试点采样入口。构建提效的独立待验项继续在本页维护。

2026-11-26 回查了性能优化、现代艺术大屏、跨游戏审阅修正、安装器瘦身、游戏菜单一致性和宝可梦布局六项真实工作的会话。原日志保留了部分实际命令和返回内容，部分调用混读多份正文且输出截断。六项均未找到同一问题、同一范围的基线与改后记录，累计为 0／5。
