### 文档知识整合与技能抽象计划

2026-10-18用户确认的改造计划，实施未开始。目标是在现有文档体系中引入轻量 LLM Wiki 方法，并将“文档维护与资料整合”“按变更范围验证”抽象为两个项目 skill，提高查询准确度、减少重复阅读和工具选择成本。本轮只建立计划，不执行正文迁移、工具改造或 skill 创建。

#### 范围与完成标准

改造覆盖入口精简、长篇主题整理、状态与范围标识、章节检索、增量审计及真实任务收益评估；其中游戏规则资料、候选游戏与方案研究、素材来源和采用理由、已解决的重复工程问题采用轻量 LLM Wiki 方法。沿用[文档索引](../README.md)、[维护规则](../reference/maintenance.md)、[游戏索引](../games/README.md)和[工具索引](../../tools/README.md)，不新增平行的全库 wiki 或逐文档摘要副本。

完成时，各类纳入内容具备可定位的来源、适用范围、状态和唯一正文；新增资料可按固定流程增量整合；两个 skill 能调用已有工具并正确处理缺口与失败。通过代表性任务比较准确度、读取量、调用次数及维护开销，实际收益与未达目标分别记录。

现行平台规格、交付契约继续由对应正文维护；包哈希、测试通过状态和设备验收继续以实际证据为准。知识摘要用于导航和复用结论，不替代产品规则核验、源码检查或必需验收。

#### 六项文档组织改造

##### 1 精简入口与职责

AGENTS.md 保留必须遵守的边界、最小阅读方法和主题入口；docs/README.md 按“当前问题 → 唯一正文及章节”导航；分类 README 说明所属主题职责；完整规则、操作、例外和依据归主题正文。将入口中的重复状态、历史变化和详细功能说明归回对应主题或归档，必要的关键边界继续保留。

先试点 docs/README.md 与维护规则页，再按实际查询扩展；已有上下文注入且未变的入口不重复读取。验收时检查常见问题能否直达目标章节，以及精简后是否仍能发现必须遵守的约束。

##### 2 整理混合内容的长文档

优先审查 validation.md、requirements.md、art-preferences.md 和 maintenance.md：分别梳理检查选择与证据／安装验收、现行与未来要求、通用与游戏专属偏好、当前规则与历史变更理由。先重组章节，确有独立职责再拆文件，保留必要的上下文、例外、原话来源及历史边界。

借鉴 Diátaxis 区分操作方法、参考规格、解释理由与教程的阅读需求，保留现有目录职责，不为凑齐分类新增教程或重建目录。完成标准是每个目标问题有可独立读取的完整答案，迁移后原有入口与适用旧锚点可追溯。

##### 3 就近标明状态与适用范围

按下文主题约定，在易歧义的结论旁注明要求、实现、待验收、研究判断或历史状态，并写明版本、游戏、端侧和例外。已确认未来要求与现行行为分别呈现；日期用于追溯，不单凭更新时间判断权威性。不强制所有页面增加大量元数据。

验收样例包含“未来扩展包方向与现行完整EXE契约”“源码模拟通过与真实设备待验收”“官方规则与项目解释”，检查检索片段是否保留关键限定。

##### 4 增强章节定位与按需读取

复用 docs:read 的大纲、精确章节、8KiB输出与续读机制。试点轻量、按需执行的章节查找能力；拟议接口为 `pnpm docs:find "换机授权" --scope=platform`，命令名、范围映射及实现方式在工具阶段定案，当前尚不可作为已实现命令使用。

默认只搜索当前源码文档，排除 archive、日志与生成物；历史查询须显式选择。标题精确匹配优先，正文匹配补充，返回少量候选及路径、完整标题层级、行号和短摘录，再按需读取正文。已知多个章节可评估批量读取并共享输出预算；保留原文定位、截断／未命中提示，无法确定的范围不得静默当作完整结果。

检索片段须保留影响判断的章节性质、适用范围、版本及关键限定，不能仅凭目录排除归档就将当前页面中的未来要求视为现行行为。必要前提或例外位于父章节、其他段落时，随结果提供原文补读位置；预算不足时明确标记上下文未完整返回，命中关键词不能直接视为已取得充分依据。

续读游标绑定所读文件的内容版本；工具阶段确定内容指纹及传递方式，不以行号或修改时间代替内容一致性。首段与后续读取之间文件发生变化时，明确拒绝继续按旧游标解释并提示重新定位，不静默拼接不同版本的正文。当前 read-doc.mjs 的游标仅为 line:column，此项属于待实现能力。

与现有 rg 加 docs:read 对照验证首次命中、同名章节、中文术语、无结果、截断续读和显式历史查询；补充同页现行／未来内容、跨段前提与例外，以及首段读取后正文插入、删除或章节迁移导致旧游标失效的场景。新增章节查找、批量读取仅在证据表明仍有定位瓶颈时扩展；向量库、全库摘要和常驻检索服务暂不纳入实施。

##### 5 复用审计并补准确性检查

在现有链接、标题和迁移审计上增量补充重复标题歧义、当前入口误指历史正文、迁移后可达性及超长章节提示。命令与路径优先从已有工具或配置核对，不再建设重复注册表；只对实际变化涉及的内容检查，迁移按需审查全量入链。

机械检查之外，用代表问题核对目标正文是否适用、例外是否完整；链接可达不能代表答案正确。既有失败单独保留，新增失败必须定位修复，不能通过改基线掩盖。

正文迁移按单一主题或独立章节分小批次实施，每批核对“原章节 → 新正文 → 适用旧入口转链 → 必要前提与例外”，通过内容及入链检查后再扩大范围。沿用既有迁移对照和证据，不另建长期重复正文；同一文件保持唯一负责人，写入前若发现其他任务的新改动，重新核对差异。需撤销时只处理本任务改动，保留其他工作内容，不整体重置工作区。

##### 6 用真实问题比较收益

复用下文收益评估与既有提效任务，选择安装验收、秘密投影、游戏规则、UI偏好等固定问题，对比权威章节定位、必要例外、首次命中、读取量和工具往返。将资料整合及审计成本计入，避免只报告查询时的节省。

先记录基线，再用相同问题验证试点，最后通过后续可比实际任务观察；真实 token、字节数与费用分别处理，不用字节降幅替代 token 或费用降幅。正确性和必需验收不因读取预算而降低。

#### LLM Wiki 改造范围

LLM Wiki 采用“保留原始依据、增量整理主题、维护关联与冲突”的方法；具体规则按项目职责裁剪，不照搬外部目录模板。

| 内容                             | 适合度 | 计划改造                                                                 | 正文落点                                           |
| -------------------------------- | ------ | ------------------------------------------------------------------------ | -------------------------------------------------- |
| 游戏规则原文、勘误和版本差异     | 高     | 按采用版本定位原文，连接规则主题、例外、裁定和未核实缺口                 | 对应游戏的 sources 与规则主题                      |
| 候选游戏、扩展玩法和技术方案研究 | 高     | 积累方案比较、来源、取舍及相互矛盾的结论，区分研究与已确认决策           | 候选页、对应任务及 decisions；定案知识进入既有主题 |
| 素材来源和采用理由               | 中高   | 将原件、派生、用途和采用理由关联至现有清单，明确检索资料与正式导入边界   | 外部素材工作区及对应游戏资源主题、manifest         |
| 已解决的重复工程问题             | 中     | 提炼触发条件、原因、解决办法、验证边界和失效条件，仅保留有复用价值的结论 | 对应 reference 或工具 README；过程留既有证据或归档 |

##### 主题与来源约定

- 每个结论只有一个维护正文；索引、任务和 skill 通过链接引用，不平行维护完整规则或命令。
- 来源记录包含版本／语言、原始定位、核验状态及适用章节；资料原件和原始证据保留在已有位置，不为 Wiki 复制一份。
- 实际采用的来源以已有版本、修订标识或文件 SHA 识别，优先复用来源表与 manifest，不重复登记。来源替换、修订或原核验依据失效时，沿既有关联定位受影响结论，将其核验状态标为待复核并定向核验；保留原结论与依据边界，复核结果更新到唯一正文。来源变化不自动否定用户要求或改变产品实施状态，未受影响的结论继续复用原依据，不建立全库定期重验机制。
- 易歧义的章节明确标注“已确认要求／当前实现／待验收／研究判断／历史结论”，并写清适用游戏、端侧、版本及例外。混合页面按章节标注，避免整页状态掩盖局部差异。
- 新资料与旧结论冲突时，保留冲突双方和采用理由；不能仅凭日期新旧、LLM 推断或既有实现改写用户要求及官方规则。
- 长篇按可独立回答的问题组织；必要前提和例外随章节保留。只在确有独立主题时拆文件，不机械按字数拆分。
- 受影响主题维护必要的来源关联与入链；不建立全库手工标签体系、常驻索引、每次查询总结或全聊天自动归档。

##### 增量工作流

1. 核对新增或变化资料的来源、版本、内容范围和可信边界；来源身份变化时先定位受影响结论并标记待复核。
2. 从现有索引找到唯一正文及相关决策，仅读取受影响章节；未变依据复用，变化部分补读 diff。
3. 判断是补充、替代、冲突还是重复；只更新相关正文，未定事项留原任务或研究入口。
4. 同步必要的来源定位、状态、例外和入链；正文迁移时保留适用的旧锚点转链。
5. 执行定向链接、标题、迁移与内容核对；按小批次闭合条件确认后再扩大迁移范围，返回变化结论、依据及剩余缺口。

查询时先使用现行主题结论；涉及精确规则、争议、版本差异或资料变化时回到原始依据。来源缺失或尚未核实应明确显示，不能将摘要推断写成已核验事实。

#### YAML 元数据使用机制

不批量给现有 Markdown 添加 YAML front matter。仅当技能发现规范要求，或已确定的工具需要读取整页属性时使用；LLM Wiki 整理本身不要求 YAML。文档维护 skill 在新增或修改页面时先判断是否存在实际消费方，不能为格式统一自动补字段。

| 文档类型             | 采用机制                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------- |
| SKILL.md             | 必须使用技能规范要求的 front matter，至少包含 name、description；创建时核对规范和技能发现方式 |
| 游戏来源与研究整理页 | 仅在章节检索／筛选试点需要整页属性时添加，先少量试点                                          |
| 当前规格、操作指南   | 默认不用；适用范围、例外和状态在相关章节就近说明                                              |
| README 与索引        | 默认不用；目录、链接及标题承担导航职责                                                        |
| 历史归档             | 默认不用；开头说明归档日期、原因与当前入口，原结论保留原边界                                  |

- type 仅表达文档类别；status 仅表达整页整理生命周期；scope 仅表达整页稳定适用范围。试点前固定字段含义、允许值和实际用途，不建立任意标签集合。
- 上例 status: draft 表示研究整理尚未定稿，不表示产品未实现，也不表示全部来源未核验。整页状态不能替代章节的“已确认要求／当前实现／待验收”等性质说明。
- 一页含官方规则、项目解释和待核实事项时，各部分分别标识；不得用单个 verified 或 current 字段暗示全部内容已核验或已实现。无法准确概括的整页属性直接省略。
- 标题、路径、Git变化和已有来源表／manifest可取得的信息不重复手填；版本、来源定位和核验结果继续维护在其唯一正文。仅因重新保存不刷新所谓核验日期。
- 元数据用于导航与筛选，不增加内容权威性。缺少可选 YAML 的文档仍参与默认标题及正文检索，不能被静默排除。

##### 采用与校验流程

1. 明确字段的消费工具、筛选问题和预期收益；无实际用途则保持普通 Markdown。
2. 在代表研究页试点，比较读取与维护成本；SKILL.md 单独按技能规范校验，不套用研究页字段。
3. 使用已有锁定依赖或受限解析能力读取纯数据，不执行 YAML 中的对象标签或指令；不为元数据全局升级工具。工具阶段按需校验语法、重复键、字段类型、允许值及适用文件范围。
4. 新增字段必须同步其消费逻辑和必要检查；格式错误明确报告，不静默当作可信状态，也不把解析失败当作无搜索结果。检查只覆盖实际使用 YAML 的文件，不强制其余文件补齐。
5. 消费方取消或字段无法可靠维护时，移除无用途字段；有价值的结论、来源和状态先保全到对应正文。

验收覆盖无 YAML、合法研究页、混合状态章节、错误 YAML 和技能必需字段缺失。确认检索不会因缺少可选元数据漏掉权威正文，元数据不会覆盖原文、用户要求或实际验收证据。机制通过试点后归入维护规则唯一正文，任务页只保留剩余接续。

#### 两个项目 skill

Skill 负责触发条件、输入、步骤、分支判断和输出；确定性执行继续由仓库工具承担。创建时按 skill-creator 流程确定项目级存放与发现方式，使用相对引用或项目根定位，避免固定本机绝对路径。SKILL.md 保持精简，现行知识和详细参数链接已有正文，不复制动态状态。

各 skill 的 description 简洁写明工作流、应触发条件和容易混淆的不适用边界；详细步骤放正文，不能仅在正文说明触发条件。技能试点在未预读技能正文、未继承前次答案的新会话中验证实际发现和路由，分别覆盖应触发、不应触发，以及两个技能连续配合的任务；核对是否按需读取正文和调用既有入口，不能用 front matter 格式通过或当前会话显式读取代替路由验收。

##### 文档维护与资料整合

触发：用户要求整理项目文档、接入新资料、整合规则或研究结论、迁移／归档主题，或修正文档冲突与入链。普通问答和单次读取不强制执行完整维护流程。

输入为用户目标、受影响主题／来源、可写范围和完成标准。先读取任务相关状态与 diff，判定唯一正文及来源；按上述增量工作流整合，区分要求、现状、计划和历史；最后定向核对内容及链接，报告修改路径、采用依据和未决事项。

复用 [read-doc.mjs](../../tools/maintenance/read-doc.mjs) 的大纲、章节与续读能力，以及 [audit-efficiency-docs.mjs](../../tools/maintenance/audit-efficiency-docs.mjs) 的链接和迁移审计。不把已有工具写入 skill 副本，不将归档默认混入当前检索。若试点证明定位仍需过多往返，再评估扩展现有工具的标题查找或批量章节读取；不预先承诺新增检索服务。

完成标准：能够处理新资料补充、来源冲突及变化后定向复核、未核实原文、章节迁移小批次闭合、正文未变复用及文件版本绑定的截断续读；检索片段保留判断所需上下文，无新增坏链接，不丢失必要例外和历史边界；普通查询不会自动产生文档写入。

##### 按变更范围验证

触发：用户要求针对本次改动选择或执行检查、解释证据能否复用、处理验证失败及定向复验。单条明确命令不增加无关检查流程。

输入为任务自有变更、实际依赖影响、验证目标和已有证据。按[验证规格](../reference/validation.md)及[验证工具](../../tools/test/README.md)识别 scope／preset 或显式计划；复核实际变化绑定和证据适用性，再选择执行、复用与排除。执行后说明通过、失败、未执行及其理由，避免将源码、模拟设备或历史包证明升级为当前安装器或真实设备验收。

复用既有 scoped runner、changes 清单、计划、证据和失败账本；范围登记和统计仍由现有实现负责，不在 skill 中再建测试注册表。统一失败阈值、修复后定向新轮、无变化不重试及收尾边界按对应正文读取，不复制成第二套可漂移规则。

完成标准：覆盖单游戏、共享依赖、纯文档／工具改动、变化清单过期、可复用证据、证据失效、达到失败阈值和实质修复后新轮等场景。只读选择也须检查工具实际副作用；需写报告或执行检查时遵循任务授权，skill 不扩大系统操作、清理、发布或部署权限。

#### 验证与收益评估

沿用[渐进开发提效任务](../tasks/development-efficiency.md)的真实任务采样和证据入口，不另建每聊天账本。先用固定问题集比较改造前后表现，再通过后续5个可比实际任务观察收益；复用既有兼容样本时注明范围，不重复计算。

| 指标               | 记录与判断方式                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 查询准确度         | 是否找到适用的权威章节、原文及例外，片段是否携带关键限定或明确补读位置；来源变化后受影响结论是否准确标为待复核；不得以减少阅读牺牲正确性 |
| 首次命中与调用次数 | 第一轮是否包含目标章节，定位到充分依据所需的工具往返                                                                                     |
| 读取量与 token     | 记录实际输出字节；有真实 token 数据时分别记录，字节不直接换算成 token 或费用                                                             |
| 技能路由           | 在未预读技能正文的新会话中，应触发任务能触发、不适用任务不过度加载或执行，两技能连续配合任务路由正确；比较人工选择工具的成本             |
| 维护成本           | 记录资料整合、关联更新和审计开销，计入总成本后评价收益                                                                                   |

读取量减少50%以上、工具往返减少25%以上沿用既有试点目标，属于待验证目标。准确性不得下降；未达收益时记录实际值和原因，调整受影响组织方式，不放宽规则、断言或必需验收。

本轮计划文档仅做格式和定向链接核对。后续文档迁移执行既有审计并区分旧失败与新增失败；skill 创建按工具影响执行适用检查。普通问答不调用有写入副作用的审计入口，验证 skill 的副作用场景使用隔离样例，不以试点名义启动完整构建、安装或发布。
