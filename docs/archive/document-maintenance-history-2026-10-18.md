## Agent入口迁入的执行约束

以下为原入口的有效约束，2026-10-13按主题迁入；不是新增产品要求。入口仅保留关键规则与阅读路由。

1. 先读本文件、[文档索引](../README.md)，检查 Git 状态与相关 diff；按 [定向查询](../README.md#定向查询)读必要章节和源码，复用未变结论，不重复遍历生成物。

2. 目录归属查 [目录职责](../reference/project-structure.md)，实现边界查 [工程结构](../reference/architecture.md)，运行、验证、清理与压缩查 [开发环境](../reference/development.md)。维护文档前读 [维护规则](../reference/maintenance.md)，项目瘦身查 [方案与执行记录](../reference/project-slimming.md)。

3. 当前交付查 [验收](../reference/acceptance.md)，发布流程、附件和更新说明查 [Release流程](../reference/release.md)，接续工作查 [任务索引](../tasks/README.md#后续开发接续入口)，重要选择查 [决策索引](../decisions/README.md)；第一至六阶段已完成，仅追溯历史时读 [归档](README.md)。

4. 游戏规则、来源、权限、策略与验证各自维护：[宝可梦奇遇](../games/pokemon-encounters/README.md)、[现代艺术](../games/modern-art/README.md)、[电力公司](../games/power-grid/README.md)、[拉密](../games/rummikub/README.md)、[UNO](../games/uno/README.md)、[阿瓦隆](../games/avalon/README.md)。电力公司只采用经典德国修正版，42 城／六区／83 边及横向绘图边界见 [地图](../games/power-grid/map.md)，不能混入 Recharged 或其他地图。拉密仅采用经典版 2–4 人，不混入 XP／六人版；整回合与百搭边界见该游戏规格。UNO 采用 Mattel G7942 经典 108 牌、平台 2–6 人，不混入自定义或交换手牌版本。阿瓦隆采用2012经典版、平台5–10人，新局仅使用 `configured` 人数角色表，含同版莫德雷德／奥伯伦知识边界；旧 `classic`／`court` 仅恢复原局，不混Big Box或其他扩展。

5. 跨游戏交互、计时、恢复与显示查 [平台规格](../reference/phase-02-platform-spec.md)，接入新游戏查 [扩展指南](../reference/game-development.md)，电脑玩家查 [人机规格](../reference/bot-players.md)。游戏 bot 与开发子 agent 是不同角色。

6. UI、布局、图标、头像、插画、声画与视觉审查先读 [用户美术偏好](../reference/art-preferences.md)、[通用视觉](../reference/visual-design.md)及对应游戏规格；美术资源检索与处理进入外部 [素材工作区](../../../TMP/TableMaxMaterial/AGENTS.md)，该目录不创建 Git，正式资源核验后仍导入本项目 `assets/`。设计时按用途、端侧与人数适当参考偏好及细节，派工传入这些入口。偏好依据仅取用户历史请求，不能把 agent 回答、既有实现或实施选择写成用户偏好。

7. 协作先读 [职责索引](../subagent/README.md)及对应角色文档；已授权的位图生成、编辑与核验交给 [imagegen 子 agent](../subagent/imagegen.md)。

- 修改前明确范围与完成标准；关键未知项影响目录或实现选择时先询问。保留用户及其他 agent 的已有改动，只改本次授权内容；区分产品要求、已实现行为和技术建议。

- 执行 [Agent 开发效率规则](../reference/maintenance.md#agent-开发效率规则)：合理复用、模块解耦；测试驱动并优先易错项；每个构建项进行中定期播报预计完成时间；适当并发并明确依赖、唯一负责人及隔离输出。按任务预检环境／素材，先打通跨层路径和高风险场景，再完成适用验收。仅相关变化、失败或未解决疑点才重跑已通过检查，较大任务保留实际关键耗时与未完成项。

- 工具输出只留结论、失败详情和证据路径；独立检查批量执行，等待使用完成通知或有界等待，无新信息不反复读取或询问进度。模拟验证优先隐藏窗口／后台，截图来自实际更新后的渲染；原型走查不代表产品验收。

- 未来计划只保留未完成事项，部分完成只列剩余工作与验收缺口；全部完成后移出并修复入链，不保留已完成占位，不把技术建议写成用户已确定方案。状态与归档规则见 [维护规则](../reference/maintenance.md#未来计划维护)。

- 按[周期提交与推送](../reference/maintenance.md#周期提交与推送)执行 Git commit／push：长任务默认每30分钟检查一次，独立阶段完成或任务收尾时立即执行；仅提交通过适用验证的本次改动，保留用户及其他任务的暂存／未提交内容，由主 agent 统一推送。用户明确指定的频率、分支或禁止推送要求优先。
