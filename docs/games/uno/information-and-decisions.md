# UNO 信息权限与决策

规则以 [U01](sources.md) 为准，数字平台解释集中在 [规则](rules.md#数字平台解释)。游戏使用稳定座位，不读取昵称、房主授权、网络凭证或管理员身份。

## 信息投影

| 内容                                     | 公共／管理员 | 玩家本人／该座位 bot                   |
| ---------------------------------------- | ------------ | -------------------------------------- |
| 当前弃牌、颜色、方向、发牌者、回合与阶段 | 可见         | 可见                                   |
| 每位手牌数量、累计分、胜局数、已喊 UNO   | 可见         | 可见                                   |
| 牌库顺序与旧弃牌实体顺序                 | 不可见       | 不可见                                 |
| 手牌具体编号与牌面                       | 不可见       | 仅本人                                 |
| 刚摸牌具体编号                           | 不可见       | 仅当前摸牌者                           |
| 待决 +4 出牌者、受罚者、旧颜色、选定颜色 | 可见         | 可见                                   |
| 待决 +4 是否违规、完整原始手牌证据       | 不可见       | 声明阶段不可见；质疑完成后仅质疑者可见 |
| 最新保存动作与公开目标／摸牌数量         | 可见         | 可见                                   |
| UNO 漏喊窗口                             | 可见         | 可见，可提交本人响应                   |
| bot 记忆与策略随机源                     | 不可见       | 不下发 UI；仅服务给相应 bot            |

`project` 新建全部可变容器，管理端始终用 public，不扩展游戏权限。卡牌封面、计时或动画都不能推导牌库。规则存档含完整秘密，由平台本地持久化；客户端只接收投影。

## 动作与节点

| 节点                 | 决策者                 | 动作及边界                                                                |
| -------------------- | ---------------------- | ------------------------------------------------------------------------- |
| 开局 Wild 选色       | 发牌者左边首位         | `choose-color {color}`，红／黄／绿／蓝，选完仍由本人行动                  |
| 正常回合             | `turnSeat`             | `play {cardId,color?,uno?}`；普通牌不可传 color，Wild 必须选色；或 `draw` |
| 能出的刚摸牌         | 本人                   | 只可 `play` 刚摸到的编号，或 `pass` 保留                                  |
| 摸到不能出的牌       | 自动                   | 交棒，无新的玩家选择                                                      |
| +4 待响应            | 受罚者                 | `accept-draw-four` 或 `challenge-draw-four`；不开放叠牌                   |
| 倒数第二张同时喊 UNO | 出牌者                 | 出牌含 `uno:true`，只在出后剩一张时接受                                   |
| 漏喊后补喊           | 漏喊者                 | `declare-uno`，关闭当前窗口                                               |
| 抓漏                 | 其他任一座位           | `catch-uno {target}`，必须为当前漏喊者；罚 2，关闭窗口                    |
| 下一小局             | 平台管理员／已授权房主 | 生命周期 `next-round`，只在 `round-result`；游戏 bot 不提交               |
| 500 分结束           | 自动                   | `ended`，无游戏决策与下一小局动作                                         |

UNO 补喊、抓漏与当前回合彼此冲突，不声明独立并发组。决策编号包含小局、回合、已保存动作序号与座位；先提交成功的动作更新序号，旧决策由平台拒绝。全部动作精确白名单化，拒绝多余字段、未知牌、非本人持牌及非法阶段。

## +4 证据与恢复

动作列表始终列本人 +4 的四种颜色声明，包含可受质疑的诈唬；不会因为存在同色牌而拒绝动作并旁路泄露秘密。规则在出牌时保存旧颜色、移除 +4 后的完整手牌及违规计算。

待决证据必须与出牌者当前手牌完整一致。唯一可在响应前改变这副手牌的动作是抓漏罚摸，此时证据仍完整匹配罚摸前手牌前缀，最新保存动作目标和追加张数必须一致。读档拒绝只保留“没有同色牌”的子集、伪造 guilty、错受罚座位和牌组丢失／复制。

质疑成功或失败都保存私密证据给质疑者；公开事件仅包含成功／失败、受罚者和数量。后续公开出牌可让已获授权的 bot 更新其记忆；回退和重启恢复当时的规则与策略记忆，不能延用撤销分支知识。下一小局清除证据及策略观察记忆。
