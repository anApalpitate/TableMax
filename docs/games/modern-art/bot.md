# 现代艺术独立人机策略

2026-10-04 根据用户关于公开竞价节奏、有限记忆与跨轮规划的反馈更新。统一入口为 [bot/index.ts](../../../games/modern-art/bot/index.ts)，策略 ID `modern-art-local`、版本 `1.0.0` 保持不变，兼容旧存档中的 `null` 记忆。三档均为包内本地算法，不调用云端服务。

## 授权输入与记忆

策略只接收本人安全投影、合法动作、可恢复随机源、取消信号及本人策略记忆，不读取规则 `State`。当前行情与历史估值表、本人现金和手牌、公开收藏、当前拍品及报价始终重新读取；忘记的是过去见过的画作身份，不丢失当前可见局面，也不故意算错公开价格或现金。

[memory.ts](../../../games/modern-art/bot/memory.ts) 逐条读取尚未观察过的公开记录，并记住当前公开收藏与拍品。记忆保存最近日志编号、公开画作 ID、轮次与本人本场公开拍卖的加价次数；忘记后不会通过重复读取旧日志立即补回。记忆不保存未知手牌、未公开暗标或其他席位现金。

| 等级 | 公开见牌记忆上限 | 换轮保留       | 未来轮次范围 |
| ---- | ---------------- | -------------- | ------------ |
| 默认 | 最近 8 幅        | 最近 2 幅      | 只考虑当前轮 |
| 豆包 | 最近 28 幅       | 最近 14 幅     | 下一轮       |
| 绝悟 | 最多全部 70 幅   | 保留已观察记录 | 全部剩余轮次 |

容量与换轮衰减是本项目对有限记忆的可解释采用方案，不是游戏规则或真人记忆能力的定量结论。当前可见画作即使超出容量也参与本次评估。绝悟只保留实际被其投影观察到的信息，记录已经截断时不会补造缺失历史。策略记忆随原有动作保存、checkpoint、回退与重启流程恢复；新增对象有严格字段／数值／唯一卡 ID 校验，旧 `null` 会在下次决策建立记忆。

## 报价与选画

三档按当前排名、累计历史价格、本人持牌和记住的公开供给估计成交后可兑现价值，按各自保守系数设置最高报价。默认选画含受保存随机源控制的扰动，豆包比较公开收藏收益，绝悟增加持牌影响和结束轮次的相对收益。第五张候选后，所有画家统一按同一个新排名计算，不能给不同画家混用排名。

公开拍卖使用与自身估值成比例的跳价：第一次通常进入预算中段，第二次接近预算，第三次最多到达预算上限，此后确认不加价。正常跳价至少 2；离上限只剩 1 时可以最后补 1，但不会反复每次只加 1。当前价已经超过预算则直接确认。每场最多三次本人加价；报价仍须从输入合法动作中选择且不得超过本人现金。一轮拍卖一次给出预算内报价，暗标不读取未公开竞争者金额，定价与购买沿用相应合法动作。

普通选画和双拍卖会比较实际组合价值；为双拍卖提供第二幅画时计入两幅成交收益，接牌本身可能触发第五张时改用结算收益。高级策略会因保留画作的未来价值而拒绝低收益接牌。

## 多轮规划与限度

[planner.ts](../../../games/modern-art/bot/planner.ts) 从公开总发行量扣除已记住的画作、当前公开画作及本人手牌，得到各画家仍未知的供给量。它不把未知量当作对手真实持牌，也不假定知道未来发牌顺序。

豆包对下一轮做轻量估算；绝悟对所有剩余轮次比较六种供给情景：均衡供给以及每位画家分别更受关注。每轮根据估计供给与本人持牌预测排名，并累加市场价值、扣减预计消耗。未来收益考虑延后折损、出售机会数量和同画家多张手牌的递减机会，不能假设全部手牌都能成交。选画评分结合本轮收入与剩余手牌的未来收益差，竞价为下一轮可能的购买机会保留部分现金；第四轮不留跨轮预算。

这是有界期望评分，当前热度排名仅作为本轮累计行情的估计起点，不是未来排名、对手行为或胜率保证；不模拟未知手牌。每个候选最多计算五名画家、六种情景及三轮预测，取消信号在情景边界检查，计算量远低于平台 2 秒 Worker 预算。品牌等级表示本项目策略差异，不表示模型调用或全知能力。

## 验证

[strategy.test.ts](../../../games/modern-art/bot/strategy.test.ts) 覆盖三种人数 × 三档 × 三个固定种子，共 27 场完整四轮对局。每一步核验合法动作、输入不变、游戏序列化与恢复、本人记忆 JSON 往返和公开权限；另外核验隐藏现金／手牌顺序不影响选择、第五张统一排名、有限记忆不自动补回、当前场面仍可使用、公开跳价至多三次、未来轮次范围与保留高潜力画作的明确选择差异、无效记忆与取消。整局测试记录每档决策数量和实际最长计算时间，保留 1.5 秒上限检查，为平台预算留出余量。

这些用例证明声明的算法、授权与恢复边界，不证明绝悟一定战胜豆包／默认，也不替代真实服务或最终便携包验收。
