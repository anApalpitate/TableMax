# 电力公司：三档电脑策略

独立策略入口为 `games/power-grid/bot/index.ts`，经共享 `BotStrategy` 接收本人安全投影和服务端合法动作。策略只看到本人现金、公开的电厂／仓储／城市／顺序／市场、本人可见建城费用与合法动作；对手现金、牌堆牌号、秘密移除牌号均不提供。记忆为 `null`，不调用其他游戏策略或网络服务。

## 已实现层级

2026-10-05 debug 将竞价与经济规划分开。三档先由本人现金、厂组、聚合燃料、公开市场、城市及对手公开可供电能力计算最高预算 B，再依当前价依次进入 `ceil(60% B)`、`ceil(85% B)`、B；正常追加至少 2，预算仅剩 1 时允许最后补 1。超过预算退出，同一场最多三次追加。竞争者报价不提高 B，厂间转存不改变聚合库存。沿用共享思考节奏、两秒上限、策略版本 `1.0.1` 和 `null` 记忆，旧存档无需迁移。

| 决策 | 默认                                       | 豆包                                         | 绝悟                                                   |
| ---- | ------------------------------------------ | -------------------------------------------- | ------------------------------------------------------ |
| 选区 | 在连通合法区域组中带种子随机               | 评估区域内低价连线密度                       | 更重视网络可扩展度与连线费用                           |
| 竞拍 | 简单产能收益，保留基本现金，少量带种子扰动 | 评估升级／替换、燃料成本、扩城预算           | 加入后期公开对手产能、终局紧迫度与升级效率             |

三档都遵守完整燃料输入、有限仓位、按计划批量采购、拆厂转存、混燃和终局燃料可用性。购厂报价保留资源／扩城预算；高档不凭空使用隐藏的对手现金，不读取底层状态。终局判断从公开的对手城市、电厂和储存燃料推算其当前可供电城市，而不是把名义总产能当作本轮可供电数。

## 生产计划与动作粒度

联合预测位于 `games/power-grid/bot/planner.ts`。豆包保留最多 8 个候选、每次决策最多 1000 个预测节点；绝悟最多 16 个候选、6000 个节点，多个购厂／替换候选共享该预算。每轮搜索前三次扩城的不同序列，再合法贪心完成后续扩张；除本轮现金收入外计入网络和可供电能力的后续价值，避免无限积累现金而停滞。节点上限、稳定排序和取消检查固定，时间不会改变选出的动作。

采购费用按完整价格阶梯逐份计算，售罄不可购；混燃同时约束煤油共仓。三档策略保留原有燃料及电厂优先级，将同厂同种燃料合并为一次合法数量采购，上限取当前计划缺口与服务端合法数量；跨厂、跨燃料仍分别决策。旧的单份合法动作列表仍可使用。运行资源返回供应池，补给受供应与市场容量限制。当前建城／发电阶段不能预测本轮再购料；已运行厂从剩余组合排除。只根据公开已出现的第三步信号预测生效边界，不猜牌序或保证未来电厂可得；行政阶段抽到第三步牌的最后一次第二步补给由规则层保持。

2026-10-06 用户要求快速调整 AI 采购且不重新构建。本次仅更新策略源码及针对性测试，现有 v1.0.3 运行 ZIP 保持上次交付内容，批量 AI 采购需下次构建后进入运行包。

生产规划采用最多四座厂的有限资源动态规划：按总煤／油／垃圾／铀用量合并相同状态，保留最高产能，再选达到最大城市数的最少资源方案。混燃厂逐厂枚举合法配方，服务端合法动作仍只有“运行这一厂，用这个配方”，没有把整套电厂组合指数展开成网络动作。

运行前按目标配方逐份转存，双方混燃仓满时可原子交换煤油。运行过的厂不能再运行，后续计划扣除本轮已经生产的电力；环保厂足够供电时不再多烧有料厂。每次策略只返回一个已有合法动作，照常经过统一身份、决策、校验、保存、事件、回退和暂停流程。

## 验证与局限

规则场景测试覆盖第一轮强制购厂／重排、顺时针竞价与两种退出、未购厂清理、拆厂和燃料守恒、全部混燃配方、满仓交换、三个第三步触发与第二步交叉时序、最短路线经过满城、终局燃料证明和三级平局。三档策略还有“燃料竞争偏紧时高档增加储备、无收益时结束采购”“改变所有对手现金仍不改变投影和决策”“免费环保发电后不多烧资源”的具体测试。

带种子的 45 场完整规则对局覆盖 2–6 人 × 三档 × 三个种子，逐动作检验可恢复状态，定期 JSON 往返恢复，逐动作规范形式与平台契约一致，终局验有限资源守恒；计算最长目标低于 1500ms。额外核验三档报价上限、末次加 1、混燃跨档／售罄、公开现金权限和具体等级动作差异。电脑 Worker、SQLite 恢复和真人手机完整路径的实际结果另由平台集成／交付验收承担。

当前策略是三档本地启发式加有限生产规划，不宣称搜索最优或已有统计胜率优势；不读取真实玩家掉线状态代其行动，不以不合法动作试探秘密余额，不枚举未来隐藏牌堆。
