# 马尼拉视觉设计

本次用户明确要求“写实、模拟实体桌游沙盘、有动态感”。这是《马尼拉》本次要求；布局参数、材质色值与具体动效时长属于实现选择，不追加到通用用户偏好。

设计参考[通用偏好 G01／G02／G09／G10／G11／G13／G18](../../reference/art-preferences.md)和[视觉规范](../../reference/visual-design.md)：游戏主体优先、主题成熟、具体位置操作、稳定沙盘、规则按需浮层、小屏重排与保存后反馈。

## 契券与铜牌深化（2026-10-17）

本轮采用用户确认的“契券与铜牌”：秘密股份入口使用叠契券与封印，展开的每张股份以真实货物图、名称、本人／公开状态及抵押章呈现；回执、账本和操作列表使用轻薄铜牌。圆叉关闭保持至少44px热区，信息至少16px，主要操作及关键状态至少18px。

状态栏左侧用当前`turnSeat`对应的座位头像和昵称辨认行动者；无行动者时不虚构玩家头像。本人资产按“现金”与“抵押可借”分别显示，避免把可借款当作现款。港口、修船坞、货船、船员分红、海盗、领航、保险及航次详情分别组合对应插图、关键数值和短规则；必要费用、风险、分红池与具体占位均保留。

窄屏保险标题采用图标在上、双字横排，避免窄列拆成孤字；账本姓名、本人和港务长采用独立标签。费用、收益和行动状态分组展示，不用中点串联；这些形态属于本轮设计选择，文字偏好依据仍归用户美术偏好。

商人账本采用纸册、紧凑书本图标／航次副页眉、带头像的资产行、货物行情轨道、最近航次分红及终局信息。公开账本只使用公开资产和公开股份，未揭示股份只从本人投影显示。样式与全屏布局作用域分离，账册不继承页面`100dvh`最小高度。

港口／修船坞卡按内容定高并靠顶部排列，不随旁边航道拉长；场景背景继续承载航道空间。只有固定确认栏实际存在时才按实测高度避让，其他状态不保留140px空白。骰子为独立正方形显示组件，手机32px、电脑44px，不因行高或flex拉伸。

## 场景与组件

2026-10-16深化方案采用同系列竖版港湾、朝上木船、四种货物及保险行／港口／修船坞／海盗／领航图像；图像承担对象辨识，规则数字、费用、座号和轨道由代码精确排版。各素材的生成、alpha、比例、字节与来源以资源清单为准，生成完成不代表UI导入与实际渲染已经通过。

本地原创 `harbor-v1.webp` 为写实微缩殖民港湾，平静青绿水域承载航道，岸边建筑与仓库提供环境。透明 `boat-v1.webp` 保持原始长宽比，用于可移动木船；货箱色块、格数、骰点和伙伴编号由代码绘制。封面与资源来源、提示词、原图及 SHA 由[资源清单](../../../assets/games/manila/manifest.json)维护。

三条水平航道精确显示起点 0 与 1–13 格；超过第 13 格的状态以“已靠港”及泊位字母表达。未装船时只展示等待装载的空木船，不伪造已选择货物或骰点。船旁的货物标签同时给出名称、独立配色和分红池，不能只凭颜色判断。

货船岗位、港口、修船坞、海盗、领航员和保险行是实体棋盘分区。奶油纸与木质边框承载精确中文和费用；伙伴棋子使用稳定座号与对应色，旁边商人资料显示头像和昵称。选择用青绿色实线／描边，已经占用用棋子与文字，草稿不提前移动真实船或更新资产。

行情保留六档完整价格和库存，每货当前价格突出。公开商人信息显示现金、股份张数、伙伴数、港务长及公开股份，私密股份只出现在玩家本人资料。

## 屏幕适配

信息字号至少 16 CSS px，主操作与关键状态至少 18px，电脑分区标题至少 20px。短屏和手机采用重排、滚动与分步骤操作，保持字号；按钮、选择框与岗位动作至少 44px。

桌面将沙盘与操作侧栏并列，适配720p至4K；主机突出管理与公开局势，公共屏突出航行、占位与结果。手机竖屏独立采用三条自下向上的航道，底部0、顶部13，超过13另示靠港；港／坞ABC与专家各有图形岗位。手机横屏将港湾与操作左右排布，根据实际可用宽高重排，不等比缩小电脑棋盘。主要确认固定于底部安全区，现金、必要费用、风险与额度常显；股份、行情与商人详情由可点击或长按的半透明卡片按需查看。公共屏与主机缩放沿用独立偏好，手机不提供电脑显示设置。

正常390×844派遣将托盘、任一合法目标与确认保持首屏可达；320×568核心操作页目标不超过1.5屏，唯一纵滚负责人，确认不得遮挡目标。货船只提供当前最低空费位的派遣落点；图形与列表替代入口表达相同动作。图像保持比例，目标至少44px，信息至少16px，主要动作与关键状态至少18px。

玩家浮动交互按钮默认停靠页面顶部并随页面滚动；竖屏顶栏保留独立空列，宽屏顶栏右侧预留64px，避免遮挡岗位、现金或阶段信息。用户仍可自行拖动，默认位置的避让由实际页面几何检查核验。

## 动态边界

船的位置仅由保存后的投影改变，以短行驶过渡连接；掷骰结果使用本地代码骰点并做落定动效，回执保留可读结果。骰子只在本次新增航行保存反馈时播放，不把派遣或抵押误表现为重新掷骰。没有无限装饰循环、联网资源、WebGL 或额外重型库。

测试模式与系统减少动态关闭过渡和动画。刷新、重新连接及历史状态完整同步不补播，退出组件后不留下计时器或媒体播放。本次深化补充原创短音效与主题演出，分类来自公开前后投影和已执行动作，不解析中文记录。派遣、航行、靠港、掠夺、保险与结算可以在一次保存中分别产生反馈；新终局也可演出。桌面声源遵循公共屏优先仲裁，手机初始静音、显式启用；静音后开启不补播。规则图解包含完整航次、装船合计9、船员均分与港坞阈值、13格海盗、领航、保险和贷款。实际证据由[验证场景](validation-scenarios.md)记录，源码静态通过不能替代截图、解码或试听。
