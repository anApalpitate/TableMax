# 马尼拉视觉设计

## 信息精简与行动引导（2026-10-21）

岸上名称与费用／棋子组成独立居中顶行，条件收益另起一行居中；海盗与领航只有一行，取消隐含第二行并将完整头身棋子与名称一起居中。各端沿用所属样式负责人，不靠缩字、裁切或额外高特异性补丁解决。保存提示只保留一份，锚定阶段／行动状态区，按实际文字与可交互图形边界寻找既有空白；锚点与文字均绝对定位，不再附着MANILA标识，也不增加占位或内边距。窄屏结算状态明确分为阶段行、说明与启程操作行，避免控件占满所有空白。

当前行动入口用金色底、清楚描边和约1.8秒一轮的柔和光晕呼吸强调，定位后保留静态高亮；显式点击后操作区边框强调约1.2秒。减少动态仅保留静态强调和立即定位，不进行快速明灭或自动滚动。周期、配色、目标强调时长属于本次实施参数；用户明确要求及确认的停止条件见[美术偏好](../../reference/art-preferences.md)。

持仓入口统一为“查看股票”，正文仅按张展示货物图卡，抵押单据／持有勾及公开眼睛／私密锁表达状态，名称和状态可按需读取。融资复用既有财富区域另行打开；收支零分项隐藏但零余额和汇总保留，详见[交互](interaction.md#信息精简与行动引导2026-10-21)。

## 标识、顶部与岗位对齐（2026-10-18，追加反馈）

用户随后用三张实际界面图指出：新增标识不协调且有文字省略，顶部阶段白底突兀，右侧费用、收益与岗位名排列别扭。本次调整限马尼拉展示，不改变动作、规则或秘密投影。

实现采用同一套纸牌标识：空航道标签按文字宽度收口；电脑船员数、分红及完整编号岗位合在一张纸牌内，预留四岗位宽度，不以省略号裁掉状态。顶部阶段信息沿用整条工具栏底色；右侧设施采用统一行卡，图标与标题左对齐，岗位名和费用在同一行居中，收益独立一行。玩家具体船舱岗位的编号与价格分行，在44px触控行中完整呈现。色值、宽度及行高属于本次实现选择。

手机竖屏货物牌将完整货名放在首行，分红标签和金额在左下分行，骰子独立放在右下；预留72px牌高，关键金额保持18px，避免骰子遮住货名或分红。

2026-10-19追加修正：电脑船只状态从基础样式移除省略号，按完整状态保留最小宽度；状态与分红允许分行，覆盖靠港A／B／C及进坞。开发预览需要重新启动并新建对局加载新资源，旧存档仍固定原发行。

源码守卫除原字号、船字间距和对比度外，增加实际字形边界、骰子与文字相交、主机／公共屏裁切与顶部透明背景检查。文字允许采用深字纸底或奶白字深青底，对比度仍至少4.5:1；不把所有覆盖照片的标签都强制涂成独立深色条。实际结果见[验证记录](validation-scenarios.md)。

## 照片文字、船位与收支卡（2026-10-18）

本聊天三图反馈要求继续解决背景上的深色文字、横屏调位方向、合法范围高亮和船遮刻度，补齐每航次收益消息。实现采用局部深青实底与奶白字，覆盖照片上的航道名、刻度、起点／草稿、船员、空舱及去向；纸卡内部继续深色文字。横向船体与下方数字独立分层并至少间隔8px，竖向保留独立数字栏，不以缩字处理短屏。

三端收支卡在棋盘上方正常占位，默认展开、可收起，高度按设备与结算内容分配且不超过320px，正文内部滚动（现行比例见文末图形语义与信息层级）。商人头像与姓名对应收入、支出、现金净变化；分类及融资按需展开，借款不是收益、购股不等于财富亏损。窄屏按信息组重排；顶部阶段与下方行动提示一致。具体收支与恢复边界见[交互](interaction.md#航次公开收支与调位2026-10-18)，本轮源码验证见[验证](validation-scenarios.md)，历史“已修复”只证明各自旧输入与范围。

电脑收支摘要按商人并列，卡片上限30dvh；结算期行情改为货物与完整价阶同一行，保留右侧五设施的岗位空间。手机竖向航道保留0／5／10／13刻度，精确在航位置放在货物标题下方预留区，合法格用金色格标，不挤出相邻数字。最终可见标牌与横向船字均留至少8px间距，竖向航道／轨道有独立最小高度。

本次用户明确要求“写实、模拟实体桌游沙盘、有动态感”。这是《马尼拉》本次要求；布局参数、材质色值与具体动效时长属于实现选择，不追加到通用用户偏好。

设计参考[通用偏好 G01／G02／G09／G10／G11／G13／G18](../../reference/art-preferences.md)和[视觉规范](../../reference/visual-design.md)：游戏主体优先、主题成熟、具体位置操作、稳定沙盘、规则按需浮层、小屏重排与保存后反馈。

## 玩家横屏问题分析（2026-10-18，已修复）

证据：修复前 `artifacts/manila/validation/ui-final6-20261018/player-{844x390,932x430,1024x768,1123x1428}.png`；修复后 `artifacts/manila/validation/clean-1/`（13 视口＋10 详情，守卫全绿）。以下问题按严重度排序，均是实际渲染可见，不是推测。

### P0 结构性问题

- **右列与行情垂直碰撞（1024×768 最严重）**：五设施行、黑市四行与决策行需要约 590px，但 1024×768 的展板可用高度不足；港口/修船坞、海盗/领航与行情相互压叠，行情最后一行被裁切，保险“即收10₱”被决策面板盖住。1123×1428 虽能放下，但行情四行在约 150px 内，标题与价目几乎相接。
- **右列最右侧槽位文字裁切（844/932/1024/1123 均有）**：A/B/C 的费用与“收益 N₱”在槽位右缘被截断；844/932 的港口/修船坞列更窄，C 槽几乎只剩字母。原因是右列宽度由 `clamp` 决定，但槽位仍按三列均分，16px 文本没有最小宽度保障。
- **短横 844×390/932×430 的航道内容互相压叠**：`船员 N`、座号徽章、`3号位` 空位卡、`空舱` 与相邻航道/船体重叠；`3号位` 卡跨越航道边界。五设施列与槽位也互相贴边，标签“港口/修船坞”与 A/B/C 槽共用边框，读成一张卡。
- **短横的决策区悬浮在棋盘照片上**：`伙伴/结束派遣/操作列表`作为漂浮卡片压在展板右侧与保险行上，既遮住对象，又没有占位；页面下方是大片空照片，空间分配与内容重要性相反。
- **短横把行情与商人整体隐藏**：844/932 只能通过账本浮层查看行情、商人与公开股份；竞拍/派遣阶段缺少对手现金、股份和当前价，玩家必须离开棋盘查账。
- **顶部占用过高**：844×390 中顶栏、状态条与钱包占约 140px（36%），实际棋盘只剩约 250px；MANILA 品牌与两行状态仍在争抢首屏高度。

### P1 可读性与层级问题

- 航道只标 0/5/9/13，船又压在 9 上；刻度点过小、间距不均，1–4、6–8、10–12 没有可读定位。
- 货物标题卡在 1024 溢出到轨道（“肉豆蔻”压住 0 格），1123 又被省略成“肉…”，同一个对象在不同宽高下表现不一致。
- 1024/1123 商人条姓名被截成“长昵称测试…”，标签换行占掉第二行，现金/股份/伙伴被挤到第三行；844/932 直接隐藏商人条。
- 黑市四行在 1123 的标题行与价目行几乎相接；1024 最后一行被裁切，当前价与库存无法完整读取。
- 岸线与行情都是奶油纸底、细边框，缺少分组间距/标题，视觉上连成一块；展板照片又从决策面板下方透出，层级更乱。

### 修复结果（2026-10-18）

按高度分档重排，全部落在 `games/manila/ui/stage.css`，只作用于玩家屏；主机／公共屏与竖屏既有骨架不动。

- **P0① 右列与行情垂直碰撞**：宽屏（`mn-wide`）玩家改用与主机链同特异性的六类选择器 `.mn-screen--player.mn-wide .mn-layout > .mn-main .mn-board-scroll > .mn-harbor` 重述骨架——两列 `minmax(0,1fr) clamp(300px,34%,380px)`、三行 `minmax(0,1fr) minmax(0,.62fr) auto`、areas `'lanes shore'/'lanes market'/'actions actions'`。决策行独占整行，不再落入隐式第三列。1024×768 实测 harbor `cols 655|340`、`rows 306/190/60`，行情与决策矩形不再相交。
- **P0② 槽位文字裁切**：`.mn-space` 统一两行网格（第 1 行名称＋价格、第 2 行收益/即收），`grid-template-rows: 18px 18px`、`height: 44px`（短横 38px）、`overflow: hidden`，并在宽屏链整套重述以覆盖 `harbor-layout.css:429-437` 的 `18px 24px` 旧模板；`.mn-space-earn` 占 `2 / 1 / 3 / 3`，任何宽度下不再被卡片下缘裁切。竖屏改港口/修船坞各占一行（每槽约 97px）。
- **P0③ 短横航道互压**：短横改 `'lanes shore' / 'actions market'` 两行两列，航道/岸线各占 `minmax(0,1fr)` 行；`.mn-lane` 三列 `minmax(126px,.75fr) minmax(0,1.9fr) clamp(168px,23%,210px)`，货卡两行（26px 图＋名称 / 分红池），`3号位` 卡留在 crew 列内不再跨航道。
- **P0④ 决策区悬浮**：决策区回到网格内的底部行（短横与航道同排、右半为行情摘要），`.mn-controls` 固定 38px、`.mn-action-tray` 36px，取消浮卡与下方空照片。
- **P0⑤ 短横隐藏行情与商人**：`display:none` 只在 `max-width:620px` 生效；短横保留单行行情（`肉豆蔻 0 丝绸 0 人参 0 翡翠 0`，当前价彩色徽章）与 44px 商人条。
- **P0⑥ 顶部占用过高**：`≥621px` 时 `.mn-screen--player` 自身变两列三行网格，顶栏与状态条同排（36px），隐藏 `.mn-box-label`、品牌副标题与重复的“已保存”chip，钱包行压到 26px 单行；844×390 首屏棋盘由约 250px 提升到约 300px。
- **P1 刻度/货名/商人条/行情/岸线**：航道 `0–13` 全刻度按等距显示；货卡名称在 844/1024/1123 一致（不省略、不压 0 格）；商人条姓名 16px 完整显示、标签与资产各占一行（`.mn-merchant-name{justify-self:stretch;font-size:16px}`）；行情四行行高按容器均分、当前价用彩色徽章；岸线五设施改为 `52px` 标签列＋槽区，分组间距与标题层级恢复。
- **顺带修正**：领航位硬编码标签由 `'小'/'大'` 改为 `'小船'/'大船'`（`games/manila/ui/Board.tsx:64-68`）；`.mn-pirate-line` 海盗拦截浮标在玩家屏 `display:none`（其信息由每条航道的 13 标记与海盗设施卡承载，浮标原本 `position:absolute; top:80px` 会压在货卡上）。

### 根因

1. 玩家宽屏只有一套 `≥900×601` 网格，用固定五行设施＋四行行情＋决策行硬塞进 1024×768 与 1123×1428 两种完全不同的高度；没有按高度提供 compact/短横变体。
2. 设施槽位始终三列均分，没有最小列宽或两行布局；右列 `clamp` 只控制整列，不控制槽内文本。
3. 短横仍沿用旧 `≤1050` 三列布局，航道最小高度、船员卡与决策卡的内容高度超过可用高度，靠溢出显示而非重排。
4. 验证只断言元素存在、无页面滚动与字号，不断言子元素裁切、成对矩形不重叠；因此 1024 的压叠仍能“通过”。
5. 行情/商人在短横被 `display:none`，但没有等价的可见摘要。

### 下一轮建议（已完成）

1. 增加高度分层：`short`（高≤600）、`compact`（601–820）、`full`（>820）。短横改为“航道在上、岸线横向条在下、决策固定底栏”，或“航道左、岸线右、决策底栏”，不再三列硬挤。
2. 1024 宽屏改为展板左 60%＋右列仅设施，行情移至展板下沿或可展开的底部条；或把五设施压成 2 列×3 行，给行情固定 180px 且行高≥44。
3. 所有网格子项加 `min-height:0`、`min-width:0` 与 `overflow:hidden` 的明确策略；槽位改两行（字母/费用＋收益），列宽≥88px；文本只在名称上省略，费用/收益不得裁切。
4. 短横合并顶栏与状态为一条 48–56px，钱包并入状态；决策区改为占位的底部栏，取消悬浮卡。
5. 短横保留一行“行情＋商人”摘要（当前价、各人现金/股份）或清晰的分段入口，不再整块隐藏。
6. 验证新增：`scrollWidth<=clientWidth`、后代元素不越界、岸线/行情/决策/商人条两两矩形不相交，覆盖 844×390、932×430、1024×768、1123×1428。

结论：1024×768 与 844/932 不是“再调间距”能解决的问题，需要按高度重排；1123×1428 只需收右列槽位与行情行高。当前源码视觉验收只证明元素存在与无页面滚动，不代表上述压叠/裁切已通过。

### 验证守卫（2026-10-18 落地）

`tools/test/games/manila/verify-manila-design.mjs` 现在在渲染几何阶段计算并断言三类缺陷，全部通过才继续详情流程：

## 场景与组件

整图按控制带、港湾展板（三条航道＋右列五设施＋黑市）和底部商人条组织。海面以三条轻薄横向航道带关联货物／方形骰子、船与刻度、船员和分红池；主机／公共屏直接呈现每船真实船员岗位的费用或占用者，避免只显示人数而丢失棋盘位置关系。海上位置只以对应刻度的高亮读数为主，靠港／进坞另显示去向。“分红池”表示整船可分金额，不表示单人收益或派遣费用。

右岸五设施按内容定高、顶部连续排列，统一小间距；建筑与名称采用弱化边框的标题槽，岗位采用浅色槽。每个岗位固定为上层名称和下层状态，费用与占用者共用相同区域。主机底部商人条集中身份行与资产行，头像完整，座号放在昵称旁；现金、股份、可用伙伴采用相同标签顺序，短屏可将“可用伙伴”压缩为“伙伴”。行动者通过头像、席位色带、轻背景和短状态共同强调，分红与终局结果在本人行内展开。

主机分红池使用只读短标签，货物标题提供统一详情入口，避免给同一份说明重复配置大按钮。玩家在货物标题区持续显示分红池，调位时不因底部岗位槽隐藏而丢失金额；手机底部控制槽仍固定64px。

2026-10-16深化方案采用同系列竖版港湾、朝上木船、四种货物及保险行／港口／修船坞／海盗／领航图像；图像承担对象辨识，规则数字、费用、座号和轨道由代码精确排版。各素材的生成、alpha、比例、字节与来源以资源清单为准，生成完成不代表UI导入与实际渲染已经通过。

三端共用 `Theme.tsx` 的轮廓图形：伙伴使用人物棋子，借贷单据表示抵押额度；岸上收益行按2026-10-21反馈改为纯金额，不再加收入／风险图形。商人资产每组有完整可访问名称和详情，棋子数字对应商人座号。领航岗位明确写“小领航／大领航”，不再写成容易误认船型的“小船／大船”。这些图形为本地内联SVG，不增加位图或运行依赖。
