# 拉密经典版：三档本地人机

独立入口为 [bot/index.ts](../../../games/rummikub/bot/index.ts)，策略 ID `rummikub-local`、版本 `1.0.0`、规则版本 `classic-2025-digital-v1`。本页描述实际算法；真实 Worker、服务恢复和最终运行包的证据由平台验收记录维护。三档均为包内本地算法，名称不表示调用同名云端服务，也不保证胜率。

## 授权输入与保存

策略只接收本人牌架、公开桌面（含公开百搭绑定）、公开玩家牌数／首出状态／成绩、当前本人决策、规则提供的动作和取消信号。不接收完整 `State`、其他玩家牌架、牌池实例或顺序、身份凭证、管理权限或 checkpoint。搜索只用本人牌架和公开桌面，不通过非法动作试探秘密信息。

当前局面的全部可用信息已经在投影中，三档均使用 `null` 记忆，无额外见牌历史。选牌和同分排序完全确定；策略不调用 `Math.random`、时钟或平台随机源，不消耗规则随机序列。相同投影与等级产生相同意图，回退和重启沿用平台保存的策略版本及 `null` 记忆。

每次只返回一个完整回合意图 `submit-turn`，或规则已授权的 `draw`／`pass`。参数化回合不要求出现在建议动作列表中，仍由平台 `isLegalAction`、决策／身份／分支校验和保存事务再次检查。策略不提交 `next-game` 等管理生命周期动作，不代掉线真人行动。

## 已实现层级

| 等级 | 牌架组合                                             | 公开桌面                                         | 同等出牌数的比较                                   |
| ---- | ---------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------- |
| 默认 | 按出牌数、牌点、稳定标识贪心选择不相交的同数组／顺子 | 完成首出后直接向现有同数组或顺子两端加数字牌     | 优先打出牌点较高的牌                               |
| 豆包 | 有界搜索不相交组合，比较整套出牌                     | 尝试单个现有牌组的拆分／补牌，其他组保持原样     | 加入剩余牌架的同数、邻号与百搭可组合度             |
| 绝悟 | 同上，较大预算                                       | 对全部公开桌面做实例精确覆盖，允许跨组拆分／合并 | 同上；清空牌架优先，其次出牌数、牌点、剩余可组合度 |

[candidates.ts](../../../games/rummikub/bot/candidates.ts) 直接枚举 3／4 张不同色同数组及 3–13 张同色连续顺子的牌面模板，百搭显式绑定颜色／数值。每张物理牌使用独立位，原桌面牌必须全部覆盖，本人未出的牌可以保留在牌架。既有桌面组始终进入候选，避免候选截断丢失原桌面的可行基础。相同牌面的两份实例及百搭排列有上限，超限仅截断搜索，不改变规则。

[planner.ts](../../../games/rummikub/bot/planner.ts) 先建立合法贪心候选，再做牌架或桌面搜索。桌面搜索优先覆盖候选较少的原牌；牌架搜索可明确留下某张牌。整回合始终交给共享 `prepareTurn`／`inspectTurn` 检查实例守恒、至少出一张本人牌、首出三十点、首出当回合不动原桌面、百搭释放证明和当回合重用。百搭替代优先采用最终桌面中已经合法的牌组作证明，必要证明搜索限制 160 节点。

牌架纯候选预先建立独立索引，避免每个牌架节点反复过滤全部混合桌面候选；实例位和同一出牌集合的评分在本次规划内复用。已经首出的牌架状态可记忆化，未首出的相同实例还保留不同百搭绑定对应的三十点阈值。相同评分按稳定搜索顺序保留第一个合法布局，避免无收益的整桌字符串重排。

每次规划独立建立共享 `TurnProofCache`，最多 256 项，按原组需要的物理实例、所有可用物理实例和证明节点上限隔离。最终桌面可以直接证明时优先采用；缓存仅保存完整搜索的合法证明或完整无解，不保存取消或节点截断，成功证明防御性复制。它不进入策略记忆或存档，不绕过最终 `inspectTurn`，不改变百搭规则政策。

## 计算预算与局限

| 等级 | 每个候选池上限 | 整次候选生成步骤上限 | 整次搜索节点上限 | 首阶段牌架节点上限 |
| ---- | -------------- | -------------------- | ---------------- | ------------------ |
| 默认 | 900            | 14,000               | 1,000            | 只做贪心           |
| 豆包 | 3,000          | 60,000               | 14,000           | 3,000              |
| 绝悟 | 7,000          | 130,000              | 36,000           | 5,000              |

限制定义在 [budget.ts](../../../games/rummikub/bot/budget.ts)。每个候选池分别限量，牌架、单组和整桌搜索共享整次生成／节点预算；统计候选数记录池峰值。稳定排序及物理副本上限固定，实际耗时不参与决策。候选生成和每个搜索节点检查取消信号；返回前再次校验。搜索耗尽后保留已经验证的最佳候选；没有候选时优先使用规则已证明的合法回合建议，再使用授权摸牌／停牌，不因为搜索截断宣称不存在合法出牌。真正的 Worker 超时／异常仍按共享平台机制安全停止，不隐藏失败。

这是在授权信息下的有界组合搜索。绝悟的“精确覆盖”指对选中候选的物理实例精确覆盖，不表示在无限候选／无限节点下保证全局最优；它不预测隐藏牌池顺序或对手真实牌架。默认的简单组合会错过某些重组，较高档也可能在预算内没有发现合法复杂回合。空池停牌的规则级存在性判断属于规则模块，与本策略的启发式搜索分开。
