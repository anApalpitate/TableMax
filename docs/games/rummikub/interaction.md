# 拉密交互与三端显示

采用经典版 2–4 人，玩法以[规则](rules.md)与[来源](sources.md)为准。UI 独立入口为 [web/index.tsx](../../../games/rummikub/web/index.tsx)，不读取规则完整状态、牌池顺序或他人牌架。

## 设计依据

按[设计时优先考虑](../../reference/art-preferences.md#设计时优先考虑)与[细节偏好及适用判断](../../reference/art-preferences.md#细节偏好与适用判断)，本次采用实物牌辨识、游戏主体优先、清楚的字级与选择状态，按端侧调整密度并保持桌面布局稳定；确认操作易达，私有草稿与已保存桌面明确区分，声画只在保存后反馈，并提供顶层图文规则。这些是本次选用依据；浅色实体数字牌、木边与浅绿桌面为实现判断，不能写成用户指定材质。

四色分别附方形／菱形／三角／圆形，牌面通过颜色、数字和形状共同辨识。百搭保留独立脸谱与当前代表的颜色数字。信息文字至少 16 CSS px，主要动作与状态至少 18px，电脑分区标题至少 20px；数字牌和按钮满足 44px 触控。

## 整回合草稿

轮到本人时，牌桌显示“桌面草稿／仅你可见”，公开端继续显示已保存桌面。所有操作均在本人浏览器草稿内完成，只有“提交回合”发送一个整回合动作。

| 操作           | 行为                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 点选牌         | 可选任意本人牌架或可操作的桌面牌，按选取顺序标号；再次点选取消该牌。                                       |
| 建立新组       | 将选中牌移入新组，不复制牌实例；自动选择可能的顺子或同数组类型。                                           |
| 放到开头／末尾 | 将选中牌从原容器移入目标组；顺子在最终提交时按数字规范化。                                                 |
| 组操作         | 按数字排序，从单张选中牌之前拆开，或调整为顺子／同数组。少于三张可暂时存在，但不能提交。                   |
| 更多→暂持      | 从任意可操作组取出牌暂持，用于拆分、交换和重组；原桌面牌不能退回私有牌架。                                 |
| 更多→退回牌架  | 只可将本回合来自本人牌架的牌退回；桌面原牌禁止此去向。                                                     |
| 更多→指定百搭  | 显式选颜色与 1–13 的数字；未绑定的百搭阻止提交。替换、释放和当回合重用由共享规则校验。                     |
| 撤销／重置     | 撤销最多 60 步；重置回到本回合开始的桌面与牌架，重置也可撤销。                                             |
| 提交回合       | 全部牌组合法、暂持区清空、原桌面牌守恒、至少出一张本人牌且首出／百搭条件满足才启用。保存成功后才展示结果。 |
| 摸牌／过牌     | 结束回合。存在改动时明确确认放弃草稿；是否可过牌由服务端合法动作决定，非法提交不视作超时。                 |

首出当回合的原桌面整组只读，避免把达到 30 点后的同回合误作已允许重组。首出后的后续回合才开放桌面多选与重组。

本地预览使用本游戏 `shared/melds.ts` 与 `shared/turn.ts` 的纯校验，不另写一份规则。提交动作包含最终桌面和可审计百搭释放证明；服务端仍执行身份、决策点、实例／分支与原子保存校验。

## 草稿恢复与身份

同一组件保留草稿、选取与浏览排序，显示倍率、菜单、规则浮层、无关安全同步和横竖屏切换不重置它。安全恢复使用当前标签页 `sessionStorage` 单一槽位，不使用跨标签页的 `localStorage` 存牌。

草稿范围键绑定实例、分支、回合、本人稳定座位，以及回合开始的公开桌面／本人牌实例快照。刷新只恢复完全相同范围；回退、重启分支、换座位、下一回合与新对局都拒绝旧草稿。读入时按当前授权投影核对每个牌实例、唯一性、完整数量、组 ID、去向和百搭数字，陌生牌、重复牌或原桌面牌进入牌架均拒绝。正式秘密数据与对局始终由服务端保存和投影，浏览器草稿不是存档或 checkpoint。

## 三端与布局

- 主机／公共屏：围桌席位展示头像、完整昵称、剩余牌数、首出状态和累计分；中心只读桌面占主要区域。主机管理放菜单，管理员没有私有牌架或代出牌入口。
- 本人回合：上方保留桌面／牌架定位、撤销／重置和选牌操作；同一纵向工作区浏览桌面与私有牌架，底部提交／摸牌保持可达。长顺子只在所属组横向浏览，避免整个页面横向溢出。
- 等待回合：显示已保存桌面与本人牌架，玩家摘要按需浮层查看，不开放出牌按钮。
- 电脑浏览器玩家横屏：保持普通玩家权限与同一组件实例；按平台 `data-player-display` 将桌面与牌架排为两栏，各自负责纵向浏览。
- 短手机／横屏：精简重复计数、减少间隙并允许工作区滚动，保留字号与操作热区；320–430px、短屏、720p–4K 的实际渲染范围由[验证场景](validation-scenarios.md)记录。

各端顶层提供“规则”，包含目标与牌、合法组、首出、重组、百搭和结算计时六章。原创逻辑牌图由代码精确排版，不采用产品截图，不自动启动强制教程。菜单归组倒计时与视频设置，声音图标始终挂载，打开菜单不重建声音组件。

盒子的“进入牌桌”和游戏的“盒子”链接通过平台 `ScreenLink` 更新页面历史并切换内容，保留当前文档；玩家宿主持有的 iframe 同样保持。主动刷新或直达 URL 会重新加载文档，按上述范围恢复草稿。普通入口与刷新压力分别记录，内存测量使用实际链接操作描述普通游玩，保留刷新场景的独立结果。

## 保存反馈与声音

最新保存动作单独显示行动者、公开结果与“已保存”。新提交时已保存桌面的新增牌轻落位、消息短暂亮起；草稿和选取只显示状态，不播放保存动效。减少动态关闭这些装饰，测试模式默认静音。

三种原创本地音分别用于摆牌、摸牌和结算。完整同步、刷新和重连不补播历史；反馈先按实例／分支／修订匹配当前视图并去重。原生主机／公共屏遵循共享声音归属与事件领取，手机提示音须主动启用，且只消费本人动作。暂停、断线、bot 错误和测试模式不播放，不修改日常静音偏好；卸载时停止媒体与迟到播放请求。

本页记录本次实现流程；实际已运行的尺寸、交互、音频解码和同包验收以验证场景及任务记录为准，未运行的项目不视作通过。
