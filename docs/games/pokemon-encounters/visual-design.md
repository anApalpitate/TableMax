# 宝可梦三类布局与有限适配方案

2026-10-28源码试点，覆盖原版与当前扩展 `events-research-v3`。本轮已实施本游戏界面调整，实际通过项、失败轮次与源码SHA以[验证记录](validation-scenarios.md)为准；实体手机、Windows真实DPI与4K电视仍待验。本次不改共享外框、规则、素材或安装器。用户本次确认的设备范围是常规智能手机、电脑及额外的4K电视，允许留白和背景填充，希望减少分辨率组合；下文尺寸、区域预算及断点属于据源码提出的设计参数，不能记为用户指定值。

本页是后续布局设计的唯一入口；[交互](interaction.md)保留现行动作、能力、声画与按日期记录的旧实现约束，[验证场景](validation-scenarios.md)保留历史证据。数值与旧实现不同的地方按本轮实际证据判断，不将旧通过记录升级为新方案通过。通用下限与权限分别引用[通用视觉](../../reference/visual-design.md#三类布局与宽高比适配)、[信息与决策](information-and-decisions.md)。

## 设计依据与改动边界

### 试点实施取舍与经验

- 原版横屏使用稳定DOM及局部 `display: contents` 重排确认、目标、私看和等待项；不复制横屏控制组件，不因旋转更换选择状态的key。扩展私看步骤独占当前决策主体，不重复九格确认。
- 实测普通取牌会使原版／扩展牌阵分别上移56／49px，原因是辅助区在持牌后变矮。普通处理阶段保留对应高度预算，复杂能力仍独立重排；不能用取消稳定断言来接受跳动。
- 选人条居中时可能产生无法滚回的负溢出，采用起点对齐后再逐项滚动检查；事件详情还需展开后量边界，外容器高度不等于可点击summary热区。
- 仅有净区钩子不需要接入平台新布局契约；误加 `three-v1` 标记会改变父框800px边界，已撤回。布局状态与DOM引用分离，避免把ref返回对象传播为渲染数据。
- 原版已将完整动态引导放入按需层；扩展保留原有能力详情，并不存在与原版相同的新手引导引擎。六人54格受字号与首屏约束，优先完整角色与牌名，不为放大插画裁切角色或缩小规则信息。

适用偏好为[三类布局用户意图及管理首屏](../../reference/art-preferences.md#三类布局的用户意图2026-10-23)、[P01–P06](../../reference/art-preferences.md#宝可梦奇遇)：牌桌和角色优先；2／3人卡牌较大，4人对称，6人仍可辨认；主操作易达，说明按需；研究、事件和能力保持各自含义。新方案复用当前结构，只调整区域排列、尺寸约束和按阶段显示的辅助信息。

## 可用区域、最低尺寸与铺屏方式

`W × H`均指游戏在当前页面缩放下实际得到的净CSS区域，正常游戏工具栏与普通内边距仍包含在预算内。测量链固定为“原生／浏览器外窗→iframe视口（无iframe则游戏页面视口）→扣游戏安全区→净区”：`W = 视口宽 − 左右安全区`，`H = 动态视口高 − 上下安全区`。原生标题栏、浏览器工具栏、外框按钮与外框内边距已在形成子视口时扣除，不能再扣一次。游戏自身用padding承接安全区时，测量只减该安全padding一次，不能又把全部padding减去。旋转后重新读取视口和安全区，不能简单交换宽高。物理像素、DPR和CSS像素不等价。

| 布局       | 源码最低净可用区域 | 主要代表区域                        | 结构与上限                                                 |
| ---------- | ------------------ | ----------------------------------- | ---------------------------------------------------------- |
| 管理横屏 H | 1280×720           | 1280×720；1920×1080作放大／填充探针 | 左牌桌右局面栏；内容最多1920×1080，继续扩大时居中填充      |
| 玩家竖屏 P | 360×640            | 360×640、390×844                    | 单列决策区；内容宽360–430，最大高932；更宽／高由背景承接   |
| 玩家横屏 L | 640×360            | 640×360、844×390                    | 左操作右唯一牌阵；内容最大1320×900，桌面仍是同一种玩家布局 |

这些区域已纳入本轮实际源码渲染，逐项结果见验证记录；640×360不据此升级为真实手机证明。更大宽度不能补偿低于最低高度，反之亦然。普通1366×768电脑或720p显示器的窗口化内容可能低于1280×720，须说明可用区域不足并提供最大化／全屏入口；不因标称分辨率在表中就声称该窗口已受支持。用户主动放大使空间不足时沿用平台空间保护及提示，不静默降低字号。

手机游戏内部在横向且 `W >= 640、H >= 360`时采用L；竖向满足 `W >= 360、H >= 640`时采用P。桌面玩家保留父外框现有默认竖屏及手动横竖偏好，不新增“未选择过”状态，也不为此次设计接入新的 `three-v1` 外框契约；内部按实际获配空间排版。选择的模式空间不足时提示切换或提供可用滚动，不擅自改变偏好。角色由授权决定，不能用横竖屏或设备类型推导管理权限。宽高相等且足够时默认P，不新增方屏布局。低于支持区域保留单一纵向滚动访问和全部操作，允许选人条单轴横滚；不保证首屏完整，不静默裁切，不为此另造第四套构图。平板分屏、折叠姿态及任意狭长窗口不列独立优化目标。

**铺满屏幕的是场景底层，可读内容只在规定范围内扩展。** 采用下面的单一策略：

- 场景背景覆盖整个实际视口；宽、高分别填充，不先把整页塞进16:9或9:20的固定框。背景可以 `cover` 裁边、延展纯色／纹理；标题、人物主体、牌值和按钮不能烘焙在可裁切区域。
- 内容区宽取可用宽与本布局最大宽的较小值，高同理；在支持范围内先使用实际宽高分配区域，不用固定设计稿比例计算整体缩放。内容区未用满的横边或上下边用同一主题背景承接，无白色裸边、黑边或重复手机边框。
- 管理2／3人的局部卡阵按自身比例居中；6人及玩家牌阵按文字、编号与剩余空间安排。5人保留3×2席位中的空位，可放无信息的主题纹理，不复制玩家或塞新的常驻面板。
- 原版沿用桌面主题与已核验角色；扩展事件壁纸覆盖游戏页面及游戏内留白，信息区使用稳定高对比底板。iframe外沿用现有桌台背景，不为填充跨iframe同步事件或改共享外框。装饰不参与布局、不接收点击，也不提供秘密目标的视觉线索。不新增图片生成或下载依赖。

## 管理横屏：全桌公开牌阵与局面侧栏

区域排列为“顶部工具栏；下方左牌桌／右局面栏”。工具栏44px起，侧栏原版280px、扩展300px起，宽裕时最多360px；侧栏不得随窗口线性放大挤占六人牌桌。2／3人可适当放大，4人保留2×2和相同紧凑卡片规格，不因少两席就撑大单牌；5／6人使用同一三列两排规格。

| 区域     | 原版                                                         | 扩展                                                                     |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 全桌主区 | 2×3牌位、座号／昵称／胜星；各席公开朝向、配对标记稳定        | 3×3牌位、座号／昵称／胜星；天气有效值／来源角标直接可见                  |
| 侧栏顶部 | 行动者、当前阶段、原分段进度                                 | 行动者、阶段、事件短状态；研究以名称及结果摘要保留入口                   |
| 侧栏中部 | 合法公开牌源、唯一暂持、完整来源名称；卡槽空／有及正背同尺寸 | 牌库／当前配置的弃顶、唯一公开暂持；**不展示玩家缓冲**；旧配置不混入新局 |
| 侧栏底部 | 一条最新权威行动、历史入口、结算后的继续入口                 | 最新权威行动、研究详情、结算继续；事件／研究说明不另挤主桌               |
| 结算     | 六席分数入口留在各席；详细计分按需浮窗                       | 保留54格及各席分数入口；研究达成／失败、授胜与共同赢家不遗漏             |

常规阶段、能力、事件发生时不增加主桌外的多行说明，把非关键详情留在既有浮窗；主桌底线不随暂持空／有、普通保存成功提示或最新行动长短跳动。错误与断线必须即时可见，可用稳定状态区替换普通信息；仍不得遮住牌阵与恢复入口。

720高的预算重点是扩展54格：顶部工具、阶段／事件与边距控制在约110–130px，其余约590–610px分给双排席位，每席约290–300px；扣席头32、内边距及编号后，常规卡面约55–65px高。结算时撤掉已无意义的行动／取牌说明，将阶段结果放侧栏，给每席44px计分入口让位。原版每席仅两行，不能为了两版卡面等高而挤扩展。上述是静态预算区间，实际换行、边框与同时存在的状态必须再量；不靠隐藏牌名或把16px文字压小补差。

2／3人仍以当前高度限制卡阵宽度、保持5:7和原版较大卡片观感；4–6人的紧凑卡壳与编号槽沿用当前结构，角色图 `contain`。支持区域内全桌、状态与结算主要信息一屏完整，主页面和牌桌内部都不以纵向滚动代替适配；详情浮窗可滚动。

## 玩家竖屏：单列决策，按阶段替换辅助区

纵向顺序固定为“工具栏→行动状态→来源／暂持→唯一操作牌阵→选择说明与确认”。原版六格、扩展九格仍完整出现；常驻只保留一次本人或当前获准目标的牌阵。朋友查看和规则走现有浮窗，不追加到主页面。

| 场景             | 来源／暂持区                                                                                                               | 操作牌阵与确认区                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 初翻             | 无取牌需求时不保留空来源面板                                                                                               | 本人完整牌阵；已选格、尚需几格及确认／取消                                                             |

| 暂持处理         | 复用来源所在区域，突出唯一当前牌和来源；隐藏此时不可再取的牌源按钮                                                         | 唯一换入目标阵；确认、可选弃掉／存缓冲及取消同组；强制换入及能力已用状态不隐藏                         |

360×640不能同时堆叠工具44、状态44、来源124、九格220、说明操作88和间隙40（合计660）。因此采用以下**目标预算**，原版六格可取188–200高，余量更大：

| 扩展短竖屏阶段     | 工具 | 独立状态                    | 来源／暂持 | 九格阵 | 说明／操作 | 边距间隙 | 合计 |
| ------------------ | ---- | --------------------------- | ---------- | ------ | ---------- | -------- | ---- |
| 取牌               | 44   | 44                          | 124        | 220    | 44         | 40       | 616  |
| 暂持处理／能力选位 | 44   | 0（并入操作说明或来源标题） | 124        | 220    | 88         | 40       | 616  |

124高的来源区由100高卡槽＋24标题组成；长名称需两行时可增加约20高，总高约636，不能再叠32px事件条、44px研究条或最新行动条。同一阶段中来源空／有、正／背不改变区域高度，隐藏无用空槽也不能让区域塌陷。复杂选人用暂持旁的44px目标条，扩展私看与暂持同时态用两个带明确身份的卡槽横排；研究／事件必要短状态并入既有标题或说明，完整图文按需查看。阶段信息不能因为取消独立行而丢失。确认区需要两行按钮时用完整88高，步骤短语并入来源标题，不额外追加一行。最大同时态需单独量测，预算不足先重排辅助内容，不能把目标底排移出首屏当作通过。

最新行动在玩家端通过历史入口查看，必要的行动者、阶段、错误仍直接可见；这属于拟修改的呈现方式，不改变管理侧栏的最新行动。来源／暂持的空态、背面和正面使用相同用途尺寸；卡面名称完整换行，牌源总标题优先单行。研究／事件保留必要名称、有效值或限制，长说明与插图按需展开；开启完整新手引导时可在独立说明层阅读，主要决策面与关闭入口仍可达，不能自动关闭用户设置。

## 玩家横屏：左侧决策，右侧完整目标阵

工具栏仍在顶部；下方两列。**确认区固定在左列下部**，不再占用右侧九格下方的高度；这是对原版控制区位置的调整，扩展可沿用已有左右骨架并消除绝对定位按钮重叠。阶段切换不重挂iframe、连接或决策状态。

| 下部为确认／弃掉／存缓冲／取消；放不下一排时重排两行，取消在本行最右 | 等待显示本人场地；结算继续用同区域，不追加第二个全桌面板 |

640×360时净区横向预算：外边16＋列间8＋左列约248＋右列约368＝640；右列内边距、卡宽及标题仍由组件分配，不将每张卡撑满列宽。纵向工具44＋外边／间隙16后，工作区约300；右列目标标题24后约276留给牌阵。左列最密选位按“暂持与来源124＋目标条44＋双行操作88＋区域间隙20＝276”安排，余24可处理换行；行动者／步骤并入来源或目标标题，不另叠44px状态行。扩展暂持与私看两张72×100卡并排，含间距可放入248宽左列，不纵向叠两张；私看步骤无需选人时也不保留已经失效的目标条。原版喷火龙则只保留私看卡。

布局按扩展九格阵约220–250、原版六格188–240分配空间；编号至少16px、每个可选格整体热区至少44×44。**44px热区不是内部插画的最小高度，也不能反向证明牌名和角色已可读。** 若最密状态达不到这些目标，先修左列重叠及重复信息，保留实际失败，不宣称640×360已支持。

当前扩展横屏牌阵使用 `min(290px, 100dvh - 190px)`，在页面视口360高且安全区为0时仅170px；新方案要按右列剩余高度分配，不能把旧公式中的视口高直接当作已扣安全区的净高。宽度增加时先扩大两列间距和卡阵至上限；桌面玩家继续同一结构，不增加“电脑版玩家第四布局”。研究投票在横屏用三列简洁选项；私看卡放左列获准区域，并保留实际暂持状态。需要的私看完成、换入或取消不能互相遮挡。

## 缩放、填充与稳定性清单

| 可调整内容                     | 调整方法与停止条件                                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 场景背景、边缘纹理、装饰       | 覆盖全视口、可裁边或填充；不携带操作与必要信息                                                                                       |
| 区域宽度、间距、牌阵容器       | 有限弹性分配；先减装饰与多余间距，再重排／按需详情，不能无限缩小整页                                                                 |
| 角色图片、空态插画、非交互效果 | 等比缩放，保留主体；效果锚定实际授权元素，旋转后重新测量，缺失端点跳过                                                               |
| 管理2／3人卡面                 | 保持5:7，由可用宽与高共同限制；正背等大                                                                                              |
| 密集管理、玩家操作卡面         | 保留紧凑卡壳与稳定编号位置，图片本身不拉伸；牌名完整，配对／天气标记不压住信息                                                       |
| 文字与点击目标                 | 不随局部容器整体 `transform: scale`／`zoom` 缩小；信息≥16、主动作及关键状态≥18、电脑标题≥20 CSS px，交互≥44×44，最终检查实际渲染尺寸 |

卡片尺寸由用途与区域共同决定，不能由正背或有无牌决定；选中边框不改变盒模型。完整牌名、来源、规则数字、错误、强制动作条件和实际研究收益／风险不得为凑一屏删改。非必要动作可以按合法动作不呈现，但不能把仍可执行的关键动作藏进无提示菜单。

桌面沿用[现有DPI及显示倍率机制](../../reference/phase-02-platform-spec.md#电脑多分辨率显示150)：4K电视3840×2160在100%系统缩放时，标准自动适配约为1920×1080的有效工作区；150%系统缩放与页面适配共同作用，避免重复放大。电视没有独立布局或单独业务组件。实体电视观看距离与文字辨识仍需实际确认，DPR 2截图只能证明栅格输出；手机不增加电脑显示设置。

## 精简验收矩阵与实施顺序

**下表是本轮试点的验收范围，执行结果另见验证记录；旧92项记录保持原输入及证据边界，不计入本次新执行。** 不采用“分辨率×人数×全部阶段×倍率”的笛卡尔积。

| 分组     | 固定净CSS区域 | 只在此组重点运行的场景                                                                                                               |
| -------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| H-min    | 1280×720      | 两版6人初翻、普通回合、暂持、最密能力／事件、结算；2／3人各一次5:7及正背稳定，4人一次2×2与同卡规格，5人一次空位／顺序检查            |
| P-min    | 360×640       | 两版全部不同操作结构：取牌、处理、选对手、多格、私看、等待、结果；扩展追加三来源、缓冲强制换入、研究投票、天气及超梦暂持＋私看同时态 |
| P-normal | 390×844       | 两版一组正常取牌到保存流程；扩大后留白、卡面上限及长牌名，不重复全部能力                                                             |
| L-min    | 640×360       | 两版最密目标阵＋左侧确认／双行按钮／选人；扩展暂持与私看同时态、研究投票，验证九格底排与命中                                         |
| L-normal | 844×390       | 两版从P-normal旋转过来，确认选位／缓冲选择／投票草稿与同iframe保留；朋友浮窗、关闭焦点、等待及结算                                   |

固定为**5个主尺寸、两玩法共10个版次×尺寸分组**，每组仍含表内必要场景，不称为“仅10项测试”。8字中文、16字符无空格英文、混合合法昵称及最长牌名放入最密组；不把所有名字与每个分辨率再次交叉。原版2／3人和扩展2／3人结构相似也不能互相代替真实选择器验证。

补充检查只跑指定风险，不重跑全流程：

- **最小尺寸探针**：H的1279×720、1280×719，P的359×640、360×639，L的639×360、640×359，各验证一次降级访问／模式提示；最低尺寸本身已在主矩阵内。将来增加或移动任何断点，补该断点两侧，而非新增全套分辨率矩阵。
- **普通电脑与填充**：1920×1080、1920×1200各一组6人全桌静态密集／结果；1280×720桌面玩家外框各切横竖一次，分别记录外窗、iframe及实际净区，空间不足不能当一屏通过。旧父外框在外窗800px宽附近仍有设备与模式分支，另以799／800／801宽、900高各探一次入口、文档／身份保持及子净区，不重复完整阶段。以后若接入新契约，再单列扣72×16后外窗712×376附近的兼容检查及默认偏好，不混入本次低改动路线。确有超宽屏时只补背景和最大宽度探针，不常设一套21:9阶段矩阵。
- **4K与DPI**：3840×2160真实Windows显示链在100%、150%系统缩放各查标准自动适配及一组6人全桌／结算；补125%一次几何和弹窗检查以保留[当前真人验收范围](validation-scenarios.md#当前真人验收范围)。将界面大小调大，验证空间保护和弹窗可达。至少一次真实4K电视全屏及观看可读性；它与普通4K显示器、浏览器DPR模拟分别记录，不互相冒充。没有电视时保留该未验项。
- **辅助层**：在P-min与L-normal分别检查朋友／规则／计分浮窗一个纵向滚动面、44px入口、关闭／Escape焦点、键盘与触控访问；安全区域／浏览器工具栏变化用一台常规实体手机横竖验证，无需每种型号重复。
- **权限与状态**：用最密组覆盖管理不含私看和玩家缓冲、本人私看与目标授权；选择后旋转／切布局不提交动作、不丢草稿。保存中、失败、断线／重连、暂停、回退各选一个真实受影响决策点；回退清理旧选择，重连不补播。不同独有能力分别覆盖，不因减少尺寸而省掉秘密路径。

每个实际场景至少记录净区域、系统DPI／页面倍率、玩法／角色／人数／阶段、截图及溢出／字号／热区／命中结果。主矩阵要求支持区内必要牌位与当前合法动作完整可达、管理全桌一屏；留白是否有主题承接、图片是否被拉伸、底排与取消是否被遮挡分别判定。失败按[现有预算与定向复验规则](../../reference/validation.md#历史通过率与失败阈值)处理，不通过隐藏错误或放宽首屏断言消账。

实施时先闭合P-min与L-min最密状态及H-min六人结算，再验证放大／填充与物理DPI，最后审阅其他人数；复用现有夹具、操作组件及验证入口，不新建跨游戏适配框架。仅布局变化不导出安装器、不递增版本；实际改UI后按[视觉交付要求](../../reference/visual-design.md#视觉任务交付)提供真实变化展示HTML及临时内容清理入口。本轮实际审阅页与临时清理入口随源码验证交付，路径见本轮验证记录；清理不自动执行。
