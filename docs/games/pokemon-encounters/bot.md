# 三档人机逐决策规格

2026-10-02，维护版本 1.3.0。宝可梦的人机在盒子中可选择“默认”“豆包”“绝悟”，分别对应 `default`、`doubao`、`juewu`。三个名字表示本地策略等级，程序离线运行，不调用同名云端模型或其它游戏服务。三档逐节点策略与真实 Worker 链路已实现，权限、保存和恢复仍遵循 [通用人机规格](../../reference/bot-players.md)。B01 继续采用独立 TypeScript 模块，不引入外部脚本运行、热替换或额外解释器。

统一入口为 [bot/index.ts](../../../games/pokemon-encounters/bot/index.ts)，简单与初步策略在 [strategy.ts](../../../games/pokemon-encounters/bot/strategy.ts)，局势评估在 [evaluation.ts](../../../games/pokemon-encounters/bot/evaluation.ts)，授权记忆在 [memory.ts](../../../games/pokemon-encounters/bot/memory.ts)。策略标识继续使用 `id=pokemon-encounters/basic`、`version=1`，兼容 `tablemax-cn-s19-v1`、状态版本 1 和旧 `memory=null`。输入为本人投影 view、合法 actions、decision ID／seatId、memory、独立 random、signal、difficulty；只返回合法意图及策略数据，平台再次校验／保存。不给完整 RuleContext、数据库、连接、房主凭证、checkpoint 或调试视图。

三档均为确定性策略，不消耗游戏 RNG 或策略 RNG，不依赖时钟／Math.random；等级随座位及 checkpoint 保存，未声明等级的旧存档仍使用默认策略。默认级保留原行为，始终返回 `memory=null`。豆包和绝悟只保留本人合法查看过的暗牌类别；临时查看 UI 权限照常关闭，回退恢复对应边界之前的策略记忆。

## 等级能力与边界

| 等级 | 已实现能力                                                                                                                                                                                 | 判断边界                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 默认 | 优先取牌库、最小暗格；全明时换公开最高固定值；梦幻先选下位，卡比兽不发动，喷火龙选第一个暗格。                                                                                             | 合法、完整、简单且兼容旧存档，不追求最优。                                                                                 |
| 豆包 | 分析己方明牌、授权记忆、新牌与弃顶，保护已配对的列；比较全部换牌／交换／梦幻目标的预期分数，初步评估改变对手分数及翻完最后一张的风险。                                                     | 暗格用未见卡牌的公开数字分布估计，百变怪用邻牌简化估值；不展开全部能力后续或全局组合。                                     |
| 绝悟 | 枚举当前合法候选，用真实计分器共同优化百变怪方向与列消除；评估全部对手、三胜临界与结束风险；展开梦幻转移与换入、火箭队两种币面／全员补位、闪电鸟传递、卡比兽后续交换，估计喷火龙信息价值。 | 在授权信息下为当前局面模型寻找最小预期代价的候选。未知牌及对手未来行为有界近似，不声称暗牌全知、全大局严格最优或保证胜率。 |

绝悟每次建立 32 组无放回的卡牌类别假设，减去公开场地牌、本人记住的暗牌、已摸牌和可见弃顶。每个概率维度使用固定置换的 32 个等宽积分区间，覆盖完整概率范围，不读取牌库、未知弃牌或他人暗牌的实际内容／排列。空牌库重洗时把已知弃顶纳入可抽类别；火箭队补位仍使用未知卡牌池的局势模型，不模拟未公开的实际洗牌序列。

候选通常最多 24 个梦幻目标、6 个换入格、15 个交换，能力只展开到本次效果完整完成。取得牌／抽到牌会按公开后的类别分组，再对一组未知局面共同选后续动作，不分别按每个未观察暗牌假设采取全知动作。闪电鸟对手选位使用其当时明牌和收到牌的初步策略，不提前使用被采样的暗牌值。完整场地计分缓存上限 20,000 项。

评分以己方预期总分为基础，兼顾对手最低分、翻牌进度和对手接近全明的风险。效果完成且任一场地全明时，以小局获胜／落败为主要判断；对手已有两胜时提高失败代价，同分按真实规则算共同胜利，负数配对仍清零。权重是项目策略参数，不是官方规则，也不会为推进偷偷切回默认级。

## 记忆与计算预算

豆包／绝悟的普通数据为 `{version:1, roundNumber, seatId, cards:[categoryId|null ×6]}`。只记录本人喷火龙合法看过且仍在暗格的类别，没有实例 ID、他人暗牌、牌库序列或管理信息。自身交换时记忆随牌移动，自身换入以及他人梦幻／火箭队的公开替换清除相应暗格记忆；换小局或换座位全部失效。已公开牌不再重复作为暗格记忆扣减未见池。`validateMemory` 验证字段、格数、类别与数量，并兼容旧 `null`；默认级接受合法高级记忆后仍返回 `null`。

正式 Worker 的旧代堆限制 32 MiB，调度器两秒截止可终止同步计算，各候选及期望汇总检查 signal。预算与动作失败不会扩大授权、越过保存流程或触发静默降级。

策略任务键 `gameInstance/decisionId/seat/branch/revision/strategyVersion`；初始 choicesBySeat 可包含多个人机，逐座位调度；同键只调度一次，结果进入统一去重事务。暂停／回退／结束取消旧任务，迟到结果按键拒绝。输入只有该座位投影，日志仅节点／结果状态，禁打印视图中的秘密字段。缺少策略、异常或非法返回：停止推进、显示人机行动失败、保留待选，不无限重试／偷偷 fallback；房主可暂停、结束或恢复，不默认改真人控制。

存档包含 strategyId／version／difficulty／memory 和策略 RNG 数据；同 checkpoint 恢复等级、输入与观察记忆，撤销分支信息不留到新分支。版本不兼容保留原文件并拒绝加载，更换策略仍需明确兼容，不在恢复中默默改变版本或等级。第四阶段模板的“合法首选”和“非法／延迟／异常”测试策略继续验证同链路，不为真实策略放宽授权。

## 当前验证

[策略专项](../../../games/pokemon-encounters/bot/strategy.test.ts) 有 12 项测试，覆盖明确弃顶收益、差牌丢弃、列消除、可选交换、百变怪联合最优、跨座位梦幻、获胜终局与对手第三胜风险、授权 peek 利用和移动／公开替换／小局失效、空库、取消、积分区间、输入隔离和计算预算。三档各在 2–5 座位完成固定种子三胜大局，共 12 个大局；逐动作重新校验状态和合法参数，每档全部 12 个玩家阶段均实际出现，单局少于 2,000 步，没有高级人机长期丢牌而无法结束的现象。

五座位、弃顶梦幻的 draw／mew-other 已在实际独立 32 MiB Worker 内完成，测试设两秒硬截止并检查合法结果和记忆；当前机器约 0.2 秒，完成后的 `heapUsed` 约 10 MiB，不把它写成内存峰值或其它机器的时延承诺。既有默认策略的 20 个人数／种子大局继续由 rules.test.ts 覆盖，recovery.test.ts 继续检查受限输入、混合局与 D01–D13 恢复，Worker 异常与版本替换复用平台专项。全工程使用 `pnpm check`，实际混合局和最终便携验证见 [验收记录](../../reference/acceptance.md)。
