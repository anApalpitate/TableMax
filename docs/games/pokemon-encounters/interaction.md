# 交互与动效规格

采用 [规则](rules.md) 及 [状态／决策](information-and-decisions.md)，通用启动、网卡、加入、重名、关闭加入、暂停、换绑及恢复见 [平台规格](../../reference/phase-02-platform-spec.md)。独立原型 URL `/prototype.html?game=pokemon-encounters`，React／TypeScript、锁定 Vite、合成授权视图；不连接真实服务、秘密状态或存档。普通主机合并公共屏与房主管理，手机仅本人合法选择。角色切换仅审阅，不构成认证。

## 流程与页面

1. 通用启动选择可达地址；网络设置／端口／存档错误有草图。大厅真人扫码取得座位，重名提示允许继续，真人加电脑 2–5；房主可关闭新加入、开局前调整顺序、添加／移除电脑。全部准备方可开始，大局不换座／控制者。
2. 六张布局固定上排三格、下排三格。手机初始选一格，确认保存后显示一明五暗并等待其他人；主机显示完成数不代选；全员后进入正常摸牌。
3. 正常手机在本人卡位附近显示牌库／弃顶来源，空弃牌禁用；公开新摸牌单独暂持显示。普通牌选择换位或合法直接弃；触控先选、再提交，取消本地选择不改状态。
4. 梦幻在对方场地选位，再回本人场地选位；火箭队先显示已保存币面再选位，同位全员弃出后补齐；闪电鸟显示接牌队列，接牌者本人选位，其他人等待。卡比兽点两格交换或不发动；喷火龙选己方暗牌、临时仅本人查看并确认关闭；百变怪无主动弹窗。
5. 中间有人六张全明仍显示“能力处理中”，完成全部效果后才揭示／解析计分。结果按各列贡献、百变怪采用数字、总分、共同赢家及胜局显示；未达三胜房主开始下一局，达阈值显示共同整局赢家和新大局入口。
6. 真人掉线／暂停禁提交并清选择，不代操作；重连先同步授权和未确认动作结果。房主历史选择具体 before 边界、揭示提醒、保存新分支后同步；旧选择／动画废弃。换绑房主确认、原凭证失效；重启恢复包括能力中间状态，不提前结算。

## 布局与所有操作

公共主机 1920×1080：顶部回合／行动者／胜局，中部各玩家独立 2×3 场地，旁边公开牌堆数量、弃顶及可展开弃牌；底部紧凑进度与安全历史，管理在折叠区。普通公共投影只有牌背，未展示暗牌真实值或实例 ID。手机 360／390 CSS px：本人身份、短状态、公开新牌、主要操作与本人 2×3 卡位；对手卡位在必要目标流程或折叠公共区，不等比缩小大屏。所有触控目标至少 44 px，长昵称换行／截断结合完整可访问名称，安全区使用 env 留白，固定操作区不遮卡位。

| 场景 | 手机操作／等待反馈 | 主机展示 |
| --- | --- | --- |
| 初始／普通来源／替换／弃 | 选择格或来源→提交，已保存后再变牌面；合法弃牌单独按钮 | 当前行动者、公开新牌、初始化完成数 |
| 梦幻两步 | 阶段标题说明当前选他人／己方，合法对手座位与格号 | 两次替换进度，接收牌公开；未完成不结算 |
| 火箭队两面 | 先看币面再选格，皮卡丘全员补位过程禁额外选择 | 币面、同位弃底与补位进度、完整结束 |
| 闪电鸟 | 当前接牌者本人选格；其余等待，保持正常回合标记 | 来源／当前接牌者／剩余队列，最后弃底 |
| 卡比兽／喷火龙 | 两格交换／放弃；己方暗牌查看／放弃／确认关闭 | 安全能力进度，不显示 peek 值 |
| 结算／共同赢家 | 列贡献、总分、百变怪解析、胜局 | 全员公开结果；未达三胜下一局由房主开始 |
| bot | 当前电脑行动／暂停／失败状态，只展示已保存结果 | 大厅标电脑、全部节点调度状态；不代真人 |

## 提交与失效反馈

选择：仅高亮，不显示成功。提交中：禁重复按钮／重选，旧牌仍保留。保存后确认：更新授权牌面／阶段并清空选择。拒绝：安全原因，按最新视图重选，不增加历史。未收到确认：结果未知，等待同步而非假定失败；同步后根据动作结果继续。任何角色／阶段／分支／身份改变立即清本地选择与临时查看；过期迟到确认不能重新激活动画。

能力的下一玩家选择与正常回合是不同等待原因，不能显示对方手机号或凭证。管理授权在服务端，屏幕看到管理按钮不授予玩家管理权；普通大屏可以显示管理控件，与游戏秘密权限无关。

## 动效契约

| 事件 | 保存后触发／节奏 | 结束状态和失效清理 |
| --- | --- | --- |
| 本地选择 | 100 ms 边框／轻微位移，无牌值揭示 | 尚未保存，取消即清；减少动态仅边框 |
| 保存翻牌 | 180 ms 卡片淡入／轻微翻转，不渲染未授权背后纹理 | 保持最终投影；提交中无翻牌，拒绝不翻 |
| 换入／传递／补位 | 220 ms 新公开牌进入与卡位强调，按已保存进度顺序展示 | 不阻塞下一选择；远端缺失事件直接完整同步，不补播历史 |
| 能力／等待阶段 | 160 ms 透明度过渡，短进度文字 | 不遮触控，不用加载动画冒充持久化成功 |
| 结算 | 240 ms 结果出现，先显示已保存完整结果 | 允许立即操作下一局；不逐格等待动画才计算 |
| 回退／重连／重启 | 不播放历史移牌／音效，立即替换完整授权视图 | 清所有旧动画及 peek；本地选择不沿旧分支继续 |

使用 CSS／Web Animations 的一次性效果，不加入循环晃动。`prefers-reduced-motion:reduce` 关闭移动、翻转和过渡但保留状态反馈。上表为第五阶段目标节奏。当前低保真原型仅实现保存后场地／结果 220 ms 淡入与位移，动态验证采集实际动画时长／运行状态、保存触发及同步清除旧动画；其他翻牌／传递细节尚未制作，不将静态截图当作完整动效验证。第五阶段实现事件投影驱动，第六阶段检查实机触控、刷新、横竖屏和自然观感。调试字段与修改另行专项，不伪装为审阅工具或当前已实现功能。
