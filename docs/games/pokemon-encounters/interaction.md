# 交互与动效规格

## 当前视觉审查后的补充行为（2026-10-04）

初始进度使用座位标签，与牌位编号分开；进度为白色斜纹矩形条，当前步骤暖金、完成步骤青绿，仍是只读进度而非操作按钮。摸牌堆采用蓝色底座、弃牌堆采用暖金底座，并保留名称、数量与合法取牌提示。未取牌的暂持区使用紧凑图标与状态，有牌后突出公开待处理牌。最近保存行动在公共屏居中收敛宽度，行动者、操作、牌名和公开位置分开排版，详细记录按需展开；常驻状态不再用中点拼接重复文字。

常规六人公共屏采用三列两排，牌阵按实际剩余高度缩放并缩小玩家间空隙；六人结算另为两排计分按钮预留高度，二人结算放大各自卡牌和分数。手机连接状态使用清楚的浅底深字，本人状态与星标紧凑排列，星标维持至少 28px；测试模式标记收紧且连接文字可收缩，避免窄手机顶栏横向溢出，完整连接状态保留在可访问文本和标题。重复提示合并到选择确认区。360×640 竖屏以当前六卡牌阵、合法选择及确认全部位于首屏为验证目标；取牌、弃牌／换入、梦幻两步、卡比兽、喷火龙等按阶段核验，不以隐藏底排或缩小触控面积规避溢出。梦幻对手入口居中，多人入口保持可点且完整姓名保留在可访问文本及标题。确认、取消和一键意图在短手机中共用一排；更小视口和辅助浮窗仍允许必要滚动，横屏保留左右分区。未选完仍不可提交。

2026-10-04 共用倒计时验证暴露了高 Windows DPI 的既有短桌面断点缺口：701–1000 CSS px 宽、最多 600px 高时，六席卡宽的容器高度计算可能归零。该窗口组合改为六席一行，每席仍保留两行三列卡牌、独立星标及完整号位；收束外框和状态留白，角色图保留实际显示空间，结果按钮至少 44px。常规桌面与手机布局保持；绘制、结算及无遮挡证据关联到本轮 [验收记录](../../reference/acceptance.md)。

保存成功后，普通取牌／换入／弃牌增加短暂连接轨迹与落点亮光，梦幻使用念力轨迹，卡比兽使用双向交换弧线，闪电鸟使用电流，火箭队同位补牌使用有界局部冲击。轨迹只测量同一牌桌中已渲染的授权组件，缺失、隐藏或屏外端点跳过，不复制暗牌牌值。胜局增加赢家牌阵扫光和新增星标闪亮，原赢家横幅保持可读。喷火龙关闭按钮在私密牌面上方，火焰及私看位置仍只在本人投影出现；能力提示和币面不遮挡主要操作。暂停、回退、重连与减少动态沿用原失效／清理边界，测试模式不播放装饰；特效不接收触控、不改变规则、合法目标或秘密投影。独立逐图提示与核验范围见 [验证场景](validation-scenarios.md#当前界面的独立视觉审查)。

采用 [规则](rules.md) 及 [状态／决策](information-and-decisions.md)，通用启动、网卡、加入、重名、关闭加入、暂停及恢复见 [平台规格](../../reference/phase-02-platform-spec.md)。独立原型 URL `/prototype.html?game=pokemon-encounters`，React／TypeScript、锁定 Vite、合成授权视图；不连接真实服务、秘密状态或存档。普通主机合并公共屏与房主管理，手机仅本人合法选择。角色切换仅审阅，不构成认证。正式 UI 已在 games/pokemon-encounters/ui 与 apps/web/src/game-clients/PokemonScreen.tsx 接入真实服务，场景在 ui/table.tsx，下面的行为已实现，验证见 [验收记录](../../reference/acceptance.md)。

## 1.6.0：行动面板与声画反馈

行动面板左侧突出当前行动者和动作，中间分段横进度表示完成状态，右侧独立摆放待处理牌及牌堆。首翻显示已完成人数，普通回合显示取牌／处理／能力步骤，闪电鸟显示接牌传递进度；不是倒计时。最新已保存行动降为次级信息，历史在浮窗查看。

待处理牌标明玩家、来源及未入场状态，使用独立底座与边框；换入强调真实公开落点，弃掉明确到弃牌堆。合法牌堆使用沿边框移动的虚线提示，弃掉当前牌有独立明显按钮；左上文字提高对比度。选中与最新目标边框仅围卡面，位置编号在独立底部区域。各人的初始选牌按稳定决策 token 保持，别人首翻不清本人的选择；回退／暂停等关闭旧窗口。

只使用公开信息标记可确定的零分列：同数值相抵和 −2／+2 均包含。暗牌或未确定的百变怪不提前标记；全场公开后按计分函数确定，结算永远以权威分数为准。

声音默认开启，公共游戏窗口优先、关闭后交回管理员；手机静音，手动静音保存。一个有限播放器与有界队列，按保存事件去重，连续相同币面仍可触发。刷新、重连、回退不补播；退出清理资源。减少动态隐藏移动和烟花、保留静态状态，效果不接收触控、不阻挡下一操作。资源及核验边界见 [声音记录](assets.md#权限动画和声音)。

## 流程与页面

1. 电脑只运行服务、房主管理和公共展示，不占玩家座位。每位真人各自用手机扫码入座和准备，重名允许继续，手机真人加人机共 2–6；盒子呈现围桌席位、空座、手机状态与人机等级。房主可关闭新加入、开局前调整顺序、添加／移除及配置默认／豆包／绝悟人机。全部准备方可开始，大局不换座／控制者；原班回到大厅可重新配置。
2. 六张布局固定上排三格、下排三格。手机初始选一格，用“翻开位置”确认保存后显示一明五暗并等待其他人；主机显示完成数不代选；全员后进入正常摸牌。
3. 正常手机在本人卡位附近显示牌库／弃顶来源，空弃牌禁用；公开新摸牌单独暂持显示。普通牌选择换位或合法直接弃；取牌、弃掉暂持牌、跳过能力及关闭查看一键提交；卡位触控先选、用具体动作按钮确认，取消本地选择不改状态。
4. 梦幻在对方场地选位，再回本人场地选位；火箭队先显示已保存币面再选位，同位全员弃出后补齐；闪电鸟显示接牌队列，接牌者本人选位，其他人等待。卡比兽点两格交换或不发动；喷火龙选己方暗牌、临时仅本人查看并确认关闭；百变怪无主动弹窗。
5. 中间有人六张全明仍显示“能力处理中”，完成全部效果后才揭示／解析计分。结果默认展示赢家、胜局、总分和列贡献，百变怪解析路径按需展开；未达三胜房主开始下一局，达阈值显示共同整局赢家和新大局入口。
6. 真人掉线／暂停禁提交并清选择，不代操作；重连先同步授权和未确认动作结果。房主历史选择具体 before 边界、揭示提醒、保存新分支后同步；旧选择／动画废弃。1.6.0 已删除换手机；重启恢复包括能力中间状态，不提前结算。

## 布局与所有操作

公共主机 1920×1080：对局顶部回合／行动者／胜局，结果以赢家横幅和全员场地／总分为主，中部各玩家独立 2×3 场地，旁边公开牌堆数量、弃顶及浮层查看弃牌；底部紧凑进度与安全历史，管理和公开记录在牌桌菜单；教学在线下完成，正式菜单不设规则帮助。独立 `/game` 页面占满窗口，无大厅宣传区／邀请侧栏；两到六人场地随可用宽度分布，六人桌面采用三列两排，返回盒子不修改对局。普通公共投影只有牌背，未展示暗牌真实值或实例 ID。手机 360／390 CSS px：本人身份、短状态、公开新牌、主要操作与本人 2×3 卡位；对手卡位在必要目标流程或折叠公共区，不等比缩小大屏。所有触控目标至少 44 px，长昵称换行／截断结合完整可访问名称，长牌名用省略显示、可访问文本与桌面悬停仍保留完整名称／能力，安全区使用 env 留白，随内容的粘性确认区不遮卡位；只有位置选择显示该区，等待和取牌时不保留空确认按钮。

## 提交与失效反馈

选择：仅高亮，不显示成功。提交中：禁重复按钮／重选，旧牌仍保留。保存后确认：更新授权牌面／阶段并清空选择。拒绝：安全原因，按最新视图重选，不增加历史。未收到确认：结果未知，等待同步而非假定失败；同步后根据动作结果继续。任何角色／阶段／分支／身份改变立即清本地选择与临时查看；过期迟到确认不能重新激活动画。

能力的下一玩家选择与正常回合是不同等待原因，不能显示对方手机号或凭证。管理授权在服务端，屏幕看到管理按钮不授予玩家管理权；普通大屏可以显示管理控件，与游戏秘密权限无关。

## 动效契约

| 事件             | 保存后触发／节奏                                    | 结束状态和失效清理                                   |
| ---------------- | --------------------------------------------------- | ---------------------------------------------------- |
| 本地选择         | 120 ms 边框／轻微位移，无牌值揭示                   | 尚未保存，取消即清；减少动态仅边框                   |
| 保存翻牌         | 320 ms 卡片翻转，不渲染未授权背后纹理               | 保持最终投影；提交中无翻牌，拒绝不翻                 |
| 换入／传递／补位 | 220 ms 新公开牌进入与卡位强调，按已保存进度顺序展示 | 不阻塞下一选择；远端缺失事件直接完整同步，不补播历史 |
| 能力／等待阶段   | 220 ms 阶段标题轻微位移，短进度文字                 | 不遮触控，不用加载动画冒充持久化成功                 |
| 结算             | 240 ms 结果出现，先显示已保存完整结果               | 允许立即操作下一局；不逐格等待动画才计算             |
| 回退／重连／重启 | 不播放历史移牌／音效，立即替换完整授权视图          | 清所有旧动画及 peek；本地选择不沿旧分支继续          |

使用 CSS／Web Animations 的一次性效果。`prefers-reduced-motion:reduce` 关闭移动、翻转和过渡但保留状态反馈。正式 UI 以新保存反馈驱动翻牌 320 ms、发牌 360 ms，公开暂持牌、换入和阶段标题 220 ms 一次性动效；结果为 240 ms。公开币面保存后增加 950 ms 翻转及 1200 ms 屏幕抛掷；1.4.0 在 1200 ms 后统一清理，暂停／回退／断开立即清理。思考点仅为等待状态的轻微透明度变化，减少动态或测试模式关闭。设备走查显式测试 no-preference 与 reduce；记录实际 animationstart 和 computedStyle，不从静态截图推断动画。手机确认栏随内容排布并粘在安全区上方；下排／目标格被选择后保持中心不被按钮覆盖。当前 Windows 上检查宽度、触控、声音解码／播放调用、恢复清理与截图观感，手机和电视按用户授权模拟；未声称真实手机浏览器或现场听音验收。调试字段与修改另行专项，不伪装为审阅工具或当前已实现功能。

## 游玩节奏、行动播报与六人布局（1.4.0）

实际游玩模式在人机行动前留出思考时间，画面标明当前人机“正在思考”；测试模式快速调度，不播放动效和声音，但仍显示真实授权结果。模式由房主通过隐蔽快捷键配置，不改变暗牌权限或随机源，规则教学继续在线下完成。运行模式的入口、启动与保存行为见 [通用规格](../../reference/phase-02-platform-spec.md#实际游玩与测试模式140)。

最新操作固定放在牌桌上部，卡牌／能力图、行动者昵称、具体动词及公开目标位置共同说明发生了什么；最近操作通过浮窗复查。最近操作在特效结束后仍可见，直至新的保存动作替代。原有“特殊能力发动”改为具体能力和行动者，公开目标卡位持续有边框标记；喷火龙仅播查看者和能力，不公开所看格号或暗牌。安全 action 元数据随既有公开事件保存，旧存档没有该字段时按安全文字展示，重连／回退只恢复静态记录、不补播历史特效。

参考 [三国杀官方工坊的询问与目标选择说明](https://diy.sanguosha.com/course/)，采用行动提示与目标位置分区、必要位置确认的原则；持续行动条和卡图播报是本项目设计，不声称照搬该游戏的完整日志实现。小局胜数只显示三颗放大五角星，已获胜星亮色、未获胜星灰色，并保留可访问胜数；结算总分仍是规则结果。主要状态与提示至少 14px，行动标题至少 17px，操作按钮至少 44px。

六人电脑牌桌采用三列两行，卡面仍有独立名称、分值和插画区域；结算的昵称、星标和可点击总分各占独立列，三列贡献和百变怪路径在“计分明细”浮窗查看，Escape／关闭回到原按钮。手机只展现本人的操作区，对手场地在目标选择及朋友牌桌浮窗查看。对局的成功确认整合到最新已保存行动区，重复的“已保存”单行不再占用牌桌高度，错误和待确认消息继续可见。六人、长昵称、三端状态和多尺寸的实际渲染另见验收，不以仅扩大上限作为 UI 已验收。

1.5.0 电脑端通过 [显示设置](../../reference/phase-02-platform-spec.md#电脑多分辨率显示150) 适配至 3840×2160，六人场地、卡名、最新操作、星标与浮窗随页面放大；手机维持独立操作布局。1280×720 或放大后等效短屏的电脑场景收紧顶部提示、场地与空白，暂停／读档提示出现时进一步收紧间距，保留恢复按钮、全部卡位、三列两行和可读卡面。工具栏标题可裁切，完整名称仍在可访问文本。显示调整不提交规则动作或改变当前选择。

## 视觉排布维护（1.0.2）

卡面用右上分值／左上能力标记、中部完整角色插画、下方名称三个独立区域；位置编号在牌外，不覆盖名称。名称至少 12 CSS px；完整名称与能力仍留在可访问文本及卡面 title。未知格始终使用同一背面。牌堆标签与等待信息保持 12px；空弃牌有与实体牌相同的占位比例。

两人／三人场地集中于桌面中央，避免横向散开；五人默认窗口收紧场地和卡位间距，平板改为分行。手机状态区与公开牌堆并列，本人场地按可用高度缩放，短屏可自然滚动；横屏将状态／确认放在左侧、卡位放在右侧，紧凑身份信息仍保留给辅助技术。菜单、弃牌历史和朋友场地在浮层中查看。

梦幻选对手时只展示一个当前目标场地，座位按钮可切换；切换即清除本地选位，不发游戏命令。选位后仍以具体动作确认，完成后按真实阶段回本人场地，不额外增加规则步骤。公共弃牌历史使用原生 dialog，支持 Escape 及关闭按钮，打开／关闭不改游戏修订。全部弃牌仍仅来自公共投影，未向主机或手机扩大信息权限。

保存翻牌用 320ms 翻转，换入／传递用 220ms 进入，下一小局发牌用 360ms 进入；阶段 220ms、结果 240ms、硬币 480ms、胜局徽章 380ms。翻牌／发牌类型只比较前后授权投影的 faceUp 和小局号，未使用暗牌实例。仍只在对应新保存反馈到达后触发，520ms 清理，暂停、分支变化、断开立即清理；刷新、同步和回退不补播。减少动态同时关闭新旧动效。
