# 第二阶段通用交互与交接规格

2026-10-01。状态：通用流程与低保真原型已建立，具体游戏规则关口未通过。本页是用户已确认的设计输入；不会把初始工程验证页面写成已实现的平台产品。规则研究状态见 [核验记录](../tasks/phase-02-rule-research.md)，阶段范围见 [第二阶段任务](../tasks/phase-02-rules-and-interaction.md)。

## 原型入口与边界

```powershell
pnpm prototype:dev
pnpm prototype:build
pnpm prototype:preview
pnpm prototype:verify
```

开发入口为 `http://127.0.0.1:5174/prototype.html`；构建预览为 `http://127.0.0.1:4174/prototype.html`。构建和验证证据在 `artifacts/phase-02/`，源码在 `apps/web/src/prototype/`。复用项目 React／TypeScript／Vite／Playwright，独立配置没有服务代理或真实通信，正式桌面构建继续只使用原来的网页入口。

顶部“角色／页面”和底部“走查工具”用于设计审阅，不是产品界面。示例地址、人数、昵称、修订、分支、历史标签、绑定代数与 A／B 选项均是合成数据，不对应真实对局。游戏区没有完整秘密状态、隐藏牌映射、卡牌数据、身份凭证或真实 checkpoint；页面重载清空本地示例，不实现持久化恢复。切换角色不代表真实授权验证。

原型可验证点击路径、反馈与视图展示；不能验证服务端权限、可靠提交、实际身份替换、存档或游戏规则。实际后台逻辑、网络检查和适用 AC 测试必须由后续阶段完成。

## 使用流程与明确取舍

| 流程           | 操作与反馈                                                                                       | 后续实现责任                                             |
| -------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 启动           | 服务就绪后展示网卡地址、端口、运行状态；选择手机可达网卡。二维码不替代 Wi-Fi 连接                | 第三阶段；当前工程端口占用停止启动，不新增自动换端口承诺 |
| 创建与加入     | 房主创建单房间，公共屏显示加入入口；手机使用自带扫码工具进入系统浏览器，输入昵称取得独立座位     | 第三阶段；实际人数上限取游戏清单，不采用原型示例人数     |
| 重名           | 提示已有同名玩家，仍允许加入；各端用昵称加座位身份区分                                           | 已选便利项，第三阶段实现                                 |
| 关闭加入       | 房主可关闭新身份加入；不阻止有效已有身份恢复                                                     | 第三阶段                                                 |
| 满员           | 拒绝分配超额座位，说明房间已满；不把失败连接加入有效玩家列表                                     | 第三阶段；规则人数核验后补满员原型                       |
| 入座与准备     | 手机明确本人座位和准备状态；房主仅在开局前调整顺序，座位身份与玩家绑定不改变                     | 第三阶段；真实开局条件待规则核验                         |
| 房主参与       | 管理界面与本人手机界面分开；房主取得普通玩家身份后按玩家授权参与                                 | 第三阶段；两种身份凭证独立                               |
| 暂停与掉线     | 显示暂停／等待原因；当前行动玩家掉线不代操作、不超时罚；暂停禁止推进动作，允许查询已授权公共内容 | 第三、四阶段                                             |

| 回退           | 房主选有效历史目标，界面明确“恢复到该决策之前”；显示揭示信息提醒，确认后保存并同步               | 第四阶段；目标须对应真实游戏声明的决策边界               |

| 重启恢复       | 房主看到未结束存档入口；恢复后显示等待重连，身份有效时恢复原座位；地址改变重新生成二维码         | 第四阶段                                                 |

| 关闭与退出     | 关闭公共屏保留服务；退出整个程序停止服务，已确认状态恢复要求仍生效                               | 第三、四阶段；桌面生命周期遵循现有架构                   |

连接帮助覆盖：同网段、错误网卡、私人网络防火墙、访客网络／设备隔离、地址变化与在系统浏览器打开。原型使用示例地址，不更改系统网络、防火墙或路由器。

手机常用操作放在本人信息附近，等待原因保持可见；公共信息可单独查询，不把公共屏布局等比缩小。公共屏强调布局、阶段、行动者和结果；房主管理强调操作后果，投屏入口不包含管理凭证。具体游戏牌面与卡位在原文核验后设计。

## 信息权限与动作边界

| 信息／动作                                   | 服务端                 | 公共屏             | 本人手机                 | 其他玩家       | 房主管理                              |
| -------------------------------------------- | ---------------------- | ------------------ | ------------------------ | -------------- | ------------------------------------- |
| 游戏全部状态、牌库顺序、随机状态、checkpoint | 可保存／执行           | 不下发             | 不下发                   | 不下发         | 不下发                                |
| 规则定义的公共状态与安全历史                 | 按规则投影             | 可看               | 可查询                   | 可查询         | 可看                                  |
| 玩家秘密与临时查看                           | 按已核验规则授权       | 不下发             | 仅本人获授权的字段与时机 | 无权部分不下发 | 管理权不授予额外秘密                  |
| 座位身份、昵称与准备                         | 权威记录               | 可展示公共部分     | 可看本人／公共部分       | 可看公共部分   | 可管理准备前顺序                      |
| 房主凭证、玩家凭证                           | 服务端验证             | 不持有、不放二维码 | 只持有本人凭证           | 不持有他人凭证 | 独立房主凭证，不进入公开 URL          |
| 合法游戏动作                                 | 绑定真实身份，游戏校验 | 无操作权           | 本人合法动作             | 不得代提交     | 以独立玩家身份执行本人动作            |
| 暂停、恢复、回退、结束、重绑定               | 校验管理权             | 仅接收安全结果     | 接收对应反馈             | 接收对应反馈   | 可执行管理动作                        |
| 诊断与存档位置                               | 保存必要信息           | 不展示内部数据     | 安全错误原因             | 安全错误原因   | 可查看必要诊断，不包含秘密 checkpoint |

游戏权限矩阵仍需按真实阶段和每类字段补齐；“本人信息区”不是永久查看暗牌的授权。公开错误只表达越权、阶段过期、分支过期、状态需同步等安全原因，不说明未知牌值、秘密目标或隐藏能力是否存在。

平台管理动作和本地 UI 行为不冒充游戏决策；翻页、放大、打开帮助不创建游戏 checkpoint。换绑不修改游戏座位状态，不增添任意改牌或改分入口。

## 提交、回退与恢复语义

| 客户端状态     | 反馈与允许行为                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 尚未提交       | 从最新授权视图取得合法选择；允许本地取消，未改变权威状态                                                         |
| 提交中         | 禁止重复发起新动作；动画不表示成功                                                                               |
| 保存并确认     | 服务端事务保存后确认；展示确认结果与最新视图，清空已完成选择                                                     |
| 明确拒绝       | 展示安全原因；同步需要更新的状态后重新选择，拒绝不产生游戏决策点                                                 |
| 确认丢失／断线 | 结果未知，不显示成功或默认失败；保留未确认动作标识供查结果／同编号重试，完整同步前不允许新动作                   |
| 重新同步       | 服务端给出当前分支与授权完整视图及未确认动作结果；清除旧选择。身份、分支或阶段变化时不得将旧意图转换成新动作重试 |

原型的“模拟完整同步”只展示清空反馈，未判断未确认动作是否已经执行；其文字和测试不构成可靠交付验证。

回退必须记录游戏声明的决策前状态与安全标签。恢复状态包括公共／秘密游戏数据、当前阶段、行动顺序、待处理选择、牌位置、牌库／弃牌顺序、得分、已生成结果及随机源状态。身份、授权、当前连接与地址不恢复成过去；平台修订和分支递增。作废分支的动作、请求、选择、待播放动画失效。

涉及信息揭示时提示“已有信息可能被看见”，不要求全员同意，也不一律拒绝回退。恢复对应 checkpoint 和随机状态，重新选择相同动作应得到该边界对应的结果；不暗中洗牌。哪些操作原子完成、哪些抽取后仍需选择，必须依据游戏原文逐项声明，尚未确定。

保存确认、回退保存和自动推进必须形成一致决策边界；一次恢复先保存新有效分支，再发布授权视图。存档需分别记录平台格式、游戏、规则和状态版本，未通过兼容检查不得加载。完整 checkpoint 不进入前端日志、公开历史或管理标签。
