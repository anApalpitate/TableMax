# 第二阶段通用交互与交接规格

2026-10-01。状态：通用流程与三端美术原型已建立，具体游戏规则关口未通过。本页是用户已确认的设计输入；不会把初始工程验证页面写成已实现的平台产品。规则研究状态见 [规则来源与核验缺口](../tasks/phase-02-rules-and-interaction.md#规则来源与核验缺口)，阶段范围见 [第二阶段任务](../tasks/phase-02-rules-and-interaction.md)。

## 原型入口与边界

源码在 `apps/web/src/prototype/`，独立入口为 `apps/web/prototype.html`。执行 `pnpm prototype:dev` 进行审阅；构建后再预览或自动走查，完整命令、Electron 前提、端口和证据路径见 [开发环境与验证](development.md)。复用项目 React／TypeScript／Vite／Playwright，独立配置没有服务代理或真实通信，正式桌面构建继续只使用原来的网页入口。

右上“审阅工具”默认关闭，角色／页面切换、模拟反馈、异常类型及工程说明集中在抽屉内，用于设计审阅，不是产品界面。原型保持“演示”标记；启动页的示例网卡选择位于默认关闭的“网络设置”。示例地址、人数、昵称、修订、分支、历史标签、绑定代数与 A／B 选项均是合成数据，不对应真实对局。游戏区没有完整秘密状态、隐藏牌映射、卡牌数据、身份凭证或真实 checkpoint；页面重载清空本地示例，不实现持久化恢复。切换角色不代表真实授权验证。

| 审阅页面 | 原型已有内容 | 规则或实现缺口 |
| --- | --- | --- |
| 启动与网络 | 示例网卡选择、端口与连接帮助 | 真实服务、网卡检测和网络可达性属于第三阶段 |
| 大厅与准备 | 加入、重名提示、关闭加入、准备和座位排序 | 用户已确认本人手机选翻牌、禁偷看且等全员完成，原型尚未加入；开局按钮保持规则待核验，人数与满员仍待确认 |
| 会话 | 等待、提交各状态、暂停、回退、换绑与声音控件 | A／B 是反馈示例，游戏布局、合法动作、待处理选择均待规则 |
| 结束 | 结束原因及房主主动结束确认 | 无分数占位，正常结算、平局与新局初始化待规则 |
| 恢复 | 示例未结束记录、恢复及等待重连反馈 | 无真实存档读取、身份恢复或状态还原 |
| 错误 | 网络不可达、端口占用、存档失败／损坏／不兼容草图 | 无真实诊断、文件保留或兼容检查 |

原型可验证点击路径、反馈与视图展示；不能验证服务端权限、可靠提交、实际身份替换、存档或游戏规则。实际后台逻辑、网络检查和适用 AC 测试必须由后续阶段完成。

用户答复新增的游戏交互输入、默认顺序和剩余边界统一见[用户已确认与项目约定](../tasks/phase-02-rules-and-interaction.md#用户已确认与项目约定)：六张两行三列、一明五暗，首次翻牌由本人手机选择；洗牌与默认起始采用用户授权方式。普通取牌为牌库顶／最新弃牌顶，牌库抽牌可直接弃掉且不用翻暗牌；替换可选己方明／暗牌，换入朝上，换出暗牌翻开置顶。S14 新图补充了能力和分值，但逐牌触发差异、特殊传递及百变怪结算仍待追问。独立计分模块已列为游戏规则层要求，当前没有计分源码或真实选牌流程。

## 公共大屏兼房主管理与调试模式

2026-10-01 用户明确公共大屏与房主管理采用同一界面，并增加调试模式，可查看更多信息和执行额外修改。采用理由、旧方案及落地状态见[界面决策 002](../decisions/002-host-public-screen-and-debug.md)。正常模式使用公开游戏信息和房主操作区，手机按本人玩家权限操作；服务端继续校验每类动作授权。合并主机界面可展开全部弃牌，手机只显示顶牌。

调试开关及模式状态须明确展示。可查看哪些秘密字段、可修改哪些数据／阶段、是否直接在大屏展示，以及调试修改如何形成历史和恢复边界，目前未确定，按[规则确认清单](../tasks/phase-02-rules-and-interaction.md#规则确认清单) Q23 接续。最终确认后另列调试投影及动作清单，不从“查看更多”推导任意改牌、身份或凭证修改。

正式工程和独立原型目前仍保留三个角色入口与不同布局，尚未合并或提供调试能力。旧角色切换与模拟异常抽屉用于原型审阅，不能视作产品调试模式。以下矩阵描述普通模式的逻辑授权，公共与管理两列在未来由同一主机界面承载；调试例外待确认后单列。

| -------------------------------------------- | ---------------------- | ------------------ | ------------------------ | -------------- | ------------------------------------- |

| 规则定义的公共状态与安全历史                 | 按规则投影             | 可看               | 可查询                   | 可查询         | 可看                                  |
| 玩家秘密与临时查看                           | 按已核验规则授权       | 不下发             | 仅本人获授权的字段与时机 | 无权部分不下发 | 管理权不授予额外秘密                  |
| 座位身份、昵称与准备                         | 权威记录               | 可展示公共部分     | 可看本人／公共部分       | 可看公共部分   | 可管理开局前顺序                      |

游戏权限矩阵仍需按真实阶段和每类字段补齐；“本人信息区”不是永久查看暗牌的授权。公开错误只表达越权、阶段过期、分支过期、状态需同步等安全原因，不说明未知牌值、秘密目标或隐藏能力是否存在。

平台管理动作和本地 UI 行为不冒充游戏决策；翻页、放大、打开帮助不创建游戏 checkpoint。换绑保留游戏座位状态；调试修改使用另行确认的动作定义，历史和恢复语义按 Q23 补齐。

## 提交、回退与恢复语义

| 客户端状态     | 反馈与允许行为                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 尚未提交       | 从最新授权视图取得合法选择；允许本地取消，未改变权威状态                                                         |
| 提交中         | 禁止重复发起新动作；动画不表示成功                                                                               |
| 保存并确认     | 服务端事务保存后确认；展示确认结果与最新视图，清空已完成选择                                                     |
| 明确拒绝       | 展示安全原因；同步需要更新的状态后重新选择，拒绝不产生游戏决策点                                                 |
| 确认丢失／断线 | 结果未知，不显示成功或默认失败；保留未确认动作标识供查结果／同编号重试，完整同步前不允许新动作                   |
| 重新同步       | 服务端给出当前分支与授权完整视图及未确认动作结果；清除旧选择。身份、分支或阶段变化时不得将旧意图转换成新动作重试 |

原型的“模拟完整同步”只展示清空反馈，未判断未确认动作是否已经执行；其文字和测试不构成可靠交付验证。原型角色切换也会清除本地选择和提示，避免审阅时沿用上一角色状态；正式产品须根据真实身份及服务端投影完成隔离。

回退必须记录游戏声明的决策前状态与安全标签。恢复状态包括公共／秘密游戏数据、当前阶段、行动顺序、待处理选择、牌位置、牌库／弃牌顺序、得分、已生成结果及随机源状态。身份、授权、当前连接与地址不恢复成过去；平台修订和分支递增。作废分支的动作、请求、选择、待播放动画失效。

涉及信息揭示时提示“已有信息可能被看见”，不要求全员同意，也不一律拒绝回退。恢复对应 checkpoint 和随机状态，重新选择相同动作应得到该边界对应的结果；不暗中洗牌。哪些操作原子完成、哪些抽取后仍需选择，必须依据游戏原文逐项声明，尚未确定。

保存确认、回退保存和自动推进必须形成一致决策边界；一次恢复先保存新有效分支，再发布授权视图。存档需分别记录平台格式、游戏、规则和状态版本，未通过兼容检查不得加载。完整 checkpoint 不进入前端日志、公开历史或管理标签。

## 已确认的美术方向与三端布局

2026-10-01 用户确认并要求实施“明亮的桌游主机”，三端统一、先做独立原型。选择奶油纸底、鲜明色块、圆润木质玩具插画，增加封面、头像和场景，替换大标题加说明面板的网页构图。它保留平台简洁现代的基线，同时适合朋友聚会及后续不同游戏主题。正式工程验证入口尚未换装，协议、游戏 SDK、服务端权威与授权边界未改变。

参考：[Playnite](https://playnite.link/) 的图像识别入口与全屏模式、[Big Box 官方图库](https://www.launchbox-app.com/download) 的盒绘与主题布局、[Jackbox 美术记录](https://www.jackboxgames.com/blog/behind-the-scenes-of-pp10-art) 的原创角色与场景，以及 [Jackbox 加入流程](https://www.jackboxgames.com/how-to-play) 的主屏／手机分工。借鉴的是视觉层级与交互分工，不引入在线加入服务、商城、手柄支持或新游戏规则。

### 视觉规范

- 奶油白 `#F6F2E8`、深灰 `#25343A`、青绿 `#247C75`、暖黄 `#F4BE45`、珊瑚橙 `#E77A60`。青绿承担主操作，暖色承担装饰；状态还配文字及符号，不只靠颜色表达。
- 8px 间距基准、24px 主容器圆角、柔和阴影；字体沿用本机 Segoe UI／微软雅黑，不新增联网字体。功能图标为统一线宽的本地 SVG，按钮与触控目标至少 44px；焦点边框可见，减少动态效果设置关闭过渡。
- 平台插画使用原创骰子、棋子、卡片、筹码及动物玩具；封面“桌边奇遇”为平台示意，实际游戏名在可控文字层显示。它不是宝可梦组件、实际棋盘或规则证据。
- 常态说明压缩到短句；连接步骤与实现说明收进帮助及审阅抽屉。回退揭示提醒、换绑后果、结束确认和保存失败原因仍保留。服务确认与视觉反馈的关系沿用本页语义。

最终 16 张素材在 `apps/web/src/prototype/assets/`，总计 877,318 字节。封面最长边 800px，头像／装饰／状态插画最长边 640px；背景保持生成尺寸。按比例缩放、WebP quality 86 压缩，保留透明通道。提示词、版本、日期及用途在同目录 `manifest.json`；原始 PNG、透明度／尺寸／哈希检查及奶油底联系表保存在 `artifacts/phase-02/art-reset/`，Git 忽略但文件树可见。通过模块引用及原型 CSS 引入资源，正式构建不包含这些素材。

imagegen 用于平台位图插画；SVG 功能图标、二维码、规则数字和关键文字由代码精确生成或排版。当前原型不生成可用二维码，只保留明显的加入入口示意；真实二维码由后续服务流程产生。游戏卡面、卡背与角色资源仍需核验对应版本资料，并按游戏命名空间独立整理。

只有公共屏播放：操作确认、行动切换和结算按新的服务端事件触发；播放失败或静音不阻断游戏。手势激活、静音入口及事件消费位置独立于游戏规则。完整同步不生成历史音效，刷新、重连、回退不重播；手机无声音控件。最终打包检查字体、图片、脚本、帮助和音频全部本地加载。
