## 原型入口与边界

源码在 `apps/web/src/prototype/`，独立入口为 `apps/web/prototype.html`。执行 `pnpm prototype:dev` 进行审阅；构建后再预览或自动走查，完整命令、Electron 前提、端口和证据路径见 [开发环境与验证](development.md)。复用项目 React／TypeScript／Vite／Playwright，独立配置没有服务代理或真实通信，正式桌面构建使用独立正式网页入口。

右上“审阅工具”默认关闭，角色／页面切换、模拟反馈、异常类型及工程说明集中在抽屉内，用于设计审阅，不是产品界面。原型保持“演示”标记；启动页的示例网卡选择位于默认关闭的“网络设置”。示例地址、人数、昵称、修订、分支、历史标签、绑定代数与 A／B 选项均是合成数据，不对应真实对局。游戏区没有完整秘密状态、隐藏牌映射、卡牌数据、身份凭证或真实 checkpoint；页面重载清空本地示例，不实现持久化恢复。切换角色不代表真实授权验证。

## 聚会连接、连续游玩与运行保障

2026-10-02 用户授权，1.2.0 实现。玩法教学在线下进行，本轮不新增游戏内教程或规则帮助。

- 手机加入／换绑在请求前保存随机请求密钥与原内容；8 秒未取得有效确认时保留原请求，可手动重试，刷新和重新回到前台会恢复确认。相同密钥不得改写请求内容，服务端串行处理并与座位变更同事务保存加密回复；成功确认可在 24 小时内跨服务重启恢复，不再次分配座位或消耗绑定码。玩家凭证仍由服务端随机生成，只存摘要；加密回复只能用对应手机保留的密钥取回，不能用它恢复已撤销身份。密钥过期／身份撤销有明确提示，由房主检查原座位后换绑。
- 一次性换绑码的摘要、座位和两分钟期限随事务保存；服务重启不重置期限，保存失败不消耗码。丢失兑换回复后重试原请求可以确认已成功结果，即使此时两分钟的兑换期限已过。新手机取得原座位，旧凭证失效。
- 地址接口与二维码校验实时读取网卡，展示网卡名称；优先常规 IPv4，保留虚拟／VPN 和自动配置地址的手动选择。主机记住选择，每十秒及回到前台刷新，地址失效时重选并更新二维码；同一个 Wi-Fi 是否互通仍取决于防火墙和设备隔离，不把本机读取网卡写成手机可达检测。连接帮助按打不开网页／无法入座分步排障。
- 大局结束或房主结束后，“再玩一局”保存全新游戏实例，保留原顺序、昵称、真人手机凭证及电脑座位；真人重新准备，电脑保持准备，全部满足条件后房主开局。小局／胜局、随机、策略记忆和有效回退历史重新初始化，旧实例意图不能作用于新局。另提供需明确确认的“清空牌桌”，才移除全部座位和手机身份。过去实例保留在 SQLite journal，不在本轮增加查询界面。
- 回退记录显示小局、有效步骤编号、行动玩家或管理步骤，可筛选并分批查看。旧存档缺少补充上下文时标记历史步骤，不推测玩家。确认说明撤销范围及已看信息，恢复后仍同步全端并暂停。
- 电脑服务运行期间防止自动休眠，可见且未最小化的公共屏防止屏幕自动休眠；公共屏关闭后服务继续，程序退出释放保护。手动休眠、关机不由此阻止；系统恢复以及手机 online／pageshow／回到前台时重新连接或同步本人授权投影。重复启动同一数据目录回到已有实例；只关闭房主窗口且公共屏还在时，可从原生“程序”菜单恢复管理窗口。
- 启动失败弹窗与 desktop.log 保留具体服务原因，中文区分端口占用、版本不兼容、损坏存档、目录不可写／路径无效及超时。原生菜单提供日志目录入口，不自动删除存档、改防火墙或替用户切换数据目录。

实现与模拟边界见 [工程结构](architecture.md)、[验证命令](development.md#聚会可靠性维护验证120) 与 [本轮验收](acceptance.md#首版维护聚会可靠性与连续游玩)。

## 公共大屏兼房主管理与调试模式

2026-10-01 用户明确公共大屏与房主管理采用同一界面，并增加调试模式，可查看更多信息和执行额外修改。采用理由、旧方案及落地状态见[界面决策 002](../decisions/002-host-public-screen-and-debug.md)。正常模式使用公开游戏信息和房主操作区，手机按本人玩家权限操作；服务端继续校验每类动作授权。合并主机界面可展开全部弃牌，手机只显示顶牌。

用户随后要求调试模式后续独立规划，面向盒子内所有游戏尽可能支持纠错、撤回和恢复。长期目标统一见[需求第 6.5 节](../requirements/TableMax_需求文档_v1.0.md#65-跨游戏调试与纠错后续独立规划)。字段、修改动作、投屏显示、历史与恢复细节留待专项，本轮停止逐项追问调试权限；普通游戏权限与决策点回退继续按既有要求定义。

正式工程保留三种身份，各自有盒子与独立游戏入口。通用原型保留三角色供对照，游戏专属原型已合并公共主机与管理；正式主机已兼管理，尚未提供调试能力。旧角色切换与模拟异常抽屉用于原型审阅，不能视作产品调试模式。以下矩阵描述普通模式的逻辑授权，公共与管理两列现由同一主机界面承载；调试例外待确认后单列。

## 盒子与独立牌桌

2026-10-01 用户增补，1.0.1 已落地。`/host`、`/public`、`/player` 承载盒子、加入与准备；各自 `/game` 子路由承载游戏。开局广播使已连接的盒子进入对应牌桌；既有对局从盒子“进入牌桌”，刷新子路由直接恢复授权状态。回到盒子、前进／后退只改变页面，连接和座位继续保持；切换身份重新建立对应凭证的会话，不把房主授权带进玩家操作。

游戏使用窗口全宽和至少一屏高度，仅留紧凑工具栏、提交反馈和必要暂停提示。电脑展示公共场地，手机突出本人 2×3 场地；记录、换手机和牌桌管理在有焦点约束、Escape 可关闭的菜单，对手场地按需查看。教学在线下完成，正式界面不设规则帮助。游戏内没有常驻邀请二维码、宣传标题或侧栏。可调用浏览器全屏；局域网浏览器不提供该能力时仍铺满可用视口。新公共窗口根据当前阶段打开盒子或游戏页。

单步意图直接点桌游组件或明确动作按钮，不先“选择按钮”再确认；卡位与两格交换仍先选后确认，确认文案说明实际动作，选中后才出现取消。暂停、断线、回退和身份失效清除旧选择／查看；已保存才改变牌面和播放动效，未收到确认时仍用原动作编号重试。此调整只改变交互，不修改规则、自动准备或代替真人。

代码职责为 `session/useRoomSession.ts`（连接／授权同步／可靠提交）、`navigation.ts`（角色与页面）、`screens`（盒子和牌桌外壳）、`components`（平台控件）。首版场景和选择留在 `games/pokemon-encounters/ui`；正式资源在共享目录，原型继续独立引用。

首版逐阶段、逐字段的授权依据见 [游戏权限矩阵](../games/pokemon-encounters/information-and-decisions.md#逐字段授权矩阵)，包括公开摸牌、主机全弃牌、本人临时查看和结算揭示。公开投影仍不包含牌库未来顺序或未授权暗牌。

bot 的逻辑角色等同于该座位的普通玩家，运行位置在本地服务端不代表策略可获得服务端完整状态。策略调用只传安全授权视图与合法选择，调试模式也不扩展策略输入；管理动作与策略调用分开，bot 不代真人操作。

“本人信息区”不是永久查看暗牌的授权。公开错误只表达越权、阶段过期、分支过期、状态需同步等安全原因，不说明未知牌值、秘密目标或隐藏能力是否存在。

平台管理动作和本地 UI 行为不冒充游戏决策；翻页、放大、打开帮助不创建游戏 checkpoint。换绑保留游戏座位状态；调试修改的动作、历史及恢复语义由后续专项定义，不作为当前规则问答关口。

| 尚未提交       | 从最新授权视图取得合法选择；允许本地取消，未改变权威状态                                                         |
| 提交中         | 禁止重复发起新动作；动画不表示成功                                                                               |
| 保存并确认     | 服务端事务保存后确认；展示确认结果与最新视图，清空已完成选择                                                     |
| 明确拒绝       | 展示安全原因；同步需要更新的状态后重新选择，拒绝不产生游戏决策点                                                 |
| 确认丢失／断线 | 结果未知，不显示成功或默认失败；保留未确认动作标识供查结果／同编号重试，完整同步前不允许新动作                   |
| 重新同步       | 服务端给出当前分支与授权完整视图及未确认动作结果；清除旧选择。身份、分支或阶段变化时不得将旧意图转换成新动作重试 |

原型的“模拟完整同步”只展示清空反馈，未判断未确认动作是否已经执行；其文字和测试不构成可靠交付验证。原型角色切换也会清除本地选择和提示，避免审阅时沿用上一角色状态；正式产品须根据真实身份及服务端投影完成隔离。

回退必须记录游戏声明的决策前状态与安全标签。恢复状态包括公共／秘密游戏数据、当前阶段、行动顺序、待处理选择、牌位置、牌库／弃牌顺序、得分、已生成结果及随机源状态。身份、授权、当前连接与地址不恢复成过去；平台修订和分支递增。作废分支的动作、请求、选择、待播放动画失效。

涉及信息揭示时提示“已有信息可能被看见”，不要求全员同意，也不一律拒绝回退。恢复对应 checkpoint 和随机状态，不暗中洗牌或重投硬币。一次选择及其确定性变化／自动推进共同保存，再等待下一选择；首版复合能力、已生成结果与中间恢复字段按 [D01–D13 决策边界](../games/pokemon-encounters/information-and-decisions.md#每项决策与恢复边界) 实现。

保存确认、回退保存和自动推进必须形成一致决策边界；一次恢复先保存新有效分支，再发布授权视图。存档需分别记录平台格式、游戏、规则和状态版本，未通过兼容检查不得加载。完整 checkpoint 不进入前端日志、公开历史或管理标签。

## 已确认的美术方向与三端布局

### 手机聚会与围桌房间（2026-10-02）

所有真人各自扫码使用手机，电脑只运行服务、房主管理和公共信息展示，管理界面没有本人玩家区、初始翻牌或取牌按钮。房主本人参赛时也拿手机领取普通身份。公共屏继续只读，公开画面和手机私密操作保持不同投影；人机是本地服务控制的玩家座位，不指操作电脑的房主。

盒子使用明亮游戏大厅式房间：中央为实体感桌面，固定最多五个围桌席位；已加入玩家依次上桌，空位显示“空座”，按实际座位顺序编号。头像、昵称、人机等级、手机在线／离线和准备状态在各自座位附近；本人的手机席位突出。桌面／公共屏以桌子和席位为主要视觉，手机保留紧凑围桌场景、自己的准备操作和入座表单，长昵称不挤压其他座位。座位设置放在独立按需展开区域，避免桌上叠加管理菜单。

房主在盒子选择默认／豆包／绝悟并添加人机，已入座人机可以在座位设置更改等级；开始后禁改，原班回到大厅可再配。等级公开显示，内部思考与授权记忆不下发。真人只用自己的手机准备和游戏选择；电脑开始按钮等待真实玩家准备，不自动替他们准备或操作。具体等级能力见 [人机规格](bot-players.md#三档智能与配置)。教学在线下完成，正式盒子／游戏菜单不设规则帮助；连接与管理排障提示继续保留。

桌面尺寸 1080×800、1366×768、1920×1080 与手机 390×844、360×640、横屏分别检查真实渲染；围桌席位、昵称、状态和主要按钮不得重叠、遮挡或横向溢出。新增风格只作用于盒子房间，不改游戏规则、牌桌私密布局或单一房间范围。

| P16／AC-23         | 接入或替换独立电脑决策文件，检查模板及版本不兼容恢复               | 策略与规则分离，版本可检查，整局和恢复场景可复查                           | 第四阶段模板真实接入已验证，宝可梦与产品验收仍属第五、六阶段                             |

上表的“待实现／未实施”是第二阶段原型交接时的记录，保留其历史范围；当前正式产品对应结果以 [验收记录](acceptance.md) 为准，用户已授权电视／手机模拟，不再要求本轮取得其他设备。
