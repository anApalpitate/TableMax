## 浏览器入座、换机与外部连接（2026-10-07）

本次最新授权允许真人用手机或电脑浏览器进入玩家页面，并恢复由电脑管理员批准的换机接续；本节覆盖旧“真人仅用手机”及“删除换手机”的当前约定。以下记录已接入源码的行为，实际界面、交付包及设备验证边界仍见 [验收记录](acceptance.md)，不替代历史完成结论。

- **玩家入口与权限**：支持扫码与直接打开网站两种方案。二维码下方提供“打开网站”，目标为同一份当前局域网或已保存外部根网址；主机／公共屏点击后用系统浏览器打开普通玩家页，浏览器页面以独立标签打开。连接帮助列出两种方式和可复制的当前地址，旧 `/player` 仍兼容。进入对局使用 `/player/game`，均只取得本人玩家投影。管理员与只读公共屏保持 `/host`、`/public` 及各自 `/game` 路由；管理员不占座位，电脑浏览器玩家不因设备或网址取得管理或原生桥接权限。根地址直接呈现玩家盒子，不重定向到管理页面；同源玩家子文档允许根地址及旧玩家路径，管理、公共和 API 文档仍禁止嵌入。被指定的真人玩家房主沿用既有权限，不增加换机批准或网络设置权限。
- **玩家视窗**：2026-10-08 最新批准方案：电脑玩家首次采用中央竖屏，可用区域外右上角按钮切换横屏，浏览器独立保存 portrait/wide；外层不足800px暂时回退移动布局，扩大后恢复选择。桌面检测只影响展示，触屏Windows仍为电脑，手机与桌面UA的iPad不显示该按钮。不增加服务端接口或存档字段。通用外框以稳定的同源子文档承载玩家页面，窗口变化不重挂载会话或游戏草稿；只有玩家文档允许同源嵌入，管理／公共文档禁止嵌入，子文档不获得原生管理桥接。具体视觉见[通用视觉](visual-design.md#电脑浏览器玩家的手机区域2026-10-08)。
- **连接确认**：Socket.IO 优先建立 HTTP polling，再尝试升级 WebSocket。`room:sync` 支持回调确认 `{ok:true,view}`，保留无回调时发送 `room:view` 的兼容方式；连接、`online`、`pageshow` 及回到前台时确认本人投影，前台每 10 秒再同步。单次确认超时为 5 秒，超时或传输失效自动重连。恢复同步期间锁定动作，不能将 Socket 已连接当成状态已同步；过期身份撤销本人连接。陈旧实例、分支、修订及旧连接回复不能覆盖较新的投影，恢复不补播旧动效；未确认动作保留原编号并在身份与同步有效后重试。
- **换机接续**：新设备进入盒子后选择“换手机进入”，选原真人座位，保存独立随机请求密钥后申请。新页显示六位核对码；仅电脑管理员看到待批准申请，在管理浮窗核对座位与码后批准或拒绝。申请有效期 5 分钟，可取消及用原密钥重试；普通玩家、玩家房主与公共屏不能批准。批准事务保存新凭证摘要并撤销旧凭证和连接，保留座位 ID、昵称、头像、顺序、准备、游戏数据与已有房主授权，不暂停或代替本人做游戏动作。批准后的加密收据可凭原请求密钥在 24 小时内跨重启恢复，相同请求不增加座位；请求密钥和新凭证不明文写入存档。后续换机或移除座位使旧收据失效；身份、换机结果和房主管理授权均不随 checkpoint 回退恢复。
- **外部二维码**：电脑管理员在“连接帮助”填写 HTTP(S) 网站根地址、带端口的根地址或旧 `/player` 地址，保存后归一为 `origin`，局域网与外部二维码均使用根地址，公共屏接收 `room:network` 更新。旧设置文件读取时只在内存规范为根地址，不自动改写；显式保存才更新文件。HTTP(S) 域名/IP 与端口均可用；拒绝登录信息、查询参数、fragment、其他协议与路径前缀，如 `/tablemax/player`。配置仅改变邀请地址，不改变服务监听端口、管理员来源或玩家身份；不自动采用 `X-Forwarded-Host`。外部映射需转发网页、资源、`/api` 和 `/socket.io`，同时支持 polling／WebSocket；根域 HTTP(S) 与 TCP 域名加端口两种樱花入口见 [官方说明](https://doc.natfrp.com/app/http.html)。
- **配置与缓存**：独立 `network-settings.json` 位于当前数据目录，原子保存 `externalJoinUrl`；与房间及 checkpoint 分离，重启保留，保存失败保持旧值，损坏原文件保留并提示，明确修复时另存原件备份。`GET /api/room/network` 提供当前配置，带管理员凭证的 `POST` 保存；公开二维码和“打开网站”只使用已保存外部地址或当前有效网卡地址，无凭证／原生管理参数。无 LAN 网卡仍可显示外部二维码，清空外部入口切回 LAN；二维码与 API 不缓存，修改网址后重新加载二维码并同步按钮目标。实际地址放在连接帮助，二维码下保留简洁按钮；公共屏只读。

原浏览器身份仍按同源 localStorage 恢复；改变域名、协议或端口形成新浏览器源，需通过换机接续领取原座位。局域网游玩及正式游戏资源继续离线可用，穿透软件和外部网络由玩家自行准备；本机 HTTP／HTTPS 代理回归不等同于现场 FRP、樱花、公网受信任证书或实体手机验收。

## 盒子头像选择与游戏介绍（2026-10-04）

2026-10-04 用户要求完善盒子，本节保存当前头像与介绍行为。设计前查询 [用户美术偏好](art-preferences.md)，本次适用 S01 的图像优先与统一头像风格、S08 的减少小字与信息堆积，以及 S09 的头像选择和游戏特异介绍。以下维护长期行为，不代替验收记录中的实际检查和交付包状态。

- 头像预设目录共 26 个：保留原有 `avatar-1` 至 `avatar-6`，新增 20 个 imagegen 头像 `avatar-7` 至 `avatar-26`，沿用现有明亮、圆润的动物桌游玩具风。图片全部本地打包；头像数量不代表游戏人数上限。
- 玩家在入座前可预选空闲头像，尚未入座的本地选择不占用资源。服务端按串行保存结果先到先得，入座或本人更换成功后才占用；同时争抢同一头像只允许先确认者成功，其他请求明确返回已被选择并保持原状态。相同入座请求重试须保留原昵称与头像，不因确认丢失重复入座。
- 选择器显示头像、可辨认名称和“已被选择”状态，被其他座位占用的头像不可点击；本人当前头像独立标记。人机自动分配未占用头像，与真人共享唯一性约束。
- 已入座真人只可更换本人头像，允许在盒子的大厅（`lobby`）或结束（`ended`）状态操作；进行中（`playing`，含暂停）锁定。头像以稳定 `avatarId` 随座位保存并公开投影，排序、离线、刷新／重连、重启恢复、原班续局和兼容游戏切换均保留。离线不会释放，移除座位或清空牌桌才释放；成功更换则释放旧头像。头像是平台身份资料，游戏 checkpoint 回退不恢复旧头像。
- 手机入座前及已入座后支持选择 JPG／PNG／WebP 原图（至多 10 MiB），预览中拖动、缩放，确认后提交 256×256 PNG；取消保持原头像。服务端检查尺寸、CRC、解压上限并重新编码，以规范化 PNG 的 SHA-256 生成 `custom-<hash>` ID。自定义图片可重复使用；26 个预设继续独占，换成上传图片后释放原预设。
- 自定义 PNG 保存到 `room.sqlite` 的独立 `avatar_images` 表，座位和历史仅引用 ID；图片、身份、请求确认和房间记录同一事务保存，失败全部回滚。入座重试保留请求编号和图片；本人更换走带凭证及动作信封的独立 HTTP 接口，仅图片相关请求提高大小限额。当前头像引用缺失或哈希不符时保护原存档并拒绝恢复。
- 旧存档缺少 `avatarId` 时，按原六头像的座位映射优先选择空闲项，再按目录顺序补齐，保存稳定 ID；已有明确的头像归属保留，重复预设或非法 ID 按损坏存档保护处理。格式 1 存档继续兼容读取。正式界面按 `avatarId` 读取图片，不再按座位顺序实时生成头像。
- 盒子标题以封面与游戏名为主，移除“电脑 · 管理员与公共展示”等重复角色小字。当前操作和必要连接／身份反馈继续可读，辅助说明不抢主视觉。
- “玩法”打开所选游戏的介绍浮窗，用核心步骤和胜利目标概述玩法。宝可梦介绍六牌初始翻牌、取牌换牌与能力、同列配对降分和三胜目标；现代艺术介绍出画拍卖、竞价收藏、行情结算和四轮资金目标。通用设备操作说明不作为游戏玩法介绍，不主动扩展对局内教程。

介绍内容分别保存于 [宝可梦 introduction.ts](../../games/pokemon-encounters/ui/introduction.ts) 和 [现代艺术 introduction.ts](../../games/modern-art/ui/introduction.ts)。平台 [轻量介绍装配](../../apps/web/src/game-clients/introductions.ts) 只按游戏 ID 组合核心文案和展示图标，不导入对应游戏主界面、规则或重资源；盒子继续保持目录／小封面先加载，游戏主体按进入牌桌加载的边界。新增游戏在自身目录维护介绍，共享层只负责组装。

## 1.6.0：游戏选择、手机房主与独立提交

2026-10-02 用户确认。此节记录 1.6.0 当轮对下文历史原型中固定游戏、电脑房主独占控制与旧换手机设计的替代；原型和早期阶段表保留为历史范围，不作为当前入口。当轮协议为 6，当前浏览器玩家与换机行为以 [最新连接增补](#浏览器入座换机与外部连接2026-10-07) 为准。

- 新房间先显示游戏库；目录仅含已接入的正式游戏，小封面可立即显示。选中后才加载规则、策略、游戏界面、样式与主体资源；旧存档按原游戏恢复。1.6.0 当轮只有宝可梦完整游戏，模板仅用于内部验证；当前正式目录另含现代艺术和电力公司。
- “切换游戏”始终可打开游戏库，只有管理员可确认切换；进行中明确确认结束当前游戏并切换。不兼容人数或人机等级说明原因并提供座位调整入口，不自动删人。先检查兼容并完成目标加载，再将旧局结束记录和新大厅同一事务保存；失败保留原对局。成功保留身份、顺序、头像和房主，清除真人准备及策略记忆，产生新实例。
- 电脑管理员指定／撤销／更换一位真人手机房主。手机房主可开局、下一小局、再玩一局及暂停／恢复，也可移除其他真人、人机及修改人机昵称；不能移除自己。结束、切换、清空和指定房主仍仅管理员执行，公共屏只读。授权持久化、续局保留，管理员移除房主同时撤权，游戏回退不恢复旧授权。
- 大厅直接移除；结束后移除与新准备大厅同一次保存，保留其他身份、顺序和头像，真人重新准备，旧局 journal 保留但当前入口退出旧结果和回退。进行中保留座位管理入口，移除和人机改名提示先结束；人机昵称 1–24 字且允许重名，昵称与头像均在 checkpoint 之外。外层紧凑操作条按阶段提供开始、暂停／恢复、再玩、结束和清空，次要管理按需展开。
- 删除常驻扫码说明、二维码下方地址及重复身份说明，地址移入连接帮助。开局条件用人数与准备两枚图标徽章，提供状态和可访问标签。座位普通操作使用青绿、移除使用浅珊瑚，长昵称和手机窄屏重排。
- 1.6.0 当轮删除旧换手机、绑定码、兑换入口及提示，旧存档 bindings 可兼容读取后丢弃。同设备同源刷新、断线恢复与入座确认重试继续保留；2026-10-07 的新换机流程见 [最新连接增补](#浏览器入座换机与外部连接2026-10-07)，不恢复旧兑换接口。
- 初始翻牌各座位有稳定决策编号，服务仅允许明确独立的并发组在仍有效窗口提交。准备按座位检查，不能用旧准备覆盖已取消。暂停／恢复／换局／回退关闭旧窗口；同人不同格双击及其他冲突拒绝并同步。别人的独立首翻不清本人本地选择。
- 显示设置按钮使用统一图标／文字居中，连接帮助将地址、刷新及状态按统一高度和间距排列。声音默认开启，公共游戏屏优先，关闭后交回管理员；宝可梦与电力公司手机静音，现代艺术手机的独立本地声音见其规格。手动静音保存，刷新／重连／回退不补播，测试与减少动态提供静态表现。

游戏行动面板与声画见 [1.6.0 游戏交互](../games/pokemon-encounters/interaction.md#160行动面板与声画反馈)，契约和选择理由见 [决策 007](../decisions/007-library-owner-and-concurrency.md)。

## 原型入口与边界

源码在 `apps/web/src/prototype/`，独立入口为 `apps/web/prototype.html`。执行 `pnpm prototype:dev` 进行审阅；构建后再预览或自动走查，完整命令、共享 WebView2／原生构建前提、端口和证据路径见 [开发环境与验证](development.md)。复用项目 React／TypeScript／Vite／Playwright，独立配置没有服务代理或真实通信，正式桌面构建使用独立正式网页入口。

右上“审阅工具”默认关闭，角色／页面切换、模拟反馈、异常类型及工程说明集中在抽屉内，用于设计审阅，不是产品界面。原型保持“演示”标记；启动页的示例网卡选择位于默认关闭的“网络设置”。示例地址、人数、昵称、修订、分支、历史标签、绑定代数与 A／B 选项均是合成数据，不对应真实对局。游戏区没有完整秘密状态、隐藏牌映射、卡牌数据、身份凭证或真实 checkpoint；页面重载清空本地示例，不实现持久化恢复。切换角色不代表真实授权验证。

## 聚会连接、连续游玩与运行保障

2026-10-02 用户授权，1.2.0 实现。本次 2026-10-04 用户已要求各游戏规则说明，按 [通用视觉](visual-design.md#顶层图文规则说明)与游戏主题维护；连接、连续游玩行为如下。

- 玩家加入在请求前保存随机请求密钥与原内容；8 秒未取得有效确认时保留原请求，可手动重试，刷新和回到前台恢复确认。相同密钥不得改写内容，服务串行处理并与座位变更同事务保存加密回复；成功确认可在 24 小时内跨服务重启恢复，不再次分配座位。玩家凭证只存摘要；密钥过期／身份撤销明确提示。1.6.0 删除旧换绑与兑换，2026-10-07 新授权的换机接续独立维护，见 [最新连接增补](#浏览器入座换机与外部连接2026-10-07)。
- 地址接口与二维码校验实时读取网卡，展示网卡名称；优先常规 IPv4，保留虚拟／VPN 和自动配置地址的手动选择。主机记住选择，每十秒及回到前台刷新，地址失效时重选并更新二维码；同一个 Wi-Fi 是否互通仍取决于防火墙和设备隔离，不把本机读取网卡写成手机可达检测。连接帮助按打不开网页／无法入座分步排障。
- 大局结束或房主结束后，“再玩一局”保存全新游戏实例，保留原顺序、昵称、真人手机凭证及电脑座位；真人重新准备，电脑保持准备，全部满足条件后房主开局。小局／胜局、随机、策略记忆和有效回退历史重新初始化，旧实例意图不能作用于新局。另提供需明确确认的“清空牌桌”，才移除全部座位和手机身份。过去实例保留在 SQLite journal，不在本轮增加查询界面。
- 回退记录显示小局、有效步骤编号、行动玩家或管理步骤，可筛选并分批查看。旧存档缺少补充上下文时标记历史步骤，不推测玩家。确认说明撤销范围及已看信息，恢复后仍同步全端并暂停。
- 电脑服务运行期间防止自动休眠，可见且未最小化的公共屏防止屏幕自动休眠；公共屏关闭后服务继续，程序退出释放保护。手动休眠、关机不由此阻止；系统恢复以及手机 online／pageshow／回到前台时重新连接或同步本人授权投影。重复启动同一数据目录回到已有实例；只关闭房主窗口且公共屏还在时，可从原生“程序”菜单恢复管理窗口。
- 启动失败弹窗与 desktop.log 保留具体服务原因，中文区分端口占用、版本不兼容、损坏存档、目录不可写／路径无效及超时。原生菜单提供日志目录入口，不自动删除存档、改防火墙或替用户切换数据目录。

实现与模拟边界见 [工程结构](architecture.md)、[验证命令](development.md#聚会可靠性) 与 [本轮验收](acceptance.md#首版维护聚会可靠性与连续游玩)。

## 公共大屏兼房主管理与调试模式

2026-10-01 用户明确公共大屏与房主管理采用同一界面，并增加调试模式，可查看更多信息和执行额外修改。采用理由、旧方案及落地状态见[界面决策 002](../decisions/002-host-public-screen-and-debug.md)。正常模式使用公开游戏信息和房主操作区，手机按本人玩家权限操作；服务端继续校验每类动作授权。合并主机界面可展开全部弃牌，手机只显示顶牌。

用户随后要求调试模式后续独立规划，面向盒子内所有游戏尽可能支持纠错、撤回和恢复。长期目标统一见[需求第 6.5 节](../requirements/TableMax_需求文档_v1.0.md#65-跨游戏调试与纠错后续独立规划)。字段、修改动作、投屏显示、历史与恢复细节留待专项，本轮停止逐项追问调试权限；普通游戏权限与决策点回退继续按既有要求定义。

正式工程保留三种身份，各自有盒子与独立游戏入口。通用原型保留三角色供对照，游戏专属原型已合并公共主机与管理；正式主机已兼管理，尚未提供调试能力。旧角色切换与模拟异常抽屉用于原型审阅，不能视作产品调试模式。以下矩阵描述普通模式的逻辑授权，公共与管理两列现由同一主机界面承载；调试例外待确认后单列。

## 盒子与独立牌桌

2026-10-01 用户增补，1.0.1 已落地。`/host`、`/public`、`/player` 承载盒子、加入与准备；各自 `/game` 子路由承载游戏。开局广播使已连接的盒子进入对应牌桌；既有对局从盒子“进入牌桌”，刷新子路由直接恢复授权状态。回到盒子、前进／后退只改变页面，连接和座位继续保持；切换身份重新建立对应凭证的会话，不把房主授权带进玩家操作。

游戏使用窗口全宽和至少一屏高度，仅留紧凑工具栏、提交反馈和必要暂停提示。电脑展示公共场地，手机突出本人 2×3 场地；记录和牌桌管理在有焦点约束、Escape 可关闭的菜单，对手场地按需查看。教学在线下完成，正式界面不设规则帮助。游戏内没有常驻邀请二维码、宣传标题或侧栏。可调用浏览器全屏；局域网浏览器不提供该能力时仍铺满可用视口。新公共窗口根据当前阶段打开盒子或游戏页。

单步意图直接点桌游组件或明确动作按钮，不先“选择按钮”再确认；卡位与两格交换仍先选后确认，确认文案说明实际动作，选中后才出现取消。暂停、断线、回退和身份失效清除旧选择／查看；已保存才改变牌面和播放动效，未收到确认时仍用原动作编号重试。此调整只改变交互，不修改规则、自动准备或代替真人。

代码职责为 `session/useRoomSession.ts`（连接／授权同步／可靠提交）、`navigation.ts`（角色与页面）、`screens`（盒子和牌桌外壳）、`components`（平台控件）。首版场景和选择留在 `games/pokemon-encounters/ui`；正式资源在共享目录，原型继续独立引用。

| 暂停、恢复、回退、结束、重绑定               | 校验管理权             | 仅接收安全结果     | 接收对应反馈             | 接收对应反馈   | 可执行管理动作                        |

首版逐阶段、逐字段的授权依据见 [游戏权限矩阵](../games/pokemon-encounters/information-and-decisions.md#逐字段授权矩阵)，包括公开摸牌、主机全弃牌、本人临时查看和结算揭示。公开投影仍不包含牌库未来顺序或未授权暗牌。

bot 的逻辑角色等同于该座位的普通玩家，运行位置在本地服务端不代表策略可获得服务端完整状态。策略调用只传安全授权视图与合法选择，调试模式也不扩展策略输入；管理动作与策略调用分开，bot 不代真人操作。

“本人信息区”不是永久查看暗牌的授权。公开错误只表达越权、阶段过期、分支过期、状态需同步等安全原因，不说明未知牌值、秘密目标或隐藏能力是否存在。

平台管理动作和本地 UI 行为不冒充游戏决策；翻页、放大、打开帮助不创建游戏 checkpoint。旧换绑流程已删除；调试修改的动作、历史及恢复语义由后续专项定义，不作为当前规则问答关口。

## 提交、回退与恢复语义

| 客户端状态     | 反馈与允许行为                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 尚未提交       | 从最新授权视图取得合法选择；允许本地取消，未改变权威状态                                                         |
| 提交中         | 禁止重复发起新动作；动画不表示成功                                                                               |
| 保存并确认     | 服务端事务保存后确认；展示确认结果与最新视图，清空已完成选择                                                     |
| 明确拒绝       | 展示安全原因；同步需要更新的状态后重新选择，拒绝不产生游戏决策点                                                 |
| 确认丢失／断线 | 结果未知，不显示成功或默认失败；保留未确认动作标识供查结果／同编号重试，完整同步前不允许新动作                   |
| 重新同步       | 服务端给出当前分支与授权完整视图及未确认动作结果；清除旧选择。身份、分支或阶段变化时不得将旧意图转换成新动作重试 |

原型的“模拟完整同步”只展示清空反馈，未判断未确认动作是否已经执行；其文字和测试不构成可靠交付验证。原型角色切换也会清除本地选择和提示，避免审阅时沿用上一角色状态；正式产品须根据真实身份及服务端投影完成隔离。

回退必须记录游戏声明的决策前状态与安全标签。恢复状态包括公共／秘密游戏数据、当前阶段、行动顺序、待处理选择、牌位置、牌库／弃牌顺序、得分、已生成结果及随机源状态。身份、授权、当前连接与地址不恢复成过去；平台修订和分支递增。作废分支的动作、请求、选择、待播放动画失效。

涉及信息揭示时提示“已有信息可能被看见”，不要求全员同意，也不一律拒绝回退。恢复对应 checkpoint 和随机状态，不暗中洗牌或重投硬币。一次选择及其确定性变化／自动推进共同保存，再等待下一选择；首版复合能力、已生成结果与中间恢复字段按 [D01–D13 决策边界](../games/pokemon-encounters/information-and-decisions.md#每项决策与恢复边界) 实现。

保存确认、回退保存和自动推进必须形成一致决策边界；一次恢复先保存新有效分支，再发布授权视图。存档需分别记录平台格式、游戏、规则和状态版本，未通过兼容检查不得加载。完整 checkpoint 不进入前端日志、公开历史或管理标签。

## 共用决定倒计时（2026-10-04）

现代艺术 2026-10-04 最新 debug 要求覆盖其旧界面约定：选画阶段不展示倒计时；手机提供独立本地声音和静音偏好。首次／刷新需浏览器手势解锁，已消费旧事件不补播，盒子重进恢复后续新动作声音。其他游戏的计时与手机声音继续按各自规格；本次已授权三款游戏规则说明，唯一视觉要求见 [图文规则说明](visual-design.md#顶层图文规则说明)。现代艺术具体界面、配图、拍卖开场与权限见 [游戏规格](../games/modern-art/README.md)。下文计时的服务端保存基准和到时不强制行动边界保持。

2026-10-05 现代艺术拍卖台改为上方横向时间进度条，不显示剩余秒数；选画和双拍补画仍不展示计时。暂停冻结，到时停在零并只播放一次主题提示音，不设置惩罚或强制动作。到时提示沿用本地静音、手机手势解锁及电脑单声源，按对局实例、回退分支和 clock ID 去重；刷新／重进不补播已到时提示，暗标其他席位提交不重复提醒。该表现仅用于现代艺术，其他游戏维持各自行为。

2026-10-04 盒子 debug 覆盖此前通用计时界面：入口改为滑杆图标和“游戏设置”，现代艺术、电力公司用大号秒数、刻度滑杆和保存按钮，明确到时仅提醒。宝可梦声明 `decisionTimer: false`，不投影计时、显示配置或空设置入口；合法决策及人机调度保持。旧计时存储兼容读取。

电脑管理员在支持计时的游戏设置中选择 5、8、10、12、15、20、25、30、40、50、60、75、90、105、120 秒，默认 20 秒。配置保存在房间元数据，新房间、续局、游戏切换与重启保留；手机房主不增加配置权限。显示设置按设备摘要、适配方式、界面大小组织，立即生效，管理与公共窗口独立保存，支持恢复自动适配，仅发生错误或缩放受限时提示。

服务端根据游戏 SDK 的合法决策标识给出同步计时基准；相同并发组共用起点，其他席位的暗标提交不重置剩余席位的时间。暂停冻结，恢复续走；重启暂停并使用最后成功保存的剩余时间，关闭期间不计入思考时间；回退重新建立暂停的完整时长。修改时长重新计时，不改游戏状态或 checkpoint 中的规则快照。

归零只提醒，原合法动作继续可用，不自动出价、截标、确认或代替离线真人。时间变化由浏览器按服务端基准显示，不产生规则动作或 SQLite 写入；刷新、重连使用服务端基准，不把浏览器打开时间当成决定开始时间。没有决定、结束、断开连接时隐藏或暂停显示，不产生持续警报。

## 实际游玩与测试模式（1.4.0）

普通桌面启动明确进入实际游玩 `play`，人机默认／豆包／绝悟分别等待 1500／1800／2200 ms 后计算，2 秒计算硬限与取消边界不变。等待只表达当前决策准备，不表示动作已保存；最新操作、卡位变化和声音仍在服务事务确认后表现。测试 `test` 的调度间隔为 40 ms，省略装饰动效与声音，保留合法操作、身份、秘密投影、存档和回退流程。

测试入口仅房主电脑快捷键 Ctrl+Shift+F12，弹出运行模式浮窗；正常菜单没有入口，手机与 public 无设置权限。当前测试模式有小徽标，防止误认普通节奏。切换经过房主授权及保存，失败不改变模式、修订或调度；切换取消旧任务并按新模式重新排队，不改规则／策略 RNG、牌序、checkpoint 或真人身份。回退与原班续局保持当前模式；普通重启回到 `play`，隐藏工程启动参数可以明确选 `test` 或 `play`。这是速度与表现开关，不是需求第 6.5 节的全知调试／规则纠错功能。

连接帮助、游戏信息与房间管理由按钮打开悬浮对话框，不在原位置推开牌桌；游戏菜单、朋友牌桌和最近操作同样使用浮窗。Esc、外侧点击及关闭按钮可以关闭，焦点回到入口；确认操作显示具体后果。房主游戏菜单直接呈现暂停／恢复、回退和“结束游戏”，结束采用单独确认，不能只藏在折叠管理中。2026-10-04 用户已要求各游戏规则说明优化，具体浮层与图文要求见 [通用视觉](visual-design.md#顶层图文规则说明)，不主动新增自动教学流程。

首版按用户要求扩到最多六位，围桌房间显示六个席位，电脑牌桌采用三列两行，手机维持本人区域。具体安全行动播报和字体／星标见 [游戏交互](../games/pokemon-encounters/interaction.md#游玩节奏行动播报与六人布局140)。

## 电脑多分辨率显示（1.5.0）

房主管理与公共屏在盒子和游戏工具栏均提供“显示设置”，打开浮窗；手机没有该按钮。当前采用保持窗口／全屏大小、调整界面大小的方式，提供自动适配与 1280×720、1920×1080、2560×1440、3840×2160 四档预设，以及标准／放大／更大（100%／125%／150%）。预设是当前画面的适配参数，系统屏幕分辨率仍由 Windows 管理。自动适配随窗口尺寸、全屏和所在显示器变化重算，结合 Windows DPI，避免 4K 固定像素内容偏小或系统已放大后再次重复放大。

在 Windows 100% 缩放、3840×2160 内容窗口下，标准自动适配为两倍页面缩放，沿用 1920×1080 的六人布局；150% 系统缩放对应 2560×1440 DIP 内容时约为 1.333 倍页面缩放。界面大小在此基础上调整，窗口空间不足时限制放大比例并提示；短屏电脑仍保留紧凑六席和三列两行牌桌。悬浮面板、最新操作、卡面和星标随同放大，Escape 和关闭后焦点回到入口。

显示设置仅在桌面程序的本地窗口可用，各窗口缩放隔离，刷新保持本窗口偏好。房主管理与公共屏分别保存最近选择，作为对应角色新开窗口／重启后的默认值；新公共窗口继承最近公共屏设置，已经打开的其他窗口保持各自偏好。设置不传播到手机或游戏存档，纯浏览器页面沿用浏览器自身的显示控制。显示设置不提交游戏命令，调整期间对局、随机、秘密信息和原玩家身份保持。具体工程实现见 [显示控制](architecture.md#电脑显示控制)，验证范围见验收记录。

2026-10-05 原生全屏已统一实际窗口状态：`tablemaxWindow.read()`、`setFullscreen(boolean)` 和 `subscribe()` 返回／订阅 `{ fullscreen }`。EXE 游戏工具栏按钮、F11 和窗口菜单共用幂等设置；进入铺满当前显示器，退出恢复原位置、尺寸与窗口状态。管理与公共窗口互不影响，变化重新计算显示倍率，不提交游戏动作或改变身份／checkpoint。桥接沿用受管理窗口、本源、顶层及 host／public 角色校验，手机与子 frame 无此权限；纯浏览器仍走标准 Fullscreen API。按钮等待时防重复请求，错误显示重试；Escape 优先关闭当前浮窗，否则退出全屏。源码已检查后台与短时不激活的正常前台窗口，实际包和设备边界见 [验收记录](acceptance.md)。

2026-10-05 合并检查补充：1080×800 等窄电脑大厅沿用短屏紧凑间距，保留 16px 信息、18px 主要动作与 44px 触控；六席及准备状态在首屏内，手机继续按页面阅读，不通过缩字规避。
