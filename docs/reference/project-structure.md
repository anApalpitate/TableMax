# 目录职责

## 已创建结构

| 路径 | 职责与允许内容 |
| --- | --- |
| `AGENTS.md` | Agent 阅读入口、关键工作和维护约定；详细说明放入对应文档 |
| `README.md` | 项目目标、真实进度和导航；实现前不编造启动与测试命令 |
| `TableMax_需求文档_v1.0.md` | 原始产品需求基线，保留原件及当前路径 |
| `TableMax.code-workspace` | 本项目编辑器设置，根目录引用为相对路径 `.` |
| `.gitignore` | 依赖、缓存、日志、临时文件、可再生文件及本地秘密的忽略规则 |
| `docs/README.md` | 按任务意图组织文档入口 |
| `docs/reference/` | 当前目录职责、通用规则及后续操作说明 |
| `docs/decisions/` | 已确定的重要选择、理由与后果；目前仅有索引，产品决策引用需求 |
| `docs/tasks/` | 进行中任务与已确认待办；目前仅有需求中的开发前研究项索引 |
| `docs/archive/` | 有历史价值的过程材料；目前仅有索引，无归档材料 |

## 实现阶段的目录选择

需求第 6.3 节建议使用 `apps/` 划分桌面壳、服务端和网页端，`packages/` 划分协议、游戏 SDK、平台核心和通用 UI，`games/` 承载独立游戏模块。这些目录尚未创建，具体源码边界及技术选型在实现阶段确认后再建立。

游戏规则研究、扩展指南和资源整理时，按实际工作建立对应主题目录并更新索引。需求建议的 `docs/games/`、`docs/game-development/` 等不是现有文件路径；根目录已有需求原件无需仅为匹配示例迁入 `docs/requirements/`。

新增目录应有当前明确职责，不预铺未来插件、多房间或后续游戏的空层级。确需跟踪空目录时使用 `.gitkeep` 或有实际用途的说明文件。

## 材料与产物边界

- 长期需求、规则规格、来源清单和必要游戏资源属于项目资料；放入对应主题，不混入临时目录。
- 本地实验、临时导出或下载中间文件可放入根目录 `tmp/`（需要时创建）；不作为长期资料入口。
- 根目录 `build/`、`dist/`（需要时创建）仅用于可再生构建中间物。正式交付包的保留位置与版本管理策略在打包阶段明确。
- 原始规则资料、数据、正式资源和最终交付物不按扩展名笼统忽略；是否提交按实际用途、来源与需要决定。
- 运行时存档位置按需求的本地应用数据目录建议在实现时确认，不提前在仓库内生成玩家存档或秘密状态。
- 忽略规则不是删除授权；已有资料不自动迁移、重命名或取消跟踪。

## Git 与编辑器策略

源码、文档、必要配置和工作区文件默认跟踪且可见。`.gitignore` 预留了依赖目录、工具缓存、日志、根目录临时／构建目录、本地 `.env` 和 `secrets/` 的排除规则；无秘密的 `.env.example` 和 `.env.*.example` 可以跟踪。

工作区分别维护 `files.exclude`、`search.exclude`、`files.watcherExclude`。文件树隐藏依赖、缓存、日志和可再生临时／构建目录；搜索排除噪声，监听排除对应目录的内容。没有按 Git 忽略规则隐藏全部文件的设置，也没有笼统隐藏原始资料、正式游戏资源或最终交付物。

当前不包含依赖安装、业务代码、代码骨架、服务启动、远程仓库或 CI 配置。后续增加真实开发与验证入口时同步更新 [项目说明](../../README.md) 和 [Agent 入口](../../AGENTS.md)。
