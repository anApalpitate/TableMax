# 通用视觉与规则说明

## 电脑浏览器玩家的手机区域（2026-10-08）

根加入网址、兼容的 `/player` 及 `/player/game` 首次保持手机视觉与操作；按用户最新批准的横屏计划，电脑浏览器可在模拟手机区域外右上角切换横屏。布局按页面角色识别，不按运行服务的机器或 IP 提升权限；`/host`、`/public` 继续采用现有大屏。窗口变化和切换须保留同一 iframe、连接、组件实例与未提交草稿。

- 通过平台、UA 和可选 Client Hints 识别电脑；排除 Android、iPhone、iPad 及 Mac UA 多触点的 iPad，触屏 Windows 仍按电脑处理。信息缺失时保守保留移动布局，普通 HTTP 不依赖 Client Hints。
- 外部按钮 48×48px，默认深绿色、横屏金色，提供名称、提示、选中状态与键盘焦点。偏好独立存为 `tablemax-player-display-mode` 的 `portrait/wide`，损坏或存储不可用默认竖屏，内存切换仍可使用。
- 竖屏优先 9:19.5，宽度随高度在 320–430px 调整，短屏保留最小可读宽度及正常滚动。横屏最大 1600px，保留背景与外部按钮空间；外层不足 800px 暂时回退移动布局，扩大后恢复所选模式。
- 游戏按子文档实际宽度在 960px 分列，1200px 增加适合并排的卡牌。盒子座位与本人操作分列；宝可梦的取牌／暂持与唯一操作牌阵分列，扩展另含缓冲和研究；现代艺术行情通栏，拍卖／资金／报价与手牌分列；电力公司保留行动、市场、地图、公司四页，建设页组合地图与确认，隐藏页继续 hidden/inert。短屏优先显示主要动作，不缩文字规避。
- 共享原生滚动条主题约 10px，奶油轨道、圆角滑块及悬停，各游戏提供自身颜色。Chromium/WebView2 圆角样式与标准属性回退分开，触摸主导和强制高对比保留系统行为。浮窗独立滚动并阻止穿透，外框不占用无意义的滚动轨道。

盒子标签、状态、说明和操作在所属卡片内成组对齐；避免座位状态孤立成行、无关联的说明块或长网址挤坏布局。长昵称和错误反馈可换行，连接帮助、换机和管理浮窗在手机区域内保持可阅读、可关闭和可操作。实际渲染及设备范围见[验收](acceptance.md)，源码布局不等同于美术验收。

盒子与游戏的当前视觉要求在本页维护；用户原话、采用背景和来源见 [用户美术偏好](art-preferences.md)，三端身份、提交、恢复和显示设置见 [平台规格](phase-02-platform-spec.md)。具体游戏的主题、组件、规则配图与已实现状态归 [游戏主题](../games/README.md)。本页规定设计与维护要求，不表示所有旧界面已经通过新要求验收。

## 主体、层级与状态语义

- 电脑和手机的游戏主体尽量占满可用区域；先突出行动者、阶段、当前进度与主要操作。电脑主机管理、公共屏只读、手机本人秘密操作各有布局，不把电脑画面等比缩小到手机。
- 删除重复身份短句、细小副标题与多段常态说明。避免用中点把行动者、动作、卡牌和状态串成一条；用头像、标题、组件与独立短标签建立关系。连接失败、保存失败和确认后果仍需明确表达。
- 数量、价格、收入、费用、容量和进度应有可理解的名称与必要单位。累计与本轮、当前与预计、暂持与已拥有、未行动与已确认要明确区分；预估不得画成已保存结果。
- 类型与状态同时使用有对比的颜色、文字或形状。加强重要边框和角标，使其在目标最小尺寸下可辨认；标记放在独立空间，不遮住画作、角色、数值、资源槽或主要按钮。装饰不得伪装成可点击动作。
- 相邻控件对齐，选择目标与确认动作关系直接；长名字与牌名可换行，必要时保留完整可访问入口，不能只有一排无法辨认的省略名称。

## 信息文字下限（2026-10-04）

传递状态、规则、金额、牌名、标签与操作含义的可见文字至少 **16 CSS px**；主要操作和关键状态至少 **18 CSS px**，电脑分区标题至少 **20 CSS px**；触控目标至少 **44px**，焦点可见。

短屏先减少冗余、重排、按需展开和提供局部滚动，不能缩字、局部缩放或把信息数字称为装饰规避下限。电脑整体显示倍率仍遵循 [空间保护](phase-02-platform-spec.md#电脑多分辨率显示150)；手机不提供电脑显示设置。设计变化后对实际渲染核验，未变化旧页在后续维护时按本页检查，不把既有截图推成全产品通过。

## 多卡集合与短屏布局

2026-10-06 游戏介绍弹窗修复：共用浮窗只负责外框、标题和关闭，介绍内容布局由 `box-overlays.css` 维护；不保留覆盖新版介绍的旧横向flex样式。独立盒子与共用runtime样式的加载顺序不能改变段落布局，介绍／头像浮窗宽度选择器须明确胜过通用外框。三游戏及宝可梦两版本的分节与窄屏回归入口见[开发环境](development.md#游戏介绍弹窗布局检查)。

手牌、收藏和电厂等重复组件优先采用容器内纵向滚动、按有意义的类别靠拢；浏览排序不改变组件 ID、规则位置、秘密投影或服务器顺序。宽度允许时每行至少两项，按目标最小文字和组件结构选自适应宽度或预设；宽复杂详情可独立展开，不为两列强压地图、规则棋盘或单个决策表单。

同一浏览区域只保留一个纵向滚动负责人，避免滚动框中再嵌套同方向滚动框；浮窗与页面作为独立浏览场景分别处理。滚动区域应明确边界，操作与关键信息易找；限制页面整体横向溢出。宝可梦已要求手机卡位与当前动作尽量在首屏，不能机械改成滚动画廊。电力公司地图保持城市、区域和连边的规则空间关系，电厂／资源／玩家公司列表分别判断。多人数、空集合、密集集合、长昵称、单／双组件各需检查；少人数或终局可利用留白，但重复卡片仍保持适当密度，不能任由宽栏撑满单张；现代艺术收藏突出画家／色标与拍卖方式，手机用摘要，各游戏按所需识别信息判断。

## 辅助提示与数字标记

非紧急的规则提醒集中为紧凑单行文字条，多条轮流切换并用自然的短淡入／轻微位移过渡；减少动态时直接切换。当前操作条件、错误、连接状态与重要保存结果保持即时可见，不进入轮播队列。现代艺术已采用该形式，间隔和尺寸由其组件维护，其他游戏按后续任务适用。

玩家座位编号使用圆形或方形色底中的清楚数字，与昵称、头像并列；优先对比鲜明的底色和白色数字。编号来自稳定座位顺序，图形表现不改变身份或动作顺序。

## 保存结果与声画反馈

声画表现应有游戏辨识度，重大结果可使用更强的入场、主题图标、光线和短全屏装饰，普通动作保持轻快。区分不同事件的音色与视觉，不把一种音效和通用横幅用于全部动作；不自动将现代艺术五类入场映射到其他游戏。

只在新动作成功保存后表现结果，明确行动者、组件／能力和公开目标；等待计算不表示已经行动。特效不阻断下一位合法操作，不覆盖必须读的状态或阻止点击，不泄露私密出价、手牌或未公开目标。刷新、重连、回退和盒子重进不补播历史事件；声音失败不影响游戏，浏览器手势解锁按实际限制提示。

减少动态使用静态或短淡入替代，测试模式省去装饰声画但仍走权限、规则和保存路径。动效完成情况用实际运行验证，静态截图只能判断所见布局；音频解码、播放消费、人耳听感分别记录，不能互相替代。

## 顶层图文规则说明

每款正式游戏提供易找到的“规则”入口，打开顶层卡片／对话框。按“目标与胜负、主要回合、对应区域、关键例外”分节，正文短而清楚，保留具体组件与当前游戏术语；不把设备加入说明当成玩法介绍，不新增自动教学流程或阻断开局。

2026-10-05 用户要求按规则逻辑重新制作原创配图，替代将游戏截图直接用于规则说明的方式。图与文字应对应：生成图负责画作、组件、材质与场景，准确数字、座号、箭头及规则文字由 HTML／SVG／代码排版，不能依赖生成图中的文字推定规则。图片不能替代可读正文或规则核验，地图／画家／能力数字仍由已采用版本确定，不包含正式玩家秘密。配图集中在 `assets/games/<id>/` 并本地打包，记录提示词、输入、来源、版本、用途、尺寸、哈希及转换；保留原图、旧截图及历史证据。三款游戏均已采用原创图解，宝可梦八章与九图来源见 [游戏主题](../games/pokemon-encounters/README.md)，完成入口见 [任务索引](../tasks/README.md#原创规则图解重做已完成)。实际同包规则弹窗检查与设备边界见验收。

规则内容引用各游戏来源与已采用规格，明确官方原文、用户说明与项目约定。打开、关闭、滚动和查看图片不改变 revision、checkpoint、计时基准或玩家身份；主机、只读公共屏和手机的说明权限均不增加游戏操作权。Esc、关闭按钮和适当的外侧点击可关闭，焦点回到入口；短手机图片适配宽度、内部纵向滚动、文字和触控满足下限，顶部关闭入口持续可用。

规则或 UI 区域变化后，仅更新受影响章节／配图及清单；核对说明与真实流程，不让旧截图误导。当前三游戏具体内容和完成状态从 [宝可梦](../games/pokemon-encounters/README.md)、[现代艺术](../games/modern-art/README.md)、[电力公司](../games/power-grid/README.md)进入。

## 三端、资源与验证

平台沿用明亮桌游主机方向：原创头像、实体感桌面、鲜明色块和柔和材质；游戏参考各自实物，保留独立 UI、样式和资源。角色分工和真实授权由 [平台规格](phase-02-platform-spec.md#信息权限与动作边界)维护。平台功能图标、本地字体、SVG／代码数值与 imagegen 位图分别承担合适用途，不用生成图反推规则或写死秘密信息。

设计前查偏好与对应游戏，优先验证六人／适用最大人数、720p、125%／150% 显示请求、短手机、暂停、空／密集集合和浮层。检查实际字号、完整名称、44px 热区、滚动与遮挡，按影响完成所需三端及 4K 验证；使用隐藏窗口、当前渲染截图，实际缩放与限制分别记录。源码／素材变更与结论对应，旧包通过不能证明新包通过，验证范围见 [验收记录](acceptance.md)。

## 平台既有方案与素材追溯

以下保留既有采用细节和历史原型范围，方便定位来源；不是所有游戏的固定皮肤或当前完整验收。

### 手机聚会与围桌房间（2026-10-02）

所有真人各自扫码使用手机，电脑只运行服务、房主管理和公共信息展示，管理界面没有本人玩家区、初始翻牌或取牌按钮。房主本人参赛时也拿手机领取普通身份。公共屏继续只读，公开画面和手机私密操作保持不同投影；人机是本地服务控制的玩家座位，不指操作电脑的房主。

盒子使用明亮游戏大厅式房间：中央为实体感桌面，固定最多六个围桌席位（1.4.0 按用户要求扩展）；已加入玩家依次上桌，空位显示“空座”，按实际座位顺序编号。头像、昵称、人机等级、手机在线／离线和准备状态在各自座位附近；本人的手机席位突出。桌面／公共屏以桌子和席位为主要视觉，手机保留紧凑围桌场景、自己的准备操作和入座表单，长昵称不挤压其他座位。座位设置放在独立按需打开的悬浮窗口，避免桌上叠加管理菜单。

房主在盒子选择默认／豆包／绝悟并添加人机，已入座人机可以在座位设置更改等级；开始后禁改，原班回到大厅可再配。等级公开显示，内部思考与授权记忆不下发。真人只用自己的手机准备和游戏选择；电脑开始按钮等待真实玩家准备，不自动替他们准备或操作。具体等级能力见 [人机规格](bot-players.md#三档智能与配置)。当时教学在线下完成、菜单不设规则帮助；2026-10-04 本次授权已由本页的图文规则说明覆盖，连接与管理排障提示继续保留。

桌面尺寸 1080×800、1366×768、1920×1080 与手机 390×844、360×640、横屏分别检查真实渲染；围桌席位、昵称、状态和主要按钮不得重叠、遮挡或横向溢出。新增风格只作用于盒子房间，不改游戏规则、牌桌私密布局或单一房间范围。

### 明亮主机与既有美术基线

2026-10-01 用户确认并要求实施“明亮的桌游主机”，三端统一、先做独立原型。选择奶油纸底、鲜明色块、圆润木质玩具插画，增加封面、头像和场景，替换大标题加说明面板的网页构图。它保留平台简洁现代的基线，同时适合朋友聚会及后续不同游戏主题。第二阶段原型先采用该风格；第三、四阶段正式平台已复用封面、骰子和头像并接真实授权。

参考：[Playnite](https://playnite.link/) 的图像识别入口与全屏模式、[Big Box 官方图库](https://www.launchbox-app.com/download) 的盒绘与主题布局、[Jackbox 美术记录](https://www.jackboxgames.com/blog/behind-the-scenes-of-pp10-art) 的原创角色与场景，以及 [Jackbox 加入流程](https://www.jackboxgames.com/how-to-play) 的主屏／手机分工。借鉴的是视觉层级与交互分工，不引入在线加入服务、商城、手柄支持或新游戏规则。

### 视觉规范

- 奶油白 `#F6F2E8`、深灰 `#25343A`、青绿 `#247C75`、暖黄 `#F4BE45`、珊瑚橙 `#E77A60`。青绿承担主操作，暖色承担装饰；状态还配文字及符号，不只靠颜色表达。
- 8px 间距基准、24px 主容器圆角、柔和阴影；字体沿用本机 Segoe UI／微软雅黑，不新增联网字体。功能图标为统一线宽的本地 SVG，按钮与触控目标至少 44px；焦点边框可见，减少动态效果设置关闭过渡。
- 平台插画使用原创骰子、棋子、卡片、筹码及动物玩具；封面“桌边奇遇”为平台示意，实际游戏名在可控文字层显示。它不是宝可梦组件、实际棋盘或规则证据。
- 常态说明压缩到短句；连接步骤与实现说明收进帮助及审阅抽屉。回退揭示提醒、结束确认和保存失败原因仍保留。服务确认与视觉反馈的关系沿用本页语义。
