## 视觉任务交付

用户要求：每次视觉改造任务收尾，须交付可本地打开的HTML，展示本次修改的变化，并在最终答复中提供入口。此项属于完成标准，不能仅用文字总结或单张附件代替。页面聚焦本次改动，展示修改后的实际渲染、变化说明及适用端侧／视口；有可核验的修改前画面时提供前后对照，没有时明确说明，不补造旧界面。设计示意须单独标识，不能冒充实际运行结果。检查结果及未验证范围保持可读。

HTML及其本地依赖可离线查看，不引入远程CDN；仅作审阅的页面和临时图片集中在本任务 `tmp/<任务唯一ID>/`，正式验收证据仍留在所属证据目录。临时内容收尾须配齐一键清理入口，最终答复同时链接HTML与清理入口；清理范围和保护规则见[工作区维护](workspace-maintenance.md#tmp-临时内容的生命周期2026-10-11)。交付展示不自动触发删除，也不替代实际UI验证。

收尾使用[文档与交付审计](../../tools/maintenance/README.md#任务收尾检查)检查HTML、本地静态依赖、临时目录清单及清理入口；检查不执行清理、不证明图片内容或视觉质量。实际渲染及互动仍按[源码视觉验证](source-visual-verification.md)和[验证范围](validation.md)执行。

## 三类布局与宽高比适配

### 固定构图接入契约（2026-10-25）

用户已授权按[固定构图任务](../tasks/fixed-canvas-visual-validation.md)分批实施，游戏试点通过前不冻结全项目尺寸。声明可选`layout: { contract: 'fixed-v1' }`的客户端由既有宿主提供固定逻辑容器与`useGameLayout`展示上下文；未声明客户端、旧发行及原`three-v1`保持各自原契约，不提升`webHost 1`。

首轮管理1280×720、玩家竖屏360×640、玩家横屏640×360均指扣除安全区后的逻辑内容区。支持范围内内部构图固定，游戏不能再按真实窗口尺寸分支；必要地图／牌架浏览及窗口层dialog、popover另按坐标归属处理。普通浏览器CSS倍率为1、原尺寸居中，保留浏览器缩放；管理倍率只由原生层计算，不用CSS自动拟合抵消用户设置。

玩家显式选择放不下时先回退至可容纳构图，不改写保存偏好；两套均不足时保持字号、完整滚动访问和可见不足提示。布局切换不重挂载会话或清除草稿，提示不拦截操作。具体选择算法、原生profile及迁移证据只在任务／平台规格维护；全部内容与接入通过之前不得据此删减旧检查。

### 三类布局通用边界

依据用户本次提出并要求入档的方案，平台只维护三套布局规则，适用于盒子与各游戏；这是后续改造的规范，不表示现有页面已完成适配。需求来源见[需求基线](../requirements.md#911-三类布局与客户端玩家模式2026-10-23)。

| 布局规则   | 适用范围                                     | 主要约束                                                   |
| ---------- | -------------------------------------------- | ---------------------------------------------------------- |
| 服务端横屏 | 电脑管理兼展示界面                           | 固定横屏设计；公开游戏与按需管理同处一个页面，不另设公共屏 |
| 玩家端竖屏 | 手机竖屏、竖向浏览器窗口及未来客户端玩家模式 | 纵向组织信息和操作，保留触控与安全区域                     |
| 玩家端横屏 | 手机横屏、宽屏浏览器窗口及未来客户端玩家模式 | 横向组合游戏区域，短屏仍保证主要操作可达                   |

- **布局与角色分开**：管理兼展示与玩家各有盒子／游戏页面、授权投影和操作边界；三套布局规则不是三种权限。管理继续使用public公开游戏投影，桌面客户端进入玩家模式时使用玩家布局，不继承服务管理权限。
- **按可用空间选择**：玩家布局依据内容窗口的可用宽高与所需最小空间选择，不以手机／电脑、UA或运行服务的机器作为唯一依据。旋转、窗口变化与布局切换须保留连接、身份和未提交草稿，不因适配重新入座或提交动作。
- **有限适配与留白**：每套布局在实施时明确代表尺寸、最小支持尺寸、适用宽高范围、最大内容宽高与切换边界。范围内允许有限的弹性调整；更宽或更高的窗口通过居中、横向／纵向边缘留白保持构图，无须铺满屏幕。此处不冻结统一的16:9、9:20或其他单一画布比例；具体参数待实际内容验证后确定。
- **空间不足的处理**：优先重排、折叠次要信息、分页或局部滚动，避免整体无限缩小。低于最小支持尺寸时须明确提示或保留可用的滚动访问方式，不静默裁掉操作。信息文字≥16、主要动作／关键状态≥18、电脑标题≥20 CSS px等既有下限继续适用；地图与棋盘的空间关系、手机安全区域也须保留。
- **组件复用**：同一游戏的卡牌、状态、操作、浮窗和业务逻辑在横竖布局间复用，差异集中在区域排列、组合与展示方式；通用控件按实际共性复用。游戏主题、规则、样式和资源仍内聚于各游戏，共享层不引入游戏类型依赖，不为复用强行统一不同游戏的操作流程。
- **验证收敛**：以三套布局各自的代表尺寸、最小支持尺寸、切换边界及较宽／较高留白场景构成适用矩阵，尺寸相近且布局行为一致的视口可归组；不再为每种设备或分辨率另造布局。仍按本次改动覆盖管理展示与玩家、最高人数、短屏、密集状态、浮窗、旋转与草稿保留；管理公开投影与玩家秘密权限须分别核验，旧公共URL另验410及无管理授权，不再运行公共屏产品布局矩阵。4K、Windows DPI与真实设备等原有必需验收不因矩阵收敛而取消。

旧设备识别、模拟手机区域和具体断点仅在[整理前原文](../archive/visual-design-before-consolidation-2026-10-23.md#电脑浏览器玩家的手机区域2026-10-08)追溯。当前实现与实际通过范围查[验收](acceptance.md)，剩余改造从[任务索引](../tasks/README.md)接续。

## 主体、层级与状态语义

- 电脑和手机的游戏主体优先使用适用布局的内容区域，边缘留白遵循三类布局规则；先突出行动者、阶段、当前进度与主要操作。管理展示公开局面与按需管理，玩家显示本人授权操作，不把电脑画面等比缩小到手机。
- 删除重复身份短句、细小副标题与多段常态说明。避免用中点把行动者、动作、卡牌和状态串成一条；用头像、标题、组件与独立短标签建立关系。连接失败、保存失败和确认后果仍需明确表达。
- 数量、价格、收入、费用、容量和进度应有可理解的名称与必要单位。累计与本轮、当前与预计、暂持与已拥有、未行动与已确认要明确区分；预估不得画成已保存结果。
- 类型与状态同时使用有对比的颜色、文字或形状。加强重要边框和角标，使其在目标最小尺寸下可辨认；标记放在独立空间，不遮住画作、角色、数值、资源槽或主要按钮。装饰不得伪装成可点击动作。
- 相邻控件对齐，选择目标与确认动作关系直接；长名字与牌名可换行，必要时保留完整可访问入口，不能只有一排无法辨认的省略名称。

## 信息文字与触控下限

传递状态、规则、金额、牌名、标签与操作含义的可见文字至少 **16 CSS px**；主要操作和关键状态至少 **18 CSS px**，电脑分区标题至少 **20 CSS px**；触控目标至少 **44px**，焦点可见。

短屏先减少冗余、重排、按需展开和提供局部滚动，不能缩字、局部缩放或把信息数字称为装饰规避下限。电脑整体显示倍率仍遵循 [空间保护](phase-02-platform-spec.md#电脑多分辨率显示150)；手机不提供电脑显示设置。设计变化后对实际渲染核验，未变化旧页在后续维护时按本页检查，不把既有截图推成全产品通过。

## 多卡集合与短屏布局

2026-10-24补充：管理兼展示的主要游戏信息在支持尺寸内应一屏看全，不能以主牌桌内部纵向滚动代替适配。玩家竖屏仅轻微超高时，应压紧空白、合并重复信息并重排至一屏；不缩字、不裁操作。朋友、规则、历史及详情浮窗可独立滚动，低于对应游戏最小支持区域时保留可用访问方式。来源见[本次直接反馈](art-preferences.md#管理首屏与宝可梦紧凑布局2026-10-24)，具体游戏尺寸和实测范围分别记录。

手牌、收藏和电厂等重复组件优先采用容器内纵向滚动、按有意义的类别靠拢；浏览排序不改变组件 ID、规则位置、秘密投影或服务器顺序。宽度允许时每行至少两项，按目标最小文字和组件结构选自适应宽度或预设；宽复杂详情可独立展开，不为两列强压地图、规则棋盘或单个决策表单。

同一浏览区域只保留一个纵向滚动负责人，避免滚动框中再嵌套同方向滚动框；浮窗与页面作为独立浏览场景分别处理。滚动区域应明确边界，操作与关键信息易找；限制页面整体横向溢出。宝可梦已要求手机卡位与当前动作尽量在首屏，不能机械改成滚动画廊。电力公司地图保持城市、区域和连边的规则空间关系，电厂／资源／玩家公司列表分别判断。多人数、空集合、密集集合、长昵称、单／双组件各需检查；少人数或终局可利用留白，但重复卡片仍保持适当密度，不能任由宽栏撑满单张；现代艺术收藏突出画家／色标与拍卖方式，手机用摘要，各游戏按所需识别信息判断。

## 辅助提示与数字标记

非紧急的规则提醒集中为紧凑单行文字条，多条轮流切换并用自然的短淡入／轻微位移过渡；减少动态时直接切换。当前操作条件、错误、连接状态与重要保存结果保持即时可见，不进入轮播队列。现代艺术已采用该形式，间隔和尺寸由其组件维护，其他游戏按后续任务适用。

玩家座位编号使用圆形或方形色底中的清楚数字，与昵称、头像并列；优先对比鲜明的底色和白色数字。编号来自稳定座位顺序，图形表现不改变身份或动作顺序。

## 保存结果与声画反馈

2026-10-24宝可梦原版及扩展版按用户明确选择隐藏普通“已保存”成功回执，覆盖下述2026-10-17／20在宝可梦基础版显示普通成功标记的旧要求。动作记录和权威结果继续展示，保存中、错误、断线、待确认与重试仍即时可见；其他游戏沿用自身策略。

2026-10-17保存回执修正：盒子、马尼拉、现代艺术与宝可梦基础版的普通“已保存”使用顶栏空白处的绝对定位图层，不增加反馈行、不预留隐藏标记的宽高，不遮挡操作或互动浮球。马尼拉≤360px时顶栏无足够空位，使用现有行动者状态行的余白；宽屏仍使用顶栏。其他已隐藏普通回执的游戏不新增重复提示。宿主反馈槽可选择仅保存标记或其他消息，默认兼容既有调用；错误、断线、待确认及重试继续即时展示。标记至少16px，不抢焦点、不接管指针，低于原生详情浮窗；各游戏保持既有显示时机，盒子成功回执计时另见[盒子视觉](box-visual-design.md#提交与保存反馈)。

2026-10-20补充：保存锚点本身也必须绝对定位、零尺寸且不参与flex／grid分配。最新动作中的常驻“已保存”标签同样脱离内容布局，不能挤占行动者或结果正文；既有状态框边缘可用作标签位置，不增加隐藏占位或专用内边距。通过保存提示出现前后其他组件的几何不变，以及标签与正文／控件不交叠共同验证。

声画表现应有游戏辨识度，重大结果可使用更强的入场、主题图标、光线和短全屏装饰，普通动作保持轻快。区分不同事件的音色与视觉，不把一种音效和通用横幅用于全部动作；不自动将现代艺术五类入场映射到其他游戏。

只在新动作成功保存后表现结果，明确行动者、组件／能力和公开目标；等待计算不表示已经行动。特效不阻断下一位合法操作，不覆盖必须读的状态或阻止点击，不泄露私密出价、手牌或未公开目标。刷新、重连、回退和盒子重进不补播历史事件；声音失败不影响游戏，浏览器手势解锁按实际限制提示。

减少动态使用静态或短淡入替代，测试模式省去装饰声画但仍走权限、规则和保存路径。动效完成情况用实际运行验证，静态截图只能判断所见布局；音频解码、播放消费、人耳听感分别记录，不能互相替代。

## 顶层图文规则说明

每款正式游戏提供易找到的“规则”入口，打开顶层卡片／对话框。按“目标与胜负、主要回合、对应区域、关键例外”分节，正文短而清楚，保留具体组件与当前游戏术语；不把设备加入说明当成玩法介绍，不新增自动教学流程或阻断开局。

2026-10-05 用户要求按规则逻辑重新制作原创配图，替代将游戏截图直接用于规则说明的方式。图与文字应对应：生成图负责画作、组件、材质与场景，准确数字、座号、箭头及规则文字由 HTML／SVG／代码排版，不能依赖生成图中的文字推定规则。图片不能替代可读正文或规则核验，地图／画家／能力数字仍由已采用版本确定，不包含正式玩家秘密。配图集中在 `assets/games/<id>/` 并本地打包，记录提示词、输入、来源、版本、用途、尺寸、哈希及转换；保留原图、规则依据与历史文字证据；历史运行截图的已授权退役按[工作区维护](workspace-maintenance.md)执行，本次整理不删除证据。三款游戏均已采用原创图解，宝可梦八章与九图来源见 [游戏主题](../games/pokemon-encounters/README.md)，完成入口见 [实施归档](../archive/completed-tasks-2026-10-10.md#原创规则图解重做已完成)。实际同包规则弹窗检查与设备边界见验收。

规则内容引用各游戏来源与已采用规格，明确官方原文、用户说明与项目约定。打开、关闭、滚动和查看图片不改变 revision、checkpoint、计时基准或玩家身份；主机、只读公共屏和手机的说明权限均不增加游戏操作权。Esc、关闭按钮和适当的外侧点击可关闭，焦点回到入口；短手机图片适配宽度、内部纵向滚动、文字和触控满足下限，顶部关闭入口持续可用。

规则或 UI 区域变化后，仅更新受影响章节／配图及清单；核对说明与真实流程，不让旧截图误导。各游戏具体内容、采用版本与完成状态从[游戏索引](../games/README.md)进入，不把早期三游戏结果当作全目录完成。

## 三端、资源与验证

平台沿用明亮桌游主机方向：原创头像、实体感桌面、鲜明色块和柔和材质；游戏参考各自实物，保留独立 UI、样式和资源。角色分工和真实授权由 [平台规格](phase-02-platform-spec.md#信息权限与动作边界)维护。平台功能图标、本地字体、SVG／代码数值与 imagegen 位图分别承担合适用途，不用生成图反推规则或写死秘密信息。

设计前查偏好与对应游戏，优先验证六人／适用最大人数、720p、125%／150% 显示请求、短手机、暂停、空／密集集合和浮层。检查实际字号、完整名称、44px 热区、滚动与遮挡，按影响完成所需三端及 4K 验证；使用隐藏窗口、当前渲染截图，实际缩放与限制分别记录。源码／素材变更与结论对应，旧包通过不能证明新包通过，验证范围见 [验收记录](acceptance.md)。

## 发言面板与互动

发言浮窗改为单列六条，宽度最多500px且距视窗两侧各16px；图标38px底座、完整短语与轻量播放标记对齐。正文18px、字重500、行高1.5，按钮最小60／64px，长句均衡换行，避免末行孤字；面板打开时隐藏互动浮球；标题22px，关闭44px。修正标题选择器优先级，避免通用浮窗的不透明奶油色块覆盖毛玻璃；保留透明浅绿渐变、24px背景模糊和原有减少动态规则。语句、音效、权限与发送行为沿用现有契约；320×568至电脑玩家竖屏实际核验见[验收](acceptance.md#105发言面板优化2026-10-09)。

真人互动球46px，可拖拽并保存相对位置；按住240ms展开264px六等分透明毛玻璃环形盘，以球为中心，球内显示取消。视窗边缘展开时整体移入可操作区域；滑入格子选择、中心松手取消，松手关闭，发言槽使用对话图标。射击提示16px柔和闪烁，提供取消。视觉结果用独立透明层，归一坐标适配各端和玩家iframe，减少动态保留静态落点。各端“视频设置”内提供互动屏蔽按钮。鸡蛋、送花发射与命中对齐音轨，花束另有命中后绽放和花瓣层，粑粑使用透明emoji图片；完整时长按去首尾静音后的音轨配置。头像裁剪保留拖动和缩放，选图后收起预设列表，按视窗高度缩放预览；“取消／确定”紧接缩放条，短屏首屏可操作。盒子网址入口当前文案见[盒子视觉](box-visual-design.md#网址与连接帮助)。

设置入口及权限按[当前设置规范](box-visual-design.md#设置与管理面板)；无倒计时权限不隐藏游戏设置。声音按钮采用图标并保留名称、状态和悬停提示，音频组件常驻以保留设置和播放生命周期。发言面板使用本页单列排布；保留毛玻璃与减少动态行为，接收端仅呈现声画，不叠加发言文字或行动者标签。色值、尺寸及音频参数是实施选择，用户依据见[美术偏好B04／B05及D10](art-preferences.md#盒子与端侧)。

射击最多三组独立槽位，第四组立即移除最旧一组的动画、音轨及尚未完成的准备；同事件不重复占槽。发言只播放最新一条，替换发言不取消射击；发言期间射击音轨压至30%，结束后恢复，混音使用总增益及软限幅。音频准备与声源确认采用接收后300ms启动限时，超时不补播历史音频，仍呈现完整静音动画；声画可播放时共用实际音频启动时刻。屏蔽、切后台、连接恢复和上下文更换立即清除本端播放，迟到准备结果不得复活。此次定向检查和实际渲染已通过，真实手机性能及人耳听感仍待验收；同步恢复边界见[手机同步任务](../tasks/mobile-room-sync.md)。

## 平台主题与资源基线

平台沿用明亮桌游主机方向，奶油／青绿／暖黄／珊瑚色、木质玩具与柔和材质作为既有平台语言，不是所有游戏的固定皮肤。8px间距、24px主容器圆角及具体色值属于既有实施基线，可按内容与真实渲染调整；信息、触控、对比与焦点下限不可取消。沿用本机Segoe UI／微软雅黑及本地图标，不新增联网字体。状态同时配文字或符号，不只靠颜色；常态说明简短，连接排障和实现说明按需展开，回退揭示、结束确认及保存失败原因保留。

位图插画优先采用已核验资源，SVG功能图标、二维码、精确文字、规则数字与角标由代码绘制；游戏组件按对应版本核验，不能用平台示意图反推规则。应用品牌图标与各游戏区分，正式资源、来源、派生、透明度和用途以[平台资源清单](../../assets/platform/manifest.json)为准，不倒改首轮素材数量或历史字节记录；生成与交接按[素材工作区](../../../TMP/TableMaxMaterial/AGENTS.md)及[imagegen职责](../subagent/imagegen.md)执行。

应用品牌沿用青绿陶瓷磁贴、奶油桌台／叠牌T形与细暖金夹层；`app-icon.png`保留1024×1024及真实透明外沿，ICO为16–256px七档，手机主屏图标180px，缩放保持alpha。原生EXE嵌入ICO，各窗口从实际EXE提取同一图标；网页标签、手机主屏入口和盒子品牌使用本地正式资源。历史生成数量、字节、提示词及验收不因文档整理改写。

## 测试与维护边界

普通启动使用实际节奏，测试模式只给房主隐蔽快捷键；快跑、省动效不能绕过授权、规则或保存。决定倒计时只提醒，设置与checkpoint分离。反馈归用户偏好并区分原话、明确采用与实施判断；最新反馈优先，但不覆盖规则、秘密、可读性、触控或减少动态要求。历史来源与原证据保留，不把本次文档整理视作新UI验收。
