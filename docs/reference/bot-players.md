# 电脑玩家（bot）规格

2026-10-12 更新。电脑座位、独立策略、Worker 调度和恢复已实现；宝可梦、现代艺术、电力公司、拉密、UNO与阿瓦隆均有各自的三档本地策略，互不导入其他游戏，随完整EXE预装。算法、权限与实际验证从[游戏索引](../games/README.md)进入；现代艺术的历史27场种子验证见[游戏规格](../games/modern-art/README.md#状态与验证)。产品范围见[需求基线](../requirements.md#55-电脑玩家与基础决策)，重要变更见[决策003](../decisions/003-bot-and-maintainability.md)。游戏 bot 是对局中的电脑玩家，与 `docs/subagent/` 的开发协作 agent 无关。

## 已确认范围

现代艺术最新人机反馈的实现与限制见 [独立人机策略](../games/modern-art/bot.md)：默认／豆包对已观察旧画作使用不同记忆容量和换轮衰减，豆包考虑下一轮，绝悟考虑全部剩余轮次，公开按估值跳价。遗忘不抹去当前授权场面和本人现金，也不授权绝悟读取对手秘密；参数不推广到其他游戏。

- 首版在盒子支持“默认／豆包／绝悟”三档人机；后续接入游戏至少提供覆盖全部游戏选择的默认策略，声明实际支持的等级，平台拒绝未支持等级。默认简单合法、豆包初步分析局势、绝悟全面评估授权信息下的当前选择；不承诺特定胜率或全知结果。
- 每款游戏独立维护电脑决策文件，和规则执行、独立计分分开。策略可以按实际复杂度拆成小文件，但应有清楚的统一入口和版本。
- bot 在本地服务端运行，随程序本地构建与打包；正式游戏不依赖云端模型、联网服务或手机 App。
- bot 与真人遵守相同的游戏规则、合法动作和信息权限，其决定与真人决定共用权威动作和恢复流程。

B01 已采用独立 TypeScript 模块的项目默认方案，理由、边界和非产品承诺见 [决策004](../decisions/004-phase02-game-spec-and-bot-file.md)。首版逐节点入口、策略版本／授权／恢复及异常见 [游戏人机规格](../games/pokemon-encounters/bot.md)。模板已有正式 bot 代码，首版宝可梦已有同样独立的策略入口。

## 三档智能与配置

| 等级 | 稳定值    | 决策要求                                                                                                         |
| ---- | --------- | ---------------------------------------------------------------------------------------------------------------- |
| 默认 | `default` | 使用轻量局势比较，覆盖全部合法玩家节点；具体取舍和记忆由各游戏规格定义                                           |
| 豆包 | `doubao`  | 根据本人授权信息与公开局面分析当前选择、后续收益和风险，具体算法由各游戏定义                                     |
| 绝悟 | `juewu`   | 在授权信息与游戏允许的可恢复记忆内进行更完整的局势评估和有界分析，按本游戏目标选择合法意图；不推定未知秘密为已知 |

这些是本地策略等级名称，不调用外部产品 API。未知暗牌、未来牌序与随机结果仍未知；“当前优解”指声明的评分目标及计算范围内最优意图，算法具体细节、覆盖及局限由每款游戏维护。等级之间的智能差异通过有明确策略收益的局面与固定种子对局验证，不能仅更名、增加延迟或以单局胜负认定强弱。

房主在大厅添加人机时选择等级，已入座人机可在座位设置调整；真人不接受等级设置。游戏进行中或结果页禁止改等级，原班回到准备大厅后可调整。公开座位投影包含人机等级，任何端均不得收到内部记忆。座位 `botDifficulty` 和快照 `bots[seatId].difficulty` 保存同一稳定值，初始化、Worker 调度、回退、重启与续局均保留；旧字段缺失按默认级规范化。读取未支持等级、座位与快照不一致或不兼容记忆时保留原存档并拒绝恢复，不偷偷降级。

## 电脑座位与交互

管理员管理电脑席位与等级；2026-10-04 盒子 debug 增加手机房主移除其他真人／人机及修改人机昵称。大厅直接处理，结束后移除原子创建准备大厅；进行中移除和改名提示先结束。昵称 1–24 字，允许重名，不随游戏回退恢复；手机房主不能移除自己。座位具有稳定标识、昵称和电脑标记，真人加电脑的总人数及开局条件以核验后的游戏规则为准。

盒子人机说明使用三档比较卡，由各游戏 `game-module.json` 的人机元数据生成包内 `web/details.json`，按当前选择或旧局的精确发行加载，注明本地运行、授权信息边界及名称不代表同名云端模型，不宣称必胜。源码中的 UI 说明入口按游戏保留，不能另维护与作者元数据冲突的公开详情。关闭手机加入不等于允许超过游戏人数；电脑不通过二维码取得玩家身份，也不向手机下发内部控制能力。

电脑参与对应游戏的准备和初始化选择，不能因没有手机而跳过选位、翻牌等步骤。只有准备与必要规则选择完成后才可进入相应阶段；界面显示电脑当前行动、等待或错误原因，动作结果在服务端保存后确认。

进行中新增玩家或切换真人／电脑控制者需要游戏明示支持并由房主执行。当前新增要求不自动授权随时改变对局人数；是否进一步支持中途接管在对应游戏流程确定时说明。掉线真人保留座位并等待重连，不自动转为 bot。盒子座位画面最多12人，实际开局人数按游戏规格限制；宝可梦首版六人属于用户授权的项目扩展。

实际游玩与快速测试共用策略：默认在开始计算前分别等待 1500／1800／2200 ms 和 40 ms，策略声明的立即动作与并发动作按[声明式调度](#声明式立即动作与并发密投2026-10-11)处理；等待不消耗随机源、不改变策略信息或两秒计算预算。模式由房主隐蔽快捷入口选择，普通启动 `play`；测试不播动效和声音。在线状态变化不能重置同一策略任务或误把取消视为异常，模式／分支／决策变化取消旧任务，真实计算超时仍安全暂停。入口与保存边界见[运行模式](phase-02-platform-spec.md#实际游玩与测试模式140)。

## 全部游戏选择的覆盖

“所有操作”指每个需要玩家作决定的游戏节点，包含本人初始化、普通行动、目标和参数、可选能力发动／放弃、强制能力的合法选择、其他玩家动作引发的被动响应，以及多步流程的后续选择。查看帮助、界面缩放、管理暂停／回退不是 bot 的游戏决策职责。

每款游戏维护逐选择覆盖表，至少写清节点与规则依据、可观察输入、动作及参数范围、简单选择方法、无合法目标的规则处理、预期结果和验证场景。已确认规则列明确策略，未知规则继续保留阶段缺口；不能用“选第一个”代替尚未定义的动作参数、信息权限或规则。

优先采用易解释、可独立验证的简单选择。合法动作和参数必须由规则／契约确定，策略不能通过试探未授权目标、读取完整牌库或调用秘密规则状态来筛选结果。规则自动处理的随机事件和结算由规则引擎完成，不伪装成 bot 策略选择。

## 授权输入与独立决策文件

游戏 SDK 提供受限策略上下文：该座位的授权视图、规则允许的可选动作／参数、当前决策标识及平台提供的策略随机源。该契约在第三、四阶段依据真实选择建立，实际接口与注册方法见[游戏接入指南](game-development.md)。

决策文件只返回动作意图，不持有数据库、连接、房主凭证或完整 checkpoint，不直接修改状态。服务端运行在同一进程不授予策略额外信息；管理界面的调试显示也不扩展正常 bot 输入。临时查看和策略记忆只保留游戏允许获知的内容，回退时按定义恢复，不沿用被撤销分支的额外记忆。

每个策略需声明稳定策略标识、版本、适用游戏／规则版本、输入与返回动作约定，以及是否有记忆、其普通数据格式和恢复兼容方式。当前默认独立 TypeScript 策略模块，B01 已落定；替换策略的构建和版本检查写入接入指南，不承诺运行中任意加载外部脚本。

## 调度、暂停与失败处理

1. 平台根据已保存权威状态判断当前有哪些电脑决策，绑定对应座位身份和当前游戏实例、阶段、修订／历史分支。
2. 生成对应授权输入并运行该游戏策略；多个待选玩家按规则允许的次序调度，单个座位不重复发起相同待决策任务。
3. 将返回意图送入统一校验、动作队列、去重和事务保存流程；保存完成后才能展示成功及推进后续选择。
4. 等待人类、暂停、回退或结束时，停止不再合法的调度；迟到结果再次校验决策与分支，不能替新阶段或真人提交。
5. 限制单次计算与连续自动推进，保留主机暂停／管理响应；策略异常、缺失或给出非法意图时显示安全原因并停止该次推进，不无限重试或偷偷切换策略。

正式策略计算由独立Worker执行，每Worker的V8老生代内存限制为32MiB，每决策2秒计算预算；准备等待不计入计算预算，也不新增真人行动时限。有效任务的异常或超时安全暂停，取消与迟到结果不记作策略故障。若设计回退策略，必须事先定义、验证并明确提示；不能为了掩盖策略错误直接修改游戏状态、越过规则或伪造成功。

## 随机、回退与存档

UNO 的抢按窗口使用规则可选 `botTiming` 契约给出窗口键与等待区间；调度器分别为所有待响应人机计时，动作仍串行校验和保存。延迟由实例／分支／窗口／座位及独立策略种子派生，不推进牌库随机源。暂停冻结剩余等待，恢复刷新当前提交水位；窗口关闭、回退、换实例取消旧任务，迟到合法竞争不算策略故障。未声明反应计时的游戏保留原单任务节奏，具体三档区间见 [UNO策略](../games/uno/bot.md)。

策略可声明纯观察接口 `observe({view,memory,seatId,difficulty})`。成功游戏／生命周期动作后，每个人机以自己的授权玩家投影更新记忆，与规则动作同一事务保存；不运行决定搜索、不读取完整状态。观察失败不提交动作或记忆，保存失败不留知识，回退恢复对应记忆，重启不补观察。宝可梦版本 2 内部记忆及三档遗忘标准见 [游戏人机规格](../games/pokemon-encounters/bot.md#记忆与计算预算)。

游戏的洗牌、抽牌与随机事件继续使用可恢复规则随机源。策略若随机挑选合法意图，应使用平台提供的独立策略随机状态，不直接依赖 `Math.random()` 或时钟，也不消耗未声明的规则随机序列。

电脑座位类型、策略标识／版本、恢复所需记忆和随机状态纳入存档。游戏 checkpoint 同时涵盖相关策略恢复数据，使相同边界和输入下的简单策略可复查。所有数据使用普通可序列化结构；定时器、运行对象、函数或计算中的 Promise 不入档。

回退作废旧任务与结果，恢复策略数据，再以新的递增修订／分支计算意图。座位身份和平台授权沿用既有不倒退约定，不能恢复旧网络身份或编号；策略观察和记忆按游戏边界恢复。结束后不再自动行动。

重启先完成存档兼容检查和权威状态恢复，再按房主恢复／暂停状态启动电脑调度；真人仍等待原有身份恢复。原局固定原发行的策略与恢复数据，`restoreOnly`不阻止合法续局；缺少原策略、版本不兼容或记忆无法恢复时保留原存档并说明所需版本，必要时提示使用包含原版本且支持存档格式的旧完整EXE，不默默改用另一策略重新随机或要求下载游戏包。

## 代码组织与适度封装

策略、规则和计分按各自职责独立；平台只依赖抽象策略契约，注册入口组装具体游戏和策略。具有生命周期的调度器和依赖适配可适度使用对象，简单策略可为纯函数，不能为了人机引入巨型继承树或将 UI、存档和规则塞进策略类。

代码组织原则见 [工程结构](architecture.md#面向对象与适度封装)。新增接口须有实际节点依据，不先建立空工程或改写已经归档的第一阶段验证记录。

## 声明式立即动作与并发密投（2026-10-11）

`BotStrategy`可选`testImmediateActions`用于测试模式微任务直接派发，`concurrentActions`用于同一规则`concurrencyGroup`的多人决策。现行阿瓦隆声明 `vote-team`（组队密投）与 `quest-card`（任务牌）：测试直接启动全部待密投计算，不设置0ms或40ms准备等待；微任务派发标记与取消检查防止重复启动。实战各席同时开始本等级1500／1800／2200ms等待，随后独立计算并提交，不等待上一席封票。未声明游戏仍沿用原40ms测试准备与原顺序，UNO声明的抢按计时另按自身窗口处理；已有`immediateActions`发言确认不变。

稳定任务身份包括实例、规则／包、分支、模式、决策组及窗口底水位、座位、源策略数据。同组其他席保存不取消剩余计算；旧水位结果进入串行保存前仍核验本人授权和源数据，随机状态仅保存成功后更新。暂停、回退、模式切换与阶段结束取消旧任务，真实当前任务异常／超时安全暂停，取消及迟到不报策略故障；32MiB与2秒预算保留。
