本页维护当前构建、运行、安装与恢复方法；精确CLI全文只在对应[工具README](../../tools/README.md)维护，证明要求见[验证](validation.md)，当前交付及未测边界见[验收](acceptance.md#当前源码与本地交付)。原入口及历史标题保留为导航。

## 服务载荷无损压缩

构建辅助`tools/build/service-brotli.mjs`以Brotli质量11编码生产CJS，只有精确还原且净节省时才接受；小型CommonJS入口与`.cjs.br`载荷共同进入缓存、冻结、组装及封包。启动先核载荷SHA，再按限定输出长度解压并核原源码长度／SHA，最后在当前模块内`_compile`；缺失、损坏或哈希不符直接失败，不在存档、缓存或程序目录落盘还原源码。

该步骤应用于platform-server与宝可梦人机单元，helper纳入相应指纹；白名单和游戏预算同时计入入口及载荷。官方Node PE不压缩、裁剪或升级，其它游戏策略、规则、Worker和媒体不因该步骤改变。回归要覆盖原字节、CommonJS路径／exports／require.main、依赖、无落盘、缺失、压缩损坏及合法压缩但源码哈希不符；宝可梦实际生产Worker仍须满足32MiB与原2秒取消边界。命令归[构建工具](../../tools/build/README.md)。

历史隔离收益、缓存命中、同包运行和失败按[原验证记录](../archive/validation-before-consolidation-2026-10-23.md#服务载荷无损压缩2026-10-06)阅读，不以估算字节代替当前包大小，不把历史运行通过追认为新包通过。

## 唯一完整 EXE 交付（2026-10-12）

完整程序由冻结载荷直接封装为installer，不把旧自解压EXE再套入安装器。旧便携原件按自身字节及历史证明保留；改造过程见[安装归档](../archive/windows-installation-update-2026-10-15.md)。

日常构建只导出预装全部正式游戏与玩法的完整EXE；游戏仍按模块增量构建。预装仓库缺失或损坏时只从该EXE的本地签名载荷修复，初始化失败保留原数据并明确报错。旧安装仓库继续供原局恢复；不再提供独立游戏下载、ZIP导入或游戏更新，整个程序更新继续维护。当前命令如下，发布与恢复边界见[Release流程](release.md#完整安装器与免费应用签名2026-10-15)。

新构建先生成候选并保留原current；重封已冻结载荷不重新分配修订。候选、重封与推广命令统一见[发布工具](../../tools/release/README.md)，版本分配见[Release流程](release.md#三位公开版本与四位本地构建2026-10-12)。不接受旧edition选项，内部游戏输入必须完整。

本页现行构建与验证按实际载荷参数使用；标为旧双版本、Pages和独立安装的章节仅追溯原实施，不执行退役命令。

内部签名模块由完整打包入口检查或生成；历史模块仓库只供精确原局恢复，不提供独立导出、目录更新或导入。

实际载荷复用、逐成员核验和源码／包内夹具区别统一遵守[验证](installation-validation.md#完整安装与程序更新的证据分层)；同包物化入口见[测试工具](../../tools/test/README.md)。

candidate以dontcopy内嵌，在 PrepareToInstall 显式提取并同步完成helper提交与健康确认，成功后才允许Inno写框架／登记；准备拒绝的标准外层7与helper健康40分别记录，不用AfterInstall异常充当原框架保全门禁。

安装进度与同一准备事务同步：展开载荷、前置检查、保存关闭及健康等待等总量未知阶段使用marquee，不估算百分比；snapshot按实际已检查的原成员、stage按已复制并校验的新成员、switch按已完成切换或移除的成员递增文件计数。各阶段独立计量，不把文件数量当字节数或整个安装百分比。进度页在提取／提交前显示，成功或异常均在finally关闭；可选进度输出不改变健康、保存、退出码或框架登记门禁，协议见[安装封包工具](../../tools/release/README.md)。

此布局作为v1.0.7及以后兼容基线；不为未发布18增加升级兼容层。历史布局与各自证明按[验收](acceptance.md#当前源码与本地交付)保留，不能从路径兼容推定旧程序的更新协议兼容。仅当前用户安装。首次默认位置为Inno的 `{src}\TableMax`；用户另选的目录就是最终安装根，不再次追加产品目录。升级／修复沿用已登记安装根，不按安装包新位置搬迁；安装页显示「不推荐安装在C盘，因为这是一个有良心的安装包」。可另选可写目录，也可在可写的C盘目录安装，不自动搬到其他位置。安装根 `I` 内的稳定入口为 `TableMax.exe`，更新入口为 `Updater.exe`，事务协调器为 `UpdateHelper.exe`，卸载器由框架生成；桌面快捷方式可选，开始菜单含启动与卸载入口。首版只支持同一用户一份受管理安装，持久身份绑定安装用户SID，不能只靠HKCU或当次互斥认领原安装。

桌面任务使用 `checkedonce`，升级默认不重复创建桌面入口；卸载日志使用 `UninstallLogMode=append`，保留首次安装已登记的owned快捷方式记录。升级时未再选Desktop也必须能在最终卸载中删除该已归属入口，不能用overwrite丢弃原记录；这不改变 `PrepareToInstall` 健康成功后才写框架／登记的门禁。

配置根 `B=I/data`，运行资源为 `B/app`，当前及历史模块为 `B/games`。配置 `TableMax.config.json` 默认 `dataDirectory:"."`，数据根 `D=B`；外置 D 保持原指针，更换配置仍在重启后生效。目录不可写直接报错，不回退 C 盘。受管理身份 `.install.json`、实际外层摘要 `.installer-receipt.json`、更新暂存和事务只用于程序核验，不能作为删除任意同目录文件的依据。

`Updater.exe` 双击先显示中文启动反馈，再通过 `--check-updates` 打开主机原生盒子的「程序更新」面板；已运行时仅唤起同用户、同安装实例的面板，重复点击聚焦现有窗口，不关闭游戏。`UpdateHelper.exe` 无参数打开时给出中文引导。可信同版明确显示「已是最新版本」，可信远端旧版单独说明，不降级；网络、签名及发布描述失败分别报错，不能当作最新。面板提供主动检查、发布页、下载进度／取消及明确重启更新，不自动应用、不提供手动在线降级。普通浏览器、公共屏和子frame没有原生更新权限。下载期间可以继续使用，未验签或失败的文件不执行；应用更新在服务串行队列确认无playing对局后同步拒收、排空、保存并关闭，再取得实际Stop确认与原Native退出码0，才调用同一个完整installer升级原目录。保存失败、超时或失联时明确停止更新并安全退出旧盒子，不能留作“可更新”或启动helper提交。稳定入口无需再次解压另一份自解压载荷，健康确认核对实际新Native／Node、I/B/D、安装实例、四位版本及当前映射。正式成功后保持新版普通主机运行。

更新执行在保存关闭前，把已核验helper和完整installer原字节复制到当前用户实际TEMP中新建的私有短目录，绑定安装身份、原签名目标及双副本SHA后再交接。该临时副本不改变I／B／D／G，也不把数据移入TEMP；原下载和B内审计记录保留。原因是.NET Framework使用的[CreateProcessW空applicationName形式](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)仍限制命令行中的模块路径长度，内部文件IO支持长路径不代表可以从同一路径启动EXE。TEMP本身过深或为磁盘根时须在关闭服务前报错，不改系统长路径策略或已有目录权限。停止与更新交接还必须在发出关闭请求前持有原进程句柄，直到核验正常退出码后才释放，避免进程退出后只凭PID无法取得退出状态。证据须记录实际进程句柄查询的短helper／installer模块路径、PID、原件／副本及元数据／审计rawSHA，不能把计划路径当实际启动证明。具体证据要求见[验证](installation-validation.md#完整安装与程序更新的证据分层)。

后续本地启动在`ApplicationUpdate`构造读取真实信任根与安装receipt后同步调用`InstallationLaunch.CleanupFinished`，不联网、不等待或终止helper。只由本安装B的`handoff-UUID`记录索引私有TEMP，要求同安装实例／SID／根、全部安装事务终态、原RSA目标与各自已完成事务清单／receipt及旧helper／元数据／审计SHA匹配。历史成功目标不高于当前版本也可清理；目标就是当前版本时，另核清单全字段及receipt原字节一致。运行中、pending、链接、未知、篡改及已有清理记录（包括中断的prepared）保留。清理前先取得全部已知文件的独占原句柄并核SHA，再按原句柄删除TEMP的h／存在的i／元数据和B旧helper，最后删除已空私有目录；B公共审计、签名描述及handoff保留，`cleanup.json`记录阶段与精确元组。canonical大下载保留并单独计缓存，不冒称已回收；不遍历整TEMP、G或D，不修改既有ACL或系统策略。组件与实际下一启动分别按[验证要求](installation-validation.md#完整安装与程序更新的证据分层)记录。

安装验证的层次、三链与正式GUID／迁移要求统一见[验证](installation-validation.md#完整安装与程序更新的证据分层)；fixture模式、固定步骤和参数统一见[测试工具](../../tools/test/README.md#完整安装与程序更新验证)。

深路径WebView2启动调查与原方法范围见[整理归档](../archive/tooling-delivery-organization-2026-10-15.md#深路径webview2启动调查)。不承诺任意深I／D在所有依赖中可用。

手动升级、盒子升级和卸载共用安装互斥与准确实例停止；更新／恢复不能用卸载停止语义绕过进行中对局。迁移和程序暂存期间持有数据库组文件租约，从已持有流复制并核验；服务先取得foundation库全生命周期SQLite独占，合作旧入口或其他会话抢先占用同D时拒绝启动，不能只凭旧Local互斥保证跨会话安全。事务记录preparing等阶段与两库、sidecar、journal及迁移标记共10成员指纹；数据库已经变化时保留目标程序和原数据，重新确认同一目标，不自动启动旧程序读取新数据。

普通修复按可信完整候选保全损坏的已归属旧文件。pending且数据库已变化、当前身份与目标一致时，只有完整安装包的 `--commit` 可修复缺失／损坏的协调器：候选的完整文件集合及摘要、目标身份、当前与目标receipt、实际源installer及正在执行的helper必须精确匹配；同版本或相同helper摘要不能替代全载荷一致。通过路径、链接、未知成员、大小、运行互斥和数据库租约检查后，只替换协调器，原坏字节与实际SHA保存在独立修复日志中；不重写D/G/config、安装身份或原pending目标。`--recover`不从其他来源补文件；目标的其他载荷仍有缺坏时保留事务并明确拒绝健康确认，可默认卸载保留数据后重新安装同一或更高完整包。

每份卸载框架编译时内嵌自身固定SHA的helper，不依赖live helper是否存在或已升级。Base64严格检查字母表、末尾填充／低位和精确长度，在锁定PascalScript中以8位 `Chr` 写入 `AnsiString`；生成配方绑定原helper及include的字节数／SHA。解码后先核内存SHA，只在本次新建私有临时目录写文件，再核文件SHA后执行原 `--uninstall`，finally只清理本次文件和空目录。卸载仍检查安装身份、未知程序成员、链接和受管文件大小，缺失文件不捏造隔离副本，损坏文件按实际SHA精确保全，D/config及未知额外内容保持；游戏资源按下述引用闭包清理。全字节解码探针、完整框架编译、实际跨PE失败后卸载是不同证据层；当前结果见[验收](acceptance.md#当前源码与本地交付)，构造日志不称为真实断电验收。

Inno卸载分两阶段；首段退出0不表示原EXE已自删除或日志已关闭。验证器的有界完成观察要求见[验证](installation-validation.md#完整安装与程序更新的证据分层)。

默认卸载在保存关闭成功后移除受管理程序、快捷方式和当前用户登记。helper持有数据库组租约，从私有只读快照解析全部存档与checkpoint的固定发行，计算代码／资源及共享blob依赖；只有签名当前目录精确授权且未被保留发行引用的资源可删。历史依赖、配置、存档、外置数据、未知文件及不能可靠解析的依赖保守保留。删除使用核过大小和SHA的原文件句柄；`B/.uninstall-resources.json` 与唯一审计目录的receipt记录逐项已删除、因依赖保留及未知保留，空受管资源目录移除。partial不能声称清理成功；没有删除用户数据选项。

在任务页勾选「是否进行版本迁移」后才显示迁移页，默认不勾选。自动发现安装包同层的TableMax目录，否则留空；返回页面保留手工输入，取消勾选不传隐藏参数。静默调用仅通过显式迁移参数启用，同样核验有效配置。默认数据与G复制到新B，外置数据保留原指针，原件不删除。仅允许源配置根正好为I、目标为I/data这一父子重叠；创建data前冻结源文件清单，排除运行程序、更新事务及目标data，按冻结清单复制和校验。其他重叠、链接、运行中源或非空目标拒绝，失败保留原数据。旧局继续固定原发行，缺失时保留存档并提示所需旧完整EXE；新局只使用当前包的核验映射。

安装层对产品生成的长事务／临时路径使用预检、短归属临时名及受限内部IO转换；用户身份仍保存规范普通路径，设备前缀／UNC别名不能绕过系统目录拒绝。不修改机器LongPathsEnabled或安全策略，也不承诺任意超长I/D在全部Native、WebView2及Node依赖中可用。

## 环境与依赖

Node.js 开发约束为 `>=22.14.0 <23`，`.node-version` 记录本次验证版本；pnpm 固定为 `10.12.1`。没有修改本机全局运行时或其他项目配置。依赖清单使用精确版本，`pnpm-lock.yaml` 锁定传递依赖；后续安装使用冻结锁文件。版本升级应作为单独改动验证。

当前桌面采用 C# WinForms／.NET Framework 4.8、共享 Evergreen WebView2 和包内 Node `22.14.0` x64；开发 .NET SDK `9.0.102` 固定在 `global.json`，WebView2 SDK `1.0.4258.31` 与编译引用程序集固定在原生项目及 `packages.lock.json`。Windows 11 内置兼容的 .NET Framework；开发和运行电脑需安装 WebView2 共享运行时，缺失时程序提供官方安装入口及取消。

### Node 运行与防火墙规则

用户 2026-10-04 要求减少反复手动允许 Node 访问网络，后续运行、验证及脚本维护按以下规则执行。本节是执行约定，不代表已经配置系统防火墙或改造全部验证脚本。

- **启动前确定网络范围**：区分本机截图／UI／规则／恢复验证与局域网可达性验证，核对实际 Node 路径、监听地址和端口。普通 Node 命令执行不等于需要网络放行；Windows 防火墙提示与工具执行审批、管理员提权分别处理。
- **本机检查默认回环**：启动服务时显式设置 `TABLEMAX_HOST=127.0.0.1`，隔离存档与浏览器数据，验证可用 `TABLEMAX_PORT=0`；其他预览或辅助服务器也只绑定回环。电脑和手机模拟页面均可访问回环服务，不能仅因模拟手机尺寸就监听 `0.0.0.0`。已满足要求的入口不重复改造。
- **仅局域网验收开放网卡**：实际网卡 IPv4、手机连接、二维码地址或网络故障场景确需验证时，才监听 `0.0.0.0`／指定网卡，记录目的、Node 路径、端口与证据。现有 `verify:party` 包含实际网卡验证，不能改为回环后仍声称该场景通过；随机端口验证不得冒用正式端口的放行结论。
- **日常运行保持路径稳定**：开发使用固定构建入口，正式游玩从固定便携目录启动，更新沿用该目录并保留规定的历史包与证据。避免从每次随机解压的位置启动日常局域网服务。便携包隔离解压与验证仍使用该包自己的 Node，不能借用外部运行时替代包内验证，或复用正式存档来减少提示。
- **一次配置必要的入站规则**：用户明确授权修改系统防火墙后，使用 `wf.msc` 的自定义入站规则，指定实际 `node.exe` 完整路径、TCP 和实际监听端口；正式端口为 `38473`，仅适用“专用”配置文件，远程地址限制为“本地子网”。可信家庭／聚会网络可由用户设为专用；不自动把未知网络改为专用。路径或验收端口变化时先核对现有规则，再按授权更新，避免为每个临时副本新增永久规则。
- **提示重复先定位**：比较本次 Node 完整路径、活动网络配置文件、监听端口以及匹配的允许／阻止规则；曾拒绝提示留下的阻止规则也需核对，不以不断点击允许或重复新增规则代替诊断。不要关闭防火墙、全局放行 Node、公用网络或所有端口；仅关闭通知不能解决手机入站连接。网络测试确实受阻时说明未通过范围，不伪报通过。
- **保留系统与产品边界**：规则文档更新不自动授权修改系统设置。普通游戏仍按既有默认监听提供手机联机；本机验证的回环覆盖不改变正式产品行为。临时系统规则如获授权创建，完成后按约定撤销，保留原有规则和用户设置。

Windows 程序规则按完整可执行文件路径匹配；专用网络和本地子网范围依据 [Microsoft：Windows 防火墙规则](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)。稳定路径可减少重复授权，但不能保证消除网络配置变化或既有阻止规则造成的提示。

## 便携包体积与共享运行时

打包记录唯一EXE与内部payload的字节数和SHA，实际提取后逐文件比对；任一硬门禁达到上限立即失败。manifest在 `artifacts/package-payloads/v<公开版本>/<run>/full/release-manifest.json`，`current.json`绑定载荷、EXE及本地清单。内部 `full`保留为兼容键，不代表还有盒子版。系统共享运行时、用户存档和浏览器缓存不计入交付，缓存写入所选数据目录。缺WebView2时提示安装或取消；程序提取及预装验证完成后，游戏使用本地资源与局域网服务。

内部模块自身预算和依赖闭包继续校验；历史单玩法64,000,000字节传输／安装门禁只说明原独立包体系，不再提供用户游戏下载或安装。原局固定发行仓库保持，当前完整交付与旧版本故障边界见[验收](acceptance.md#106唯一完整-exe2026-10-12)，共享运行时理由见[决策008](../decisions/008-small-native-desktop.md)。

组装、发行和每个单元分别互斥；程序占用时拒绝替换。暂存目录完整验证后替换开发目录，失败回滚；完整EXE与清单／内部载荷按事务保护发布，失败保留旧当前交付。缓存中的有效单元可独立重用，不复用 ZIP 压缩条目，也不提供用户侧差分更新。

缓存维护先运行 `node tools/maintenance/clean-build-cache.mjs` 预览，再 `--apply`。仅处理专用构建缓存：保留当前开发快照、当前发行引用、活动锁／任务及每单元最近两份成功产物，另保留最近30分钟。删除前再次核验绝对路径、链接、单元清单哈希和空闲状态；不涉及依赖缓存、素材、存档及验收证据。

预算清单分别记录交付字节、服务堆、电脑／手机渲染堆、应用进程私有内存增量。现有游戏按独立文件实测×1.10、三次场景峰值最大值×1.25向上取整至MiB，仅初始化一次；`tools/analysis/budgets/game-budget-report.mjs --initialize` 拒绝重复初始化，常规报告只警告超限并记录整改，不自动上调。`tools/analysis/memory/measure-game-heap.mjs` 测量真实完整对局服务堆与最高等级Worker，验证脚本可用 TABLEMAX_BUDGET_TRACE／TABLEMAX_BUDGET_GAME 采样隐藏WebView2；采样峰值不称为分配分析器最大值。Worker32MiB老生代与2秒截止仍独立存在。新游戏开始开发前须填写预算与依据。

缓存回归使用 `node tools/build/verify-module-build.mjs` 和 `node tools/build/verify-cache-failures.mjs`；前者会完整组装及建立临时验证游戏，须在运行／其他验证进程退出后执行。

清理空闲判断区分带项目工作目录的Codex常驻工具解释器与实际工程子进程：只有已识别的Codex自带Node及kernel／trusted-worker引导不计作工程占用，未知Node、实际构建／验证及原生进程仍阻止清理。`tools/maintenance/verify-cleanup-idle.ps1` 用真实判断函数验证六种进程清单，不执行删除。本次首次清理因该误判被保护拒绝，修正后按原路径、近期修改、已验ZIP及哈希保护顺序重新执行。

### 构建与缓存要求

- 平台及各游戏提供独立构建入口；按规则、人机、网页和资源的实际依赖判断受影响部分，未变部分可复用。新增入口不得清空其他模块输出。
- 输入指纹覆盖源码及传递依赖、相关资源与清单、SDK／协议／宿主契约、构建配置、锁文件和工具链版本。共享项变化按依赖传播失效；不能只以修改时间或游戏目录内容判断。
- 缓存产物记录输入指纹、模块及契约版本、文件路径／大小／哈希；缺失、损坏或不兼容时重建或明确失败。构建成功并校验后才发布缓存，失败不覆盖已有有效产物；保留可用的完整重建入口。
- 并发构建使用隔离输出，组装只读取已完成且固定的模块清单和产物快照；组装期间变化即拒绝混用。统一组装步骤独占发布路径，不允许多个任务同时覆盖 `build/desktop` 或最终 release。

### 组装与验收要求

优先复用模块产物目录，汇总全部正式游戏为完整运行目录后生成内部payload ZIP并封装唯一EXE；压缩条目复用仅在测量表明确有收益后另行实现，并正确生成 ZIP 目录结构。构建缓存、压缩缓存和用户侧差分更新分别处理，后者不属于本次需求。Node、共享网页运行时和通用组件不重复装入各游戏块。

验收至少覆盖：单游戏变更只重建其受影响部分且其他模块哈希不变；共享契约变化使全部相关模块失效；资源变化、删除和重命名无旧文件残留；缓存损坏／缺失、构建失败及并发输出不造成混合包；不兼容模块被拒绝；同一输入的增量组装与干净全量构建的交付文件一致（确定性文件按哈希比较，必要的生成元数据差异明确记录）。

按影响执行源码检查，再对同次冻结输入的完整EXE验证盒子、全部正式游戏／玩法可用、受影响游戏行为、跨游戏切换、身份权限、旧局精确恢复和本地资源。实际提取逐文件核对内部清单；EXE、payload和提取内容均严格小于120,000,000字节，工程预警110,000,000字节。记录构建、命中、组装、压缩和验收耗时，模块缓存不替代交付验收。日常只导出完整EXE，第四位按一次对话中的交付更新递增一次，失败及检查未通过的中间构建不占号；具体规则与工具适配缺口见[版本流程](release.md#三位公开版本与四位本地构建2026-10-12)。公开版本不自行递增。

## 游戏包构建与运行隔离（2026-10-11）

2026-10-11安装器修复：异步文件移动结束后的索引合并与原子提交之间不再有await，合并最新索引以保留其他已完成安装和管理动作。`.transactions/<事务UUID>.json.<原子UUID>.tmp`是尚未改名的写入副本，恢复只清除该普通文件及同事务stage，不解析其未完成内容；其他未知名称及链接仍拒绝。故障驱动按准确操作／路径及局部次数注入，全局序号只作诊断；签名坏包重试须恢复合法签名目录及合法正文，不能只切换HTTP响应。限定补验与证据见[验收](acceptance.md#106安装索引并发与临时journal恢复修复2026-10-11)。

运行 `node tools/release/game-packages.mjs --key=<受保护私钥路径>` 生成独立代码／资源 ZIP、签名目录及完整玩法离线 ZIP；单游戏加 `--game=<id>`。私钥默认由 `TABLEMAX_GAME_SIGNING_KEY` 指定，禁止提交、复制进运行目录或输出日志；当前本地配置 `secrets/game-release-ed25519.pem` 受 Git 忽略和当前用户 ACL 保护，程序只内置公钥。`node --import tsx tools/release/verify-game-packages.mjs` 检查签名、闭包、逐文件哈希和资源独立指纹。

单游戏 `node tools/build/build.mjs --only=game:<id>` 只读取目标游戏与公共依赖，输出到独立缓存；同时开发不组装中心运行目录。并发构建检查 `tools/build/verify-concurrent-games.mjs`，作者接入检查 `tools/author/verify-author-platform.mjs <冻结平台目录> <独立证据目录>`。最终组装／便携打包必须等待开发服务与浏览器退出。检查保持历史低通过率排序，失败停线遵守[统一阈值](validation.md#历史通过率与失败阈值)；修正后只重跑受影响项。

安装数据通过私有配置 `gamesDir` 明确指向便携根 `games/`，不依赖当前目录，也不回退 C 盘。管理员使用游戏库的包管理刷新、更新、导入、取消、设为选局版本和卸载；原生导入经受管文件选择器，浏览器管理员可选择离线 ZIP。各端只访问主机网页／资源；资源 URL 含固定发行哈希。缺包时仍启动盒子，数据库原样保留，补齐原包后暂停恢复。

维护保护扩展至安装仓库、签名缓存、当前交付游戏包与开发工具包、`.legacy` 原包和 `.quarantine` 恢复证据。它们不属于可整目录清空的验证副本；只在核对全部当前局、存档／journal 和清单引用后退役。`artifacts/game-packages/v1.0.6/` 按签名目录明确引用的文件交付，旧候选不列入发布白名单。
