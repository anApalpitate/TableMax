## 按变更范围选择检查

正常加入、改名及布局测试的昵称统一遵守现行上限：最多8个中文字或16个半角字符，混合计长；半角ASCII计1，其他可见字素（含全角、表情）计2，总计最多16。长度与合法性以`packages/protocol/src/names.ts`的`playerNameLength()`／`playerNameError()`为准。边界布局分别覆盖8字中文、16字符无空格英文及混合名称；不要用旧24字符夹具冒充当前合法输入。超限拒绝、归一后超限及旧存档恢复用例仍可保留超限名字，但须明确测试目的；历史报告保留其原输入与结果，不随夹具缩短改标为新验证。

除非用户明确要求本次构建新导出包，默认源码单测、源码浏览器夹具或直接服务测试，不依赖安装器；源码环境失败不自动转封包／安装。只改盒子只选盒子，只改游戏只选对应游戏；共享变化先列实际依赖再选共享及对应游戏。纯文档／配置／素材记录只选格式、链接、配置、来源或解码等适用检查；不因其他工作区改动扩大范围，也不把规则改动自动扩成UI矩阵、UI改动自动扩成自然整局。

范围由`tools/test/runner/scopes.mjs`实际注册维护，包括box、shared、tooling及各游戏；混合项涉及的全部范围都须获准，不能只有交集。窄范围排除未分类项并报告缺口，未知独立脚本先登记或实现真实筛选，不向不支持过滤的脚本虚加参数。只有确实影响全范围或用户明确要求时才选full。准确测试文件可继续收窄，流程、钩子及保存边界不能因筛选省略。

选择、执行、证据导入、预览与严格只读查询分开认定：范围入口可能写选择报告，即使不启动产品也不等于只读；纯查询使用已核验的纯选择接口，不能为观察范围顺带写账本或启动服务。具体操作见[范围入口](../../tools/test/README.md#开发环境操作按变更范围选择检查)。原生几何、源码夹具与实际服务测试各用适用方法，不因脚本名判断覆盖范围。

## 内容绑定的验收计划

统一入口新增version 2计划，version 1和直接Vitest命令保持兼容。先审阅计划预览（`--list`可写选择报告，不等于严格只读）；新计划默认复用完整通过证据，`--force`强制执行选中项。`--changes=<文件>`只消费本任务路径及当前SHA-256，不自动读取全部工作区diff；清单为`{"version":1,"files":[{"path":"仓库相对路径","sha256":"当前内容SHA-256"}]}`，已删除路径使用`null`。变化清单过期即停止，不能把其他任务改动记成本任务。

每项仍明确`id`、`runtime`、`script`和`args`；`runtime`可选node、powershell或vitest。输入用`inputs.files`、`inputs.directories`登记，源码静态依赖自动展开，目录成员增加／删除也改变指纹。动态读取、Worker入口、PowerShell点引入、资源及旧报告必须显式登记；完成依赖审查后才能标记`inputs.complete:true`，缺口项执行但不缓存。`combination`登记游戏、玩法、人数、控制器／难度、种子或局面和验证类别；固定局面、快速自然整局、普通节奏检查点及完整自然整局不能互用。Vitest仅允许准确测试文件及`--testNamePattern=`，保持生命周期和失败统计。Node额外启动参数仅允许允许的tsx导入或Node测试选项，具体写法以工具入口为准。

计划先检查范围，再按历史低通过率排序；相同内容、方法、参数与组合合并，报告保留全部选择来源。输出逐项执行／复用／不适用及理由。复用不会增加attempt或通过率分母。Vitest可加入父轮次的累计失败账本；独立脚本仍以命令为一项，不从退出码推算其内部用例统计。达到[统一失败阈值](#历史通过率与失败阈值)后停止派发，保留未执行项；修复后按该节规则新建轮次定向复验，无变化不自动重试；本轮不启用执行并行。

证据索引在`artifacts/maintenance/test-history/evidence/<内容指纹>.json`，运行计划及原始证据在`test-history/runs/<轮次>/`。绑定输入字节、方法与助手代码、参数、Node／OS／架构、声明的环境变量及运行时文件；`environmentProviders`支持实际PowerShell与WebView2版本查询。现行EXE只使用full，自动绑定实际交付、EXE、payload和manifest，并要求WebView2环境绑定；box只供原历史交付。安装候选显式读取candidate交付，不从尚未推广的current推定候选身份。EXE改变重新执行其实际受影响验收，未变且完整绑定的规则／游戏证据可按原范围复用，不能替代新基础程序接入检查。

检查执行前后重核输入。复用前核对全部日志、报告、截图等证据哈希，缺失、失败、未完成、损坏或环境不符均拒绝；`resultFile`可要求本项输出目录中的通过JSON，`evidence`可登记其他精确报告路径，旧文件没有刷新不算本次证据。审计导入只接受原始报告已证明的绑定及原文件SHA，不能以当前字段追补旧方法／环境；目前旧整局缺字段时继续保留原历史结论，不导入自动缓存。

同一EXE会话助手顺序执行相关界面，并核验管理与玩家的会话及Cookie隔离。旧助手对主机／公共屏／玩家使用独立native partition，保留原版本范围；当前默认原生入口已迁移为管理窗口专项，不再以公共屏partition存在作为新版本通过条件。未运行的历史完整矩阵不得借此升级为通过。首次、重启、迁移、异常退出与不同edition仍独立。回环下载夹具使用生产PackageStore和人工签名小包，记录真实接收字节、请求头／正文EOF及安装总耗时；模拟故障、已安装缓存命中和真实线上下载分别记录。源码夹具、隐藏窗口、模拟视口及三个事务注入点不能冒称实体设备、真实磁盘满或完整故障验收。

version 2子检查关闭各自自动维护，父轮结束只尝试一次。多阶段属于同一任务时设置`TABLEMAX_AUTO_MAINTENANCE=0`，最后统一一次既有安全收尾；若已删除，不追加第二轮。当前唯一完整EXE从实际指针／候选记录精确读取适用报告，不扫描历史目录；缓存预览清单由SHA绑定供Apply消费，删除前仍重查进程、路径／链接、锁、引用、近期修改及成员SHA。

version 1独立项仍须显式id、runtime、script及args数组（无参数也提供空数组），不会自动获得version 2复用能力。版本、参数、返回字段和实际命令以[计划操作入口](../../tools/test/README.md#开发环境操作内容绑定的验收计划2026-10-11)及实现为准；不另建一份脚本注册表或统计库。

## 历史通过率与失败阈值

所选Vitest测试已接入逐项历史统计：通过率为累计通过次数／累计完成次数，同时保存分子、分母与百分比。身份由测试类型、Vitest项目名、仓库相对文件路径及完整组／用例名称组成；独立场景使用稳定且唯一的名称，改名或移文件会形成新身份。范围字段不加入身份，不重置历史。历史库在 `artifacts/maintenance/test-history/history.sqlite`，跨版本及重启保留，不随版本导出或历史截图退役清空，也不进入运行包。每轮明细在同目录的 `runs/<随机运行编号>.json`；SQLite事务保证并发写入与重复回执不会重复计数。

先按改动选择相关测试，文件按其中最低历史通过率排序，文件内按组及用例递归排序，保留 `beforeAll`／`afterAll` 等钩子的原作用域。同通过率保持声明顺序；已失败的0%项优先于未知项，未知项优先于已有通过记录的项。为确保达到阈值后不会抢先启动其他项，本入口串行执行文件和用例，关闭无变化的自动重试。每轮默认累计失败10项即停止派发后续检查，轮报告退出码非零，保留全部旧账本、原始输出和未执行项，转入依据证据修复。阈值是本轮累计失败数，不是历史失败数或连续失败数。旧阈值演变保留在整理前原文。调整不清零原失败，旧阈值下已停止的执行须先修复，再定向复验受影响项，不能借阈值变化直接重试未修复的问题。历史按3或5失败停止的原记录保持原事实。

有实质源码／方法修复或针对失败原因的环境纠正后，记录原因、变更输入及受影响范围，自动建立独立预算的新轮次并定向复验；新轮关联原轮账本和证据，旧失败仍保留在历史及通过率分母中，未执行项继续明确列出。用户已授权范围内不为另开新轮再次询问；确需新增权限时才询问。没有实质变化不得仅换轮次盲重试，不得放宽断言、扩大范围或跨越权限。未受影响且完整绑定的已有证据继续复用，不能重复全套检查来替代定位，也不能省掉受影响的必需验收。

一次完整结束的用例调用计一次，跳过、取消和未开始的用例不计入分母；失败的收集／模块或组生命周期单独记录，不能把未运行的测试正文补记为失败或通过。显式用例 `retry`／`repeat` 的最终调用结果计一次，重试／重复次数另留诊断，不自动添加重试。运行器未捕获的错误留在本轮报告并使本轮失败，不伪造有名称的用例。默认 reporter 与自定义 runner 配套使用，使用CLI自选 reporter 时须同时保留 `tools/test/runner/vitest-history.mjs`。

独立脚本一个计划项计一次命令完成，内部矩阵不能从退出码反推逐场景次数；启动失败、异常结束和非零退出均计失败。批次串行、隐藏、默认静音；范围排除及未执行不计次数，原始stdout／stderr、运行明细与未执行项保留。没有逐项结果的旧汇总不能推算次数，完整逐项Vitest原报告才可按原方法导入。隔离统计仅在项目内部，不改系统环境；复用不增加统计。底层批次API供工具夹具，日常通过范围入口，操作见[历史统计与阈值](../../tools/test/README.md#开发环境操作历史通过率与失败阈值)。

## 证据类型与历史可用性

| 材料                         | 能证明什么                                             | 不能自动证明什么                                               |
| ---------------------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| 单测／组件与源码夹具         | 该冻结源码、输入、状态与方法下的检查                   | 真实服务、完整对局、最终EXE、实体设备                          |
| 真实服务／Socket／SQLite     | 被实际执行的权威动作、身份投影及保存／恢复路径         | 浏览器实际可操作、完整安装及真实网络设备                       |
| 隐藏浏览器／WebView2模拟视口 | 实际运行画面、几何及声明的交互；保留运行时差异         | 实体手机／Safari、物理DPI／电视、人耳听感                      |
| 完整原EXE安装链              | 同一冻结原件、正式身份、原路径、账户隔离及其实际执行项 | 新源码、新EXE、所有游戏或未执行故障；不能仅靠解压或fixture替代 |
| 历史记录／退役清单／附件备份 | 原日期、字节身份、当时结果或明确删除记录               | 当前再次通过；缺失报告的内容；原路径启动；未授权删除           |

通过必须同时匹配输入、方法、参数、组合、环境和完整证据；候选／失败／未执行／历史声明／原件缺失分别标识。该项所需原件缺失、损坏、哈希或绑定不全时拒绝复用，不靠当前代码或补填元数据追认旧证明。旧固定目录、历史角色名、旧EXE／ZIP和方法版本保留原身份，不能因改名或文档整理转换证明等级。

历史路径不再存在时先核查逐文件退役、迁移映射、原报告或同字节备份；缺少来源就明确标为缺失，不能统一推断已安全退役。旧链接可转成保留原地址与出处的核查入口，但不得把入口修复称为原件恢复。原24处的逐项结论见[历史地址核查](../archive/historical-evidence-audit-2026-10-23.md)，未闭合原件仍禁止用于当前复用。

报告留实际版本／源码或产物SHA、环境、方法、参数、结果、证据位置与局限；当前事实从验收索引进入。证据名使用全新安全名称，不覆盖失败和返修；verificationOutput等按实际输入版本生成位置，不在规范写死某个旧公开版本。临时夹具和正式证据按[工作区维护](workspace-maintenance.md#tmp-临时内容的生命周期2026-10-11)区分，清理不得由一次通过或文件忽略状态自动授权。

## 先解决集成与高风险场景

- 先定位已验证的可复用职责和稳定契约，游戏规则、数据、策略与表现保持所属模块内聚；不靠跨游戏导入或将版本专属分支塞入平台共享层实现复用，避免复制已有纯函数、容器或资源。
- 新规则、计分、权限、随机、事务恢复、旧存档及多步动作采用测试驱动：先构造可暴露易错边界的失败用例或可重复真实场景，验证其确实覆盖风险，再实现并通过相应检查。纯文档／配置／素材记录选择格式、链接、来源、解码等适用检查，不新增只复述实现的测试。
- 跨模块任务在派工或并行实现前明确共享接口、数据兼容性、文件负责人和交接条件；有其他会话修改目标文件时保留其改动，重新核对当前内容并避免同时重写。同一文件仍只由一名 agent 修改。
- 协议、权限、保存恢复、旧存档或游戏切换变化时，先打通最小真实跨层路径，核验越权、失败保持原状态和迟到旧动作，再扩展其他功能；集成验证不能全部推迟到交付前。
- 布局变化先检查最容易暴露问题的代表场景：六人、720p、125%／150% 显示缩放、暂停／恢复提示及短手机；按影响选择适用组合，并说明未覆盖项。修正后只完成受影响模块所需的尺寸、端侧与适用交付验证；沿用隐藏窗口和实际更新后的渲染，不将代表场景通过当作完整验收。
- 为已通过的检查保留对应版本／改动、命令、结果与证据路径。仅相关代码、资源、配置或运行环境变化，检查失败或仍有未解决疑点时重跑；先跑受影响项，再完成本次必需的最终检查，不机械重复无关全套构建或矩阵。
- 相同布局或流程失败先固定一个可复现案例，用真实渲染定位原因并验证修正，再跑完整受影响矩阵；不在每次微调后重跑所有场景。仅本次明确导出新包时，交付前冻结最终输入并验证唯一完整EXE的实际提取与运行，证据绑定EXE、内部载荷和逐文件清单；后续仅文档变化不重复打包。

## 批量检查与等待

相关输入、方法、参数及必要环境一致且原证据完整时才复用，不能用重复完整检查代替定位。输出分执行、启动／解压、传输／校验／安装、扫描／哈希／容量、等待计时；混合旧报告保留未拆分口径，不推算加速倍数。子进程只登记产物，父轮仅一次适用收尾；忙碌保护停止后不自动重试，不结束其他任务进程。

并发前列出依赖、接口及完成条件，指定唯一文件负责人和隔离输出；独立检索、检查与稳定契约下的实现适当并行。共享文件、同一 GUI、组装、最终发布与清理目标只由一名负责人操作；后续工作只消费已完成并核验的稳定产物，不读半成品、不覆盖他人的目录，不在仍运行的工作项旁启动清理。并发数量按工具／内存／网络预算选择，不以并行本身作为效率证明。

互不依赖的搜索、读取和检查在同一批调用中执行，逐项核对结果；修改、审批、构建与依赖结果的操作保持顺序。授权并行协作时，交接集中提供改动范围、结果、证据与阻塞，避免连续发送重复进度询问；不因本节创建未授权的协作实例。

等待长任务使用完成通知或有界等待，只有实际状态变化、失败、需决策或完成时才读取相关详情。等待期间继续独立工作并按约定提供用户进度；没有新信息时不反复读取历史、重新分析同一结论或缩短轮询间隔。

## 测试声音与偏好隔离

测试默认关闭声音，包括自动验证以游玩模式运行的窗口；声音解码、调用及播放权检查可在静音输出下继续执行，真人听感或专门试听由验证入口显式开启。日常游玩保留用户声音偏好，测试静音不写入该偏好。

原生foundation-test与安装健康checking窗口导航前硬静音，适用于管理兼展示、玩家模拟和游玩节奏检查；迁移前助手仍创建的公共屏也须静音，但不作为后续必需端侧。desktop-test与browser-test助手保持默认静音。专门试听必须显式开启声音及适用游玩模式，单纯核验静音开关不等于人耳试听；声音调用、解码与播放权可在静音下检查，日常声音偏好不被测试覆盖。实际启动选项和API用法归工具文档。

## 专项方法与代表场景

- 视觉改动先查六席／适用最高人数、短手机、720p、125%／150%请求、暂停／恢复、长昵称及密集状态；先固定可复现失败再跑完整受影响矩阵。请求的缩放不是物理DPI。通用／盒子要求及图解实际加载见[源码视觉验证](source-visual-verification.md)和[盒子视觉](box-visual-design.md#验证与证据)。
- 独立视觉审查每图新上下文，只接收单图、中性提示及允许的偏好／职责基线；与自然整局、能力fixture、效果fixture和实体设备分别认定，具体方法见[视觉审查职责](../subagent/visual-review.md)。截图先落盘，不覆盖同阶段多次动作；实际操作和首屏命中不能用事后滚到目标替代。
- 简介／规则浮窗要实际解码主题图片，检查章节、字号、触控、滚动、关闭／Escape焦点恢复及查看不改变revision、checkpoint、计时或身份。规则文字、数字、箭头由代码排版，原创场景与真实截图分开；有损WebP不能宣称与原PNG逐像素一致。按采用版本维护来源，不能把早期三游戏27组合当成整个现行目录通过。
- 原始固定局面、受控事件与普通自然对局分别记录；自然发生一次事件不表示覆盖全部事件，快速自然对局、普通节奏检查点及完整自然整局不能互换。真人动作必须得到权威保存回执，私看只投影本人；不往正式服务加全状态／作弊端点以方便夹具。人机、媒体及阶段模拟不能冒充真人思考或听感。
- 历史便携检验器遇到真实人机保存引起的stale-revision暂停竞争时，仅同实例／同分支的暂停意图最多重取8次；其它命令不重试，逐次计数和首次冲突原证据保留。该已限定方法不授予一般动作盲重试，也不放宽服务校验。旧方法详见[原专项边界](../archive/validation-before-consolidation-2026-10-23.md#游戏介绍弹窗布局检查)。
- 内存测量区分源码复制fixture、GC后的renderer／DOM／监听器／本应用进程与磁盘容量；不能以整机RAM、不同运行时绝对工作集、模拟1200checkpoint或20轮导航推断真实长局或长期有界内存。完整回退历史仍须保留，源码测量和桌面运行按原方法分别认定。
- LAN专项才允许显式本机网卡监听，默认127.0.0.1；不得修改防火墙／路由器或正式存档，系统防火墙变化另需授权。本机网卡可达不证明真实Wi-Fi；故障、延迟、重启、回退、重复启动及端口占用按实际执行记录，不能借全量聚会脚本扩大盒子／单游戏任务。
- 服务载荷压缩属于[构建运行契约](build-and-run.md#服务载荷无损压缩)，工具回归命令见[构建工具](../../tools/build/README.md)。规则、数据、地图拓扑、人机记忆与各游戏决策点仍归游戏主题，不由文档整理改写。
